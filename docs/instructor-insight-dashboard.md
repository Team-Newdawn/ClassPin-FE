# 강의 인사이트 대시보드 명세

## 1. 범위

- `DSH-001` 대시보드 하나는 강의(자료) 하나를 다룬다. 경로는 `/admin/insights/[id]`(`id` = 강의 id, `ClassSession.id`). 진입은 인사이트 목록(§7)이다. 폴더 자료 카드의 아이콘과 리포트 편집 화면 머리줄 링크는 2026-10-31 사용자 요청으로 뺐다.
- `DSH-002` 포함: 핵심 수치(PIN, 질문, 공감, 강의 시간, 참여자), 분당 PIN 그래프, 시간에 따른 참여자 그래프, 슬라이드별 PIN·공감·질문 목록, 슬라이드 위 PIN 위치 분포, 슬라이드별 화면 노출 시간, 슬라이드별 시간에 따른 참여자와 PIN, 슬라이드의 분당 PIN, 주제별 묶음, 공감 많은 질문, 키워드.
- `DSH-003` 제외(2026-10-29 사용자 결정): 이모지 반응 그래프, LIVE 회차 비교, 질문 감정 분류, 폴더 안 강의 비교·주차별 추이, 여러 강의에서 반복되는 주제. 답변 기능이 숨김 상태라 미답변·답변·해결 수와 상태 표시도 넣지 않는다.
- `DSH-004` 시간 데이터는 마지막 LIVE 회차 기준이다. 같은 강의를 다시 LIVE로 열면 기록을 새로 쓴다(`started_at`과 같은 규칙).

## 2. 강의 타임라인 기록 (FE만 변경, BE 변경 없음)

- `DSH-010` 강사 플레이어가 LIVE 동안 1분마다 `{at, audience, slide}`(현재 접속 탭 수, 화면 슬라이드 1-based)를 쌓는다. 슬라이드가 바뀔 때마다 `{at, slide}`를 쌓는다. 값은 기존 heartbeat 집계와 플레이어가 보는 `currentSlide`에서 얻으며 새 broadcast를 추가하지 않는다.
- `DSH-011` 플레이어는 5분마다, 그리고 강의 종료 저장 직후에 지금까지의 기록 전체를 `POST /api/admin/lectures/:id/audience`로 보낸다(덮어쓰기). 실패해도 수업을 막지 않는다. 탭을 닫으면 마지막 전송 이후 최대 5분이 빠진다.
- `DSH-012` 서버는 강의 소유권을 강사 JWT로 `GET /api/instructor/lectures/{id}/state`에 물어 확인한다(내 강의가 아니면 그 응답에 `id`가 없다). 전체 강의 그래프를 읽지 않는다. 표본 1,440개(24시간), 슬라이드 전환 5,000개를 넘거나 값이 범위를 벗어나면 400.
- `DSH-013` 한계: 값은 탭 기준 근사치이고 출석이 아니다. 플레이어 탭이 없거나 기기가 잠들면 그동안 표본이 없고, 그래프는 그 구간을 끊어서 그린다. 슬라이드 전환 시각은 플레이어가 상태를 받는 주기(최대 5초)만큼 늦을 수 있다.

## 3. 데이터와 API

- `DSH-020` `lecture_audience_records`에 `samples jsonb`, `slide_changes jsonb`(기본 `[]`)를 더한다. `instructor_reports`에 초안 분석 결과 `analysis jsonb`를 더한다(주제별 묶음의 출처). 기존 리포트는 다음 초안 생성 때부터 채워진다.
- `DSH-021` `GET /api/admin/lectures/:id/insights` → `{ record: { startedAt, endedAt, audience, peakAudience, samples, slideChanges } | null, topics: { title, summary, questionIds }[] | null, reportId: string | null }`. 두 테이블 모두 호출자 `owner_id`로 거른다. REST 그래프를 읽지 않는다.
- `DSH-022` 질문·슬라이드·`startedAt`은 화면이 이미 가진 세션 스토어 데이터를 쓴다. 강의 종료 시각은 `record.endedAt`을 쓰고, 없으면 마지막 질문 시각까지를 강의 구간으로 본다.

## 4. 계산 (순수 함수, `app/_model/insight-dashboard.ts`)

- `DSH-030` 분당 PIN: 위치가 있는 질문의 `createdAt − startedAt`을 분 단위로 센다. 강의 구간 밖의 질문은 넣지 않는다.
- `DSH-031` 슬라이드별 노출 시간: 슬라이드 전환 기록을 강의 구간으로 잘라 슬라이드마다 합한다. 전환 기록이 없으면 1분 표본의 `slide`로 근사한다.
- `DSH-032` 슬라이드의 분당 PIN = 이번 LIVE 회차 동안 그 슬라이드에 달린 PIN 수 ÷ 노출 시간(분). 노출 시간이 0이면 값을 내지 않는다. 표의 PIN 열은 전체 PIN 수다(2026-10-29 E2E에서 예전 회차 PIN이 비율을 부풀리는 것을 확인하고 정했다).
- `DSH-033` 슬라이드별 시간에 따른 참여자와 PIN: 그 슬라이드가 화면에 있던 구간의 분 단위 참여자 수와 그 슬라이드에 달린 PIN 수.
- `DSH-034` 키워드: PIN 본문에서 한글·영문·숫자 토큰을 뽑아 흔한 조사·어미와 불용어를 떼고, 2글자 이상을 세어 상위 60개를 낸다. AI를 쓰지 않는다.
- `DSH-035` 주제별 묶음은 리포트 초안 분석의 `groups`를 쓴다. 리포트가 없거나 분석이 없으면 "리포트를 만들면 주제별 묶음이 나옵니다"를 보인다. 대시보드의 리포트 링크·버튼은 2026-10-31 사용자 요청으로 뺐다(리포트는 인사이트 목록에서 연다).

## 5. 화면

- `DSH-040` 리포트 목록과 같은 폴더 트리 사이드바 안에 둔다. 위에서부터: 머리(강의 제목·자료·날짜) → 핵심 수치 → 분당 PIN 그래프 | 참여자 그래프 → 슬라이드 표(노출 시간·PIN·공감·분당 PIN, 막대) → 선택한 슬라이드 상세(슬라이드 이미지 위 PIN 분포, 그 슬라이드의 참여자·PIN 그래프, 공감 많은 순 질문 목록) → 주제별 묶음 → 키워드.
- `DSH-041` 그래프는 OhPin 브랜드 블루 한 가지 색, 축 하나, SVG로 그린다(새 의존성 없음). 예외: 키워드 워드 클라우드는 `d3-cloud`(BSD-3)로 단어를 빽빽하게 배치하고, 세 번째 단어마다 90° 돌리며, 횟수 순위대로 블루·네이비·슬레이트 토큰을 번갈아 쓴다(2026-10-30 사용자 요청). 마우스를 올리면 값이 보이고, 그래프마다 표 보기를 둔다. 시간 그래프에는 슬라이드 구간을 옅은 띠로 표시한다.
- `DSH-042` 기록이 없는 항목은 비워 두지 않고 이유를 쓴다(예: "이 강의는 참여자 기록이 없습니다. 플레이어에서 LIVE를 진행하면 기록됩니다").
- `DSH-043` 모든 컨트롤에 accessible name과 focus-visible을 둔다. 슬라이드 선택은 키보드로 할 수 있어야 한다.

## 7. 인사이트 목록 (2026-10-31 사용자 요청, Figma `ClassPin` 2210:6624)

- `DSH-050` 경로는 `/admin/insights`. 폴더 트리 사이드바 안에 두고, 사이드바의 `홈으로` 아래에 `인사이트` 항목을 둔다(리포트 항목과 목록은 2026-10-31 삭제). 새 API 없이 세션 스토어의 자료·폴더와 `GET /api/admin/reports`만 쓴다.
- `DSH-051` 머리: `인사이트` 제목과 `자료 · 폴더 검색` 입력. 검색어가 자료 제목이나 폴더 이름에 들어 있는 자료만 두 구역 모두에 남긴다.
- `DSH-052` **최근 인사이트**: 최근에 분석한 자료 = 리포트가 있는 자료(리포트 초안이 AI 분석 결과다). 리포트 마지막 수정이 최근인 순으로 최대 4개 카드(첫 슬라이드 썸네일, 제목, `폴더 · 질문 n · 날짜`, 버튼 두 개). 해당 자료가 없으면 구역 전체를 숨긴다. 4개 제한과 "리포트가 있으면 분석한 자료"라는 정의는 리드 기본값이며 사용자가 바꿀 수 있다.
- `DSH-053` **자료별 인사이트**: 모든 자료를 한 줄씩(썸네일, 제목, `질문 n건 · 날짜`, 버튼 두 개). 폴더 선택(전체·폴더별·미분류, 네이티브 select)으로 거른다. 순서는 최근 강의순(`startedAt`, 없으면 `createdAt`) 하나뿐이라 정렬은 고르지 않고 글자로만 표시한다. 날짜도 같은 값이다.
- `DSH-054` `인사이트 보기`는 `/admin/insights/[id]`로, `리포트 보기`는 자료 카드와 같은 동작(RPT-012: 있으면 열고 없으면 만든다)이다. 버튼의 accessible name에 자료 제목을 넣는다.
- `DSH-055` 자료가 없으면 "폴더에 자료를 올리면 인사이트를 볼 수 있어요"를, 검색·폴더 결과가 없으면 "조건에 맞는 자료가 없습니다"를 보인다.

## 6. 검증

- Node 테스트: 기록 누적(1분 표본·전환), 분당 PIN, 노출 시간, 분당 PIN 비율, 슬라이드별 시계열, 키워드, audience/insights route(소유권, 입력 검증).
- SQL: 새 열 기본값, `anon`/`authenticated` 접근 거부 유지.
- 로컬 E2E: 플레이어에서 LIVE 시작 → 참여자 탭 접속 → 슬라이드 이동과 PIN 등록 → 2분 이상 진행 → 종료 → DB 기록과 대시보드 그래프 확인.
- `npm run lint`, `npm run build`, 마이그레이션 추가에 따른 로컬 DB 적용.
