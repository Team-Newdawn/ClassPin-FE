# 인사이트 AI 분석 기반 설계

- 상태: 재설계 구현 중 — 10절(2026-10-21, 속도 우선 Claude PDF 분석)이 4·5절과 Groq 이미지 흐름을 대체한다
- 작성: 2026-10-21, `feature-dev-ai`
- 범위: 인사이트 화면을 만들기 전 분석 기능·데이터 계약·구현 순서 준비
- 기준: `doc/pin_class_prd.md`, `ai-instructor-report-product.md`, `ai-instructor-report-evidence.md`, `ai-instructor-report-system.md`, `account-structure-implementation.md`
- 이 문서는 기존 승인 명세를 자동 대체하지 않는다. 아래 변경 결정 승인 후 관련 명세와 manifest를 함께 정합화한다.

## 1. 목표와 레퍼런스

자료의 내용을 이해하고, PIN이 가리키는 위치와 질문·답변을 연결해 강사가 확인할 수 있는 근거 있는 분석을 만든다. 하나의 검증된 분석을 전체 요약, 슬라이드별 분석, 질문 리스트, AI 대화, 파일 내보내기에 사용한다.

- [Figma 2000:20727](https://www.figma.com/design/Mw7TekAU6bxju63dFfJdQJ/ClassPin?node-id=2000-20727): 실제 스크린샷에서 왼쪽 자료 영역과 오른쪽 전체요약·슬라이드별·AI 분석(대화)을 확인했다. 질문 리스트와 분석 방법 선택은 사용자 요청으로 함께 반영한다. 이번 단계는 화면 구현을 포함하지 않는다.
- [LilysAI](https://lilys.ai/en/): 공식 소개의 원본과 연결된 요약·설명, 대화, PDF/DOCX 내보내기를 참고한다. Pin Class에서는 출처를 슬라이드와 PIN까지 연결한다.
- [UnivAI](https://univai.co.kr/): 공식 소개의 강의자료 요약, 핵심 개념, AI 튜터를 참고한다. 여기서는 강사가 자료와 질문을 이해하는 대화에 적용한다.
- 레퍼런스 조사는 공개 소개 기준이다. 로그인 후 실제 동작, 내부 모델·구조·성능은 검증하지 않았다. 녹음·퀴즈·플래시카드는 이번 요청에 추가하지 않는다.

## 2. 현재 코드에서 확인한 것

| 경로 | 현재 동작 | 설계상 의미 |
| --- | --- | --- |
| `app/(view)/admin/insights/controller.ts` → `_model/stats.ts` | session store의 자료를 `buildSessionInsights`로 집계 | 기존 통계 의미와 정렬을 재사용할 수 있다. AI 자료 분석은 아니다. |
| `_controller/session-store.tsx` → `_service/class-session-service.ts:fetchOwnedSessions` | `/instructor/courses` REST 그래프에서 자료·최신 버전·슬라이드·질문을 UI 모델로 변환 | 화면 캐시를 분석의 권위 원본으로 사용하지 않는다. 서버에서 소유권 확인 후 snapshot을 만든다. |
| `_service/question-summary-service.ts:toSummaryItems` → `/api/question-summary` | 질문 본문·페이지·공감 수를 Groq에 전달 | 슬라이드 이미지, 원본 질문 ID, 위치, 답변 이력이 없으므로 새 분석 입력으로 그대로 쓰면 안 된다. |
| `/api/question-summary:POST` | 로그인 사용자 검사 후 브라우저가 보낸 items를 요약; 키 없으면 503, 생성 오류는 502 | 저장 리포트에 필요한 자료 소유권 검사·서버 snapshot·근거 검증·영속 작업 경계가 별도로 필요하다. |
| `_model/types.ts:Slide` | 이미지 경로 또는 PDF 원본 페이지 참조, 강사 메모 | 이미지만 있다고 가정하면 PDF 자료를 놓친다. 메모는 분석에서 제외한다. |
| `_service/class-session-service.ts:toQuestion` | 최신 답변 하나로 축약; slide 연결 실패는 index 0으로 변환 | 분석에는 원본 slide ID와 전체 답변 이력이 필요하다. 연결 실패를 첫 슬라이드 근거로 바꾸면 안 된다. |

현재 checkout의 파일 검색에서 상세 `material-insights`/`ai-reports` 구현·migration은 확인되지 않았다. 다른 브랜치의 과거 구현을 현재 구현으로 간주하지 않는다. 운영 스키마와 실제 사용자 자료는 미검증이다. 이후 배포 Swagger와 BE 소유 자료 조회 소스를 읽어 source 준비 검사에 필요한 계약을 확인했다.

## 3. 필요한 기능 목록

| ID | 기능 | 입력 → 결과 | 완료 조건 |
| --- | --- | --- | --- |
| INS-01 | 분석 범위와 snapshot | 소유 자료/버전/슬라이드/질문/답변/반응 → 불변 snapshot | 소유권, 자료 버전, 기준 시각, 정렬, 누락·중복 검증 |
| INS-02 | 슬라이드 준비 | 이미지 또는 PDF 페이지 → 동일 좌표계의 분석 이미지 | 기존 자료 재업로드 불필요; checksum·페이지·크기 보존 |
| INS-03 | 비식별화 | 텍스트·이미지 → 가림 처리된 사본 | 내부 OCR, 이메일·전화·토큰 제거; 실패 시 외부 전송 중단 |
| INS-04 | 슬라이드 이해 | 가림 이미지 → 핵심 개념·요약·표/도표 관찰 | 이미지 근거 참조, 판독 불가 표시, 보이지 않는 값 추정 금지 |
| INS-05 | PIN 근거 구성 | 질문·좌표·답변 이력 → overlay/crop·근거 목록 | point/box/path/좌표 없음 지원; 원본 변경 없음 |
| INS-06 | 질문 분석 | 질문 근거·공감·상태 → 개별 요약·지지/모순 관계·미답변 목록 | 원본 질문 보존; 주제 유사성과 공간 근접성을 구별 |
| INS-07 | 슬라이드별 통합 | 자료 관찰 + PIN 분석 → 질문 발생 맥락·개선 제안 | 위치·본문 모두 근거로 연결; 근거 부족 시 판단 보류 |
| INS-08 | 전체 합성 | 검증된 슬라이드 결과 + 코드 집계 → 핵심 요약·우선순위 | 모든 슬라이드 포함; 새 사실·수치·관계 생성 금지 |
| INS-09 | 분석 방법 선택 | 동일 결과 → 자료 요약/질문 중심/개선 중심 보기 | 표현·강조 전환은 재분석 없이 동작; 새 해석은 명시적 새 분석 |
| INS-10 | 자료 기반 AI 대화 | 선택 snapshot·슬라이드/PIN·대화 질문 → 인용 가능한 응답 | 범위 밖 질문 기권, 대화가 원본·정식 리포트를 자동 수정하지 않음 |
| INS-11 | 요약 수정 | 기존 canonical claims + 지시 → 새 revision | 표현·길이·순서만 수정; 실패해도 이전 revision 보존 |
| INS-12 | 내보내기 | 같은 확정 revision → PDF·PowerPoint·DOCX·MD | 형식 간 사실·수치·인용 일치, 추가 AI 호출 없음 |
| INS-13 | 작업 운영 | 생성/재시도 요청 → 영속 상태·진행률·결과 | 중복 방지, lease, 제한된 retry, 비용 상한, 페이지 이탈 후 복구 |

질문 0개인 슬라이드도 자료 요약 대상이다. 질문 1개는 개별 신호이며 반복 혼란으로 부르지 않는다. 공감 수는 사람 수·출석·학습 이해도로 해석하지 않는다.

## 4. 분석 흐름과 계약

```text
인증·자료 소유권 확인 → 서버 snapshot
  → 이미지/PDF 페이지 준비 → 내부 OCR·비식별화
  → 슬라이드별 전체 이미지 + PIN overlay/crop + 질문/답변 + 코드 집계
  → 슬라이드 분석 → 구조·참조 검증 → 별도 모델 비평
  → 모든 슬라이드 성공 확인 → 전체 합성·검증·비평
  → canonical 분석 + revision 저장
  → 전체 요약 / 슬라이드별 / 질문 리스트 / 대화 / 확정본 내보내기
```

### 서버 입력

브라우저는 선택 식별자, 언어, 분석 목적, 멱등 키만 보낸다. owner, 원문, 공감 수, 이미지 URL, snapshot hash를 클라이언트 주장으로 신뢰하지 않는다. 서버 내부에는 material/version/slide/question mapping을 보관하고 외부 AI에는 snapshot 내 alias만 보낸다.

| 데이터 | 보관할 내용 |
| --- | --- |
| Snapshot | schema version, owner(내부), cutoff, 선택 범위, source/config fingerprint |
| SlideSource | material/version/slide ID(내부), alias, 원본 페이지 번호, checksum, 이미지 크기, image/PDF source 종류 |
| QuestionEvidence | question alias, slide alias, 원래 anchor, 가린 질문 본문, 상태, 시간순 답변, 공감 수 |
| Metrics | 질문/상태/공감 집계, 근거와 연결되는 metric ID; 코드에서 계산 |
| Claim | 종류, 본문, slide refs, 지지/반대 question refs, metric refs, 근거 수준 |
| SlideAnalysis | 자료 관찰, 질문 신호/패턴, 모순, 미답변, 개선 제안, 판독 한계 |
| Report/Revision | snapshot·canonical 참조, 선택 claim과 표현, 모델·prompt·schema 버전, 검증 결과 |

원본 slide ID가 없거나 다른 version에 연결된 질문은 오류를 명시하고 근거 확정 전에 해결한다. 좌표 없음과 잘못된 좌표를 구분한다. 긴 입력은 처리 단위를 나누되 일부 질문을 조용히 버리지 않는다. 지원 한도 초과는 사전 검사에서 알린다.

### 공간 분석

기존 `AIR-EVID-012~039`를 유지한다: point crop은 각 축 40%, box/path는 경계 상자에 각 축 10% 여백 및 최소 40%, 경계 안으로 이동한다. 원본 좌표를 보정하지 않는다. 같은 슬라이드의 20×20 격자와 인접 셀로 후보를 만들고 AI가 지지/모순/무관을 판정한다. 좌표 없는 질문은 별도 후보이며 위치 기반 결론에 사용하지 않는다. 가까운 PIN이라는 이유만으로 같은 질문으로 병합하지 않는다.

질문 리스트의 주제별 정리는 표시용이며 원본 질문·개수를 유지한다. 서로 다른 슬라이드의 주제가 유사해도 하나의 공간 혼란 패턴으로 합치지 않는다.

### AI 대화와 요약 탭

제안: 대화는 현재 분석 snapshot 범위의 자료·질문을 설명하는 강사용 기능이다. 응답마다 slide/question/claim 인용을 붙이고, 필요한 자료가 없으면 답변 불가를 표시한다. 선택 슬라이드나 PIN을 명시적으로 scope로 전달한다. 대화 이력은 report/snapshot에 귀속시키고 새 버전과 섞지 않는다.

대화의 설명과 리포트 수정은 별도 동작이다. 요약 수정은 기존 revision 규칙을 따른다. 새 근거 해석은 새 분석으로 요청한다. 확정본은 불변이다. 대화 입력과 자료 안의 명령은 신뢰하지 않는 데이터로 처리하고 외부 검색·도구 실행을 허용하지 않는다. 새로운 대화 출력도 schema·출처·근거 검증 및 비평을 통과해야 표시한다.

## 5. 저장·API·실행

새 저장 구조를 중복 설계하기보다 기존 `ai-report-system`의 report/material/slide/revision/job/cleanup 여섯 테이블과 API를 출발점으로 한다. 대화 이력은 추가 설계 대상으로 report/snapshot 귀속, 순서, 인용, 상태, 비용을 보존한다. 확정 후에도 읽기 대화는 가능하되 리포트를 변경하지 않는 것으로 제안한다.

기존 preflight/create/status/retry/revisions/confirm API 계약을 유지한다. 신규 제안은 다음 두 가지다.

- `POST /api/admin/ai-reports/{id}/chat`: snapshot과 선택 범위 검증, 대화 작업 생성. 비동기 응답은 기존 작업 조회 계약을 따른다. 대화 이력 조회에도 매번 소유권 검사.
- `GET /api/admin/ai-reports/{id}/export?format=pdf|pptx|docx|md`: 확정 revision만 인증 후 반환. 기존 PDF 경로와의 호환 유지 여부는 구현 시 호출자 확인.

상태·멱등성·lease·입력 한도·비용 정책은 기존 명세를 보존한다. 429는 제공자 한도와 내부 비용 상한을 구별한다. Retry-After를 존중하고 무한 재시도하지 않는다. 잘린 JSON, 근거 ID 불일치, 누락 슬라이드, 비평 실패를 성공으로 기록하지 않는다. 외부 AI 요청은 DB transaction 밖에서 수행한다.

현재 업무 데이터는 Spring REST 경계를 사용한다. 운영 구현 전에 배포 API와 BE 읽기 경로에서 version·원본 slide ID·전체 답변·권한·일관된 snapshot 확보 가능성을 확인한다. 부족한 API/원자 snapshot은 BE 인계 문서로 전달하며 이 저장소에서 BE를 수정하지 않는다. UI 모델의 최신 답변 하나나 브라우저 localStorage로 대체하지 않는다.

2026-10-21 사용자 승인으로 제공자를 Groq로 변경했다. 같은 `GROQ_API_KEY`로 Qwen 이미지 분석과 GPT-OSS 텍스트 검토를 수행하며, 이미지를 다른 모델이 재검증했다고 주장하지 않는다. FE EC2 + private worker 조합의 인증·enqueue·비밀 주입 경로는 별도로 연결해야 한다. FE를 Cloud Run으로 이전한다고 가정하지 않는다.

## 6. 내보내기 준비

| 형식 | 설계 |
| --- | --- |
| MD | 제목·본문·표·자료명/페이지/PIN 인용을 UTF-8로 출력. 임시 인증 URL을 넣지 않는다. |
| PDF | 공통 문서 모델에서 페이지 구성, 한글 폰트, 비식별 이미지·인용을 렌더링한다. |
| DOCX | 같은 모델의 heading/paragraph/table/image/caption을 편집 가능한 문서로 변환한다. |
| PowerPoint | 같은 모델의 요약·슬라이드 분석·질문·개선 제안을 편집 가능한 PPTX로 구성한다. |

PowerPoint는 `.pptx`를 제안하며 구형 바이너리 `.ppt`와 동일하다고 주장하지 않는다. 파일명만 바꾼 HTML을 DOCX/PPT로 반환하지 않는다. 현재 설치 의존성에는 DOCX/PPTX 작성기가 없으므로 출력 구현 단계에 필요한 최소 라이브러리나 변환 런타임을 검증·선정한다.

문서 모델은 확정 revision에서 결정론적으로 구성한다. 분석과 별도의 AI 재생성을 사용하지 않는다. 이미지 포함 형식은 가린 사본만 내장하며 질문 원문 인용도 가린 값으로 일치시킨다. 다운로드는 소유권을 재확인하고 임시 파일을 정리한다. 파일별 한글, 긴 질문, 표·페이지 넘침, 인용 보존을 렌더링해서 확인한다.

## 7. 구현 순서와 통과 기준

## 9. 구현 현황과 다음 연결 조건

추가 구현: `insight-groq.ts`는 고정 모델, 이미지 bytes 입력, timeout, 429 Retry-After, 잘린 출력·usage·모델 일치·결과 검증과 안전한 오류 코드를 처리한다. `insight-source.ts` 및 `/api/admin/ai-reports/source`는 서버 소유 자료 조회와 전체 답변 이력·source 참조 검사에 연결했다. 준비 검사 결과와 모델 호출을 곧바로 이어 실자료를 전송하지 않는다. 이 둘 사이에는 아직 원자 snapshot, 내부 OCR/가림, 작업·비용 관리가 필요하다.

실호출 증거: 합성 빨간 도형 이미지 → Qwen 입력 848/output 7 tokens, 합성 텍스트 대조 → GPT-OSS 입력 181/output 51 tokens. 실제 강의자료·개인정보는 전송하지 않았다. 화면·저장 report·export 완료를 의미하지 않는다.

### 서버 연결 계약

사용자의 실제 구현 진행 지시에 따라 `POST /api/admin/ai-reports/source`를 읽기 전용 준비 검사로 추가한다. 입력은 `materialIds` UUID 배열만 받는다. 서버가 Supabase로 강사 인증·admin 역할을 검사한 뒤 사용자 JWT로 Spring의 소유 자료 그래프를 조회한다. 응답은 자료·슬라이드·질문·답변 수와 분석 준비 상태만 포함하며 원문·source path·내부 mapping은 반환하지 않는다. 브라우저가 보낸 집계나 owner는 받지 않는다.

이 준비 검사는 비용 quote나 생성 API가 아니다. 조회 시점의 자료를 검증하지만 원자적 DB snapshot 저장을 보장하지 않는다. 실제 생성은 AIR-SYS-020의 원자적 snapshot API와 영속 작업이 연결된 뒤 활성화한다. 배포 Swagger에는 현재 해당 생성/snapshot API가 없으므로 별도 BE 계약이 필요하다. FE 저장소에서 BE 소스는 수정하지 않는다.

2026-10-21: `app/_model/insight-evidence.ts`와 같은 이름의 `.test.ts`에 순수 근거 계산을 구현했다. 새로운 의존성, API, DB migration은 추가하지 않았다.

- point/box/path의 crop 경계를 계산하고 잘못된 좌표는 거부한다. 좌표가 없는 질문에는 crop을 만들지 않는다.

이 모듈은 비식별화된 서버 snapshot에서 만든 입력을 받는 내부 계산기다. 실제 snapshot 수집·권한 검사, 원문·답변 이력 보존, 이미지 checksum·OCR·가림, AI 응답 schema 파싱·비평, 보고서 전체 근거 수준 계산을 대신하지 않는다. 실제 AI 호출·화면·내보내기는 아직 연결하지 않았다.

## 10. 재설계 결정 (2026-10-21, 속도 우선)

사용자 결정: 실제 자료 검증에서 "질문마다 이미지 3장 → Qwen 비전 → GPT-OSS 비평" 구조가 분당 1회 수준의 호출 한도와 전체 실패 규칙 때문에 완료되지 않았다. 분석 속도를 최우선으로 하고 품질은 80% 수준이면 통과하며, 비평 단계는 생략한다. 테스트 단계이므로 강의 PDF와 가림 처리한 질문을 Anthropic Claude API로 보내는 것을 허용한다.

이 절은 4·5절의 Groq 이미지 흐름, `insights-rest-snapshot.md`의 snapshot·worker 설계, `ai-instructor-report-evidence.md`의 AIR-EVID-070~078(코드 검증 후 별도 AI 비평, 하나라도 실패 시 후보 전체 비노출)과 질문별 이미지 근거 요구, `ai-instructor-report-system.md`의 AIR-SYS-050~054(단계 상태 전이, slide unit 비평, 전체 실패)와 OpenRouter adapter 요구를 대체한다. 비식별화, 소유자 검사, speaker note 제외, 코드가 계산한 수치만 표시, 강사 확정 후 내보내기 규칙은 유지한다.

흐름:

1. 강사가 인사이트 페이지에서 "분석 시작"을 누르면 서버가 소유 자료를 REST로 읽고(`insight-source.ts` 재사용), 강의가 종료 상태인지 확인한 뒤 `ai_insight_reports` 행을 `running`으로 만든다. 응답은 즉시 돌려주고 Next `after()`로 같은 프로세스에서 분석을 이어서 수행한다. 별도 worker·lease·비용 견적·snapshot 테이블은 두지 않는다.
2. 슬라이드는 두 종류다. PDF 쪽 슬라이드(`source_page_index`)는 저장된 원본 PDF를 서버 디스크 캐시에 받아, 실행 이미지에 이미 있는 poppler로 쪽마다 JPEG(긴 변 약 1,455px, Claude 이미지 한도 1,568px·1,568토큰 안)와 글자(`pdftotext -layout`)를 만든다. 글자가 대부분 한글·영문·숫자·문장부호가 아니면(디자인 도구 PDF의 깨진 글자층) 그 쪽 글자는 버린다. 이미지 슬라이드(`image_path`: 예전 PDF 업로드, 지금도 백엔드가 이미지로 변환하는 PPT·PPTX, 덧붙인 이미지)는 `lecture-slides`의 JPEG를 같은 크기 규칙으로 줄여 쓰고 추출 글자는 없다. 모든 슬라이드가 이미지면 원본은 받지 않으므로 원본이 없거나 PPTX여도 분석된다(2026-10-23 사용자 결정). 600장을 넘는 자료는 `SOURCE_TOO_LARGE`로 거부하고, 임시 폴더는 분석이 끝나면 지운다. 슬라이드 번호 기준 20장씩 한 요청으로 묶는다(이미지 20장 이하).
3. 조각마다 Claude 호출 1회를 병렬로 보낸다. 입력은 슬라이드마다 `슬라이드 N (이미지 WxHpx)` 라벨 + 이미지 + `<slide_text>` 추출 글자, 그 뒤에 페이지별 질문(PIN 위치를 그 이미지 기준 픽셀 좌표로 표기, 질문 본문, 답변). PDF 문서 블록과 백분율 좌표는 쓰지 않는다: 2026-10-22 실험에서 빽빽한 표의 PIN 대상 판정이 PDF+백분율 평균 92.7%(최저 72%)에서 이미지+픽셀 98.3%(최저 97%)로 올랐고, 작은 글자·숫자 받아쓰기는 이미지만 97.7%, PDF와 이미지+추출 글자는 100%였다. PIN 번호 표시를 그린 이미지는 작은 라벨을 가려 쓰지 않는다. 질문이 없는 슬라이드는 `content`에 내용을 두세 문장으로 단순 정리만 한다(평가·제안 없음, 한 줄 topic만 나오던 어색함 해소, 2026-10-22 사용자 요청). `content`는 리포트·화면("내용 정리")·내보내기에만 쓰고 병합·대화 맥락에는 넣지 않는다(PIN 없는 슬라이드 1장당 출력 약 +180토큰). 출력은 structured output(JSON schema)으로 자료 종류 `category`(정해진 목록 없이 AI가 자료를 보고 짓는 짧은 이름, 40자 제한)와 페이지별 `topic`, `questionSummary`, `suggestion`. 모델은 같은 호출에서 종류를 먼저 판단하고 그 종류의 관점으로 쓴다. 조각별 판단은 다수결(동률은 앞 조각)로 하나로 정해 병합 호출과 대화 맥락에 넣고 리포트에 "AI가 판단한 자료 종류"로 표시한다(2026-10-21 사용자 요청). 자료가 폴더에 들어 있으면 서버가 강사 권한으로 `GET /api/instructor/folders`를 함께 읽어 강의 그래프의 `courses.folder_id`로 폴더의 사용 목적(Q&A·피드백·교육·브레인스토밍·기타와 기타 이름)을 찾고, 질문 요약과 같은 목적 문구(`classFolderPurposeLine`)를 조각 분석·병합·대화 프롬프트에 넣는다. 폴더 조회가 실패하거나 미분류 자료면 목적 없이 분석한다. 백엔드 변경은 없다. 인사이트 화면은 OhPin 기존 화면 문법을 따른다(2026-10-21 사용자 요청): 상단은 종료 리포트의 뒤로가기 버튼·`인사이트 리포트` 제목 묶음, 슬라이드는 플레이어의 짙은 무대, 질문은 플레이어 질문 카드, 탭은 회색 트랙 탭, 전체 요약은 연파랑 AI 요약 카드, 확정 상태와 AI 판단 자료 종류는 배지로 보여 준다. PIN 주변 내용은 좌표 설명을 보고 모델이 PDF에서 직접 읽는다. 별도 OCR·이미지 가림·overlay·crop은 없다.
4. 조각 결과를 모아 Claude 호출 1회로 전체 요약(`summary`, 질문이 몰린 페이지 `hotspots`, `suggestions`)과 질문 묶음(`groups`: 제목·요약·질문 번호 목록)을 만든다. 입력은 텍스트뿐이라 빠르다. 질문은 UUID 대신 1부터 매긴 번호로 보내고 코드가 ID로 되돌린다. UUID는 개당 약 25토큰이라 PIN 2,000개면 묶음 출력만 5.6만 토큰이 되어 출력 상한을 넘었다(번호는 약 6,600토큰).
5. 검증은 코드만 한다. 존재하지 않는 페이지·질문 ID 참조는 그 항목만 버리고, 문장 길이를 제한한다. 수치(질문 수, 공감, 답변)는 코드가 센 값만 쓴다. Claude 호출 실패(네트워크·429·거부)는 SDK 재시도(2회) 후에도 실패한 20쪽 묶음은 그 슬라이드만 비우고 `failedPages`에 남기며, 나머지 결과와 전체 정리는 그대로 보여 준다(화면: "슬라이드 N장 분석 실패" 배지, 해당 슬라이드 안내). 모든 묶음이 실패하거나 정리 호출이 실패하면 `failed`로 기록하고 "다시 분석" 버튼을 보여준다(2026-10-22 사용자 결정). 15분이 지나도 `running`인 리포트(서버 재시작·배포로 끊긴 분석)는 조회 시 `ANALYSIS_INTERRUPTED` 실패로 보여 주고, 같은 15분 기준으로 새 분석을 허용한다. 진행 중 화면의 "분석 중지"(2026-10-23 사용자 요청)는 리포트를 `failed`/`ANALYSIS_CANCELLED`로 바꾸고 같은 서버 프로세스의 쪽 이미지 대기·Claude 호출을 중단한다. 이미 끝난 분석은 바꾸지 않으며, 중지한 분석은 실패처럼 사용 한도에 세지 않는다. 쪽 이미지 만들기는 서버당 한 번에 한 자료만, CPU 코어의 절반까지만 써서 같은 서버의 LIVE 강의를 보호한다. 원본은 메모리에 올리지 않고 `/api/pdf`·대화와 같은 서버 디스크 캐시(키 `source_path`)로 스트리밍하며, 크기는 받기 전에 Storage 정보로 확인한다. 20쪽 묶음 호출은 한 분석에서 동시에 6개까지만 보낸다(묶음 하나가 base64 이미지 약 20MB를 쥐므로; 120쪽 이하는 그대로 한 번에 끝난다, 2026-10-23). 대화는 최근 20턴을 보내되 합계 약 2만 자를 넘으면 오래된 질문·답 쌍부터 뺀다. 사용 한도(2026-10-23 사용자 결정, 결제 방식별 차등 전 기본값): 강사당 하루(한국 시간 자정 기준) 분석 2회(`ready`·`confirmed`와 15분 안의 `running`만 세고 실패·중단은 세지 않음, 초과 시 429 `DAILY_LIMIT`), 리포트당 AI 대화 질문 5회(초과 시 429 `CHAT_LIMIT`). AI 대화의 "새 대화"(2026-10-23 사용자 요청)는 확인 후 대화 내용을 지우고 빈 턴(`cleared`)만 남겨, 새로 시작해도 질문 횟수는 이어서 센다. 두 한도 모두 `next dev`에서는 없다. 동시에 보낸 요청은 한도를 한 번 넘을 수 있다.
6. 네 탭(전체 요약·슬라이드별·질문 리스트·AI 대화)은 같은 결과 JSON을 나눠 보여준다. 왼쪽 슬라이드·PIN은 세션 스토어의 슬라이드와 질문으로 기존 `SlideCanvas`가 그린다. AI 대화는 메시지마다 Claude 1회이며 분석 결과와 질문 목록을 한 줄씩의 평문(JSON·UUID 없이 질문 번호)으로 시스템 프롬프트에 주고 prompt cache를 건다. PDF 전체는 대화에 보내지 않는다. 슬라이드는 분석과 같은 형식(poppler 쪽 이미지 + 읽을 수 있는 추출 글자 + 그 슬라이드 PIN의 이미지 기준 픽셀 좌표와 대화 자료의 질문 번호)으로 보여 준다. 강사 메시지가 슬라이드를 지목하면("2페이지", "3번 슬라이드", "슬라이드 4", "이 슬라이드"=화면의 슬라이드, 최대 3장) 서버가 질문과 함께 먼저 첨부하고, 그 밖에는 모델에 `view_slides` 도구(최대 3장, 한 답변에 2번)를 준다. 분석 결과는 요약이라 위치·그림·표·문구·수치·질문이 몰린 곳을 담지 못하므로, 그런 질문이면 분석 결과가 있어도 슬라이드를 보고 답하게 하고 분석 결과만으로 답하는 것은 전체 요약·경향·개선 제안 질문으로 한정한다(2026-10-22 사용자 요청: 기준을 보수적으로). 답에는 질문 번호와 픽셀 좌표를 쓰지 않고 요소 이름으로 말한다. 답은 평문이며 강조는 `**굵게**`만 허용하고, 화면은 그 표기만 `<strong>`으로 그린다(나머지 마크다운은 쓰지 않게 하고 렌더러·라이브러리는 두지 않는다). 서버는 슬라이드가 필요할 때만 강사 JWT로 자료를 다시 읽고, 원본은 `/api/pdf`와 같은 서버 디스크 캐시 파일을 그대로 렌더링하고 이미지 슬라이드는 2단계와 같이 저장된 JPEG를 쓰며, 임시 이미지는 답 뒤에 지운다. 분석 이후 슬라이드 수가 바뀐 자료는 보지 못한다고 알린다. 연결이 끊기거나 중단된 답은 저장하지 않는다. 화면은 강사가 보고 있는 슬라이드 번호를 함께 보내고, 서버는 이를 질문 앞에 한 줄로 붙인다(대화 이력에는 저장하지 않음). 슬라이드 한 장은 약 1,600~2,400토큰이다. 답변은 `text/plain` 스트림으로 토큰이 오는 대로 화면에 이어 쓰고, 서버는 답변이 끝까지 온 뒤에만 대화 이력에 저장한다. 중간에 끊기면 그 턴은 저장하지 않고 입력을 복원한다. 별도 채팅 라이브러리(Vercel AI SDK 등)는 쓰지 않고 이미 쓰는 `@anthropic-ai/sdk`의 `messages.stream()`과 브라우저 기본 `ReadableStream`을 쓴다(2026-10-21 사용자 요청).
7. 비용 기준(2026-10-22 실측): Claude Haiku 5.5는 요청 하나의 입력이 10만 토큰을 넘으면 그 요청 전체가 5배 단가다. 쪽 이미지는 약 1,560토큰, 추출 글자를 더하면 약 2,400토큰이므로 조각을 20쪽으로 두고, 출력 상한은 32,000토큰이다. Claude 호출마다 서버 로그에 `insight_claude_usage` 한 줄(단계 slides/merge/chat, 모델, prompt=입력+캐시 읽기+캐시 쓰기, output, `over100k`)을 남겨 추정이 아닌 실측으로 비용과 5배 구간 진입을 본다. 프롬프트·답변 본문은 남기지 않는다. 2026-10-22 실측: 15쪽 분석은 slides 30,087/4,814, merge 9,934/2,913토큰(약 $0.005~0.008), 대화 첫 질문 5,381/481, 다음 질문 캐시 읽기 5,288/485. 100쪽 이미지 위주 자료와 PIN 2,000개 기준 분석 1회 약 $0.08, 대화용 평문 맥락은 약 8.8만 토큰이다. 병합 입력은 질문 목록이 대부분이라 PIN 약 2,500개부터 10만 토큰을 넘는다.
8. 강사가 "리포트 확정"을 누르면 `confirmed`가 되고 그 뒤에만 PDF·PPTX·DOCX·Markdown으로 내보낸다. 내보내기(2026-10-23 사용자 요청으로 개정)는 OhPin 디자인시스템 토큰(브랜드 파랑, 중립 회색, 1px 테두리 카드, 연파랑 AI 카드, 상태 배지)으로 구성한다. 표지에 강의명·파일명·날짜·확정/AI 판단 배지·핵심 수치(질문·미답변·답변·공감)·AI 전체 요약·질문이 몰린 슬라이드·개선 제안을 두고, 이어서 슬라이드마다 주제·수치·슬라이드 이미지(분석과 같은 `renderMaterialSlides` 결과, 서버당 한 번에 한 자료만 렌더링)·질문 요약 또는 내용 정리·개선 제안·그 슬라이드의 질문과 답변을 둔다. 전체 질문 묶음 목록은 넣지 않는다. 분석 이후 슬라이드 수가 바뀐 자료는 이미지를 빼고, Markdown은 텍스트만 담는다. PDF는 나눔고딕 Regular·Bold(OFL)를 넣는다.

모델과 설정: 기본 `claude-haiku-5-5`(속도 우선, 사용자 승인), `INSIGHT_CLAUDE_MODEL`로 교체 가능. `output_config.effort: low`, 스트리밍으로 수신. API 키는 `.env.local`의 `CLAUDE_API_KEY`를 쓰고 배포 시 `ENV_FILE`에 같은 줄을 넣는다. `INSIGHT_AI_ENABLED`, `INSIGHT_GROQ_ZDR_CONFIRMED`, `INSIGHT_TEST_OWNER_ID`, `INSIGHT_QUOTE_SECRET`, `GROQ_API_KEY`는 더 이상 읽지 않는다.

저장: `ai_insight_reports(id, owner_id, material_id, status running|failed|ready|confirmed, body jsonb, error, messages jsonb, created_at, confirmed_at)` 하나. service_role만 접근하고 API가 소유자를 검사한다. 이전 미배포 마이그레이션 두 개(`insight_captured_snapshots`, `insight_reports`)는 삭제하고 새 마이그레이션 하나로 대체한다.

검증(2026-10-21): 사용자의 실제 자료(슬라이드 15장, 질문 17개)를 `claude-haiku-5-5`로 분석해 31초 만에 `ready`가 됐고, 대화 응답 4초, 확정 후 PDF·PPTX·DOCX·Markdown 내보내기 4종 모두 200으로 생성됐다(PDF는 `pdftotext`로 한글 확인, DOCX·PPTX는 zip 무결성 확인). 테스트 7개, `npm run lint`, `npm run build` 통과. 남은 확인: 실제 Word·PowerPoint에서의 시각 검토, 100쪽 이상 자료의 분할 경로 실측, 운영 배포(`ENV_FILE`에 `CLAUDE_API_KEY` 추가).
