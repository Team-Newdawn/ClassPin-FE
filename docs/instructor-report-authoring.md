기존 `/admin/insights` 분석 화면을 없애고, 같은 분석 결과를 **편집 가능한 리포트 초안**으로 바꾸는 작성 페이지를 만든다. 인사이트 대시보드는 별도 문서로 다룬다.

## 1. 결정 (2026-10-26)

- `RPT-001` 리포트 하나는 자료(파일) 하나를 다룬다. 한 자료에 리포트를 여러 개 만들 수 있다(예: 템플릿별). 2026-11-02 사용자가 자료당 하나 규칙을 풀었다(마이그레이션 `20261102090000`). 리포트는 모두 그 자료의 전체 질문을 근거로 하며, 회차별 질문 범위는 BE 회차 데이터가 생긴 뒤에 다룬다.
- `RPT-002` 확정 단계가 없다. 초안 생성이 끝난 뒤에는 언제든 편집하고 내보낼 수 있다. 기존 AIR-PROD-012/013/078(확정 전 다운로드 금지, 직접 편집 금지)을 대체한다.
- `RPT-003` 편집기는 섹션 목록과 리포트 서식(RPT-024)을 지원한다. 굵게·기울임·밑줄·링크와 글자 크기는 강사가 직접 넣고, 표는 AI만 넣는다(2026-10-30 사용자 요청).
- `RPT-004` AI 채팅은 리포트당 사용자 질문 5회로 제한한다. 요금제가 생기면 그때 바꾼다. 초안 생성, 문서 적용, 되돌리기는 횟수에 포함하지 않는다. "새 대화"는 대화 내용만 지우고 횟수는 그대로 둔다(기존 규칙 유지).
- `RPT-005` 초안은 기존 AI 분석(`analyzeInsight`)을 1회 실행해 만든다. 분석 화면만 없애고 분석 파이프라인은 초안 생성기로 재사용한다.
- `RPT-006` AI 편집에 넘기는 근거는 슬라이드 단위로 자른다. 요청과 관련된 슬라이드의 원본 이미지, 추출 텍스트, 그 슬라이드의 질문·답변·공감·PIN 좌표를 함께 보낸다(기존 `view_slides` 방식). PIN 주변 crop은 확장 방안이다.
- `RPT-007` 총 참여자 수는 플레이어가 세던 접속 탭 수를 강의 종료 시 FE 소유 테이블에 저장해 얻는다(§8). BE 변경은 없다.

## 2. 화면과 진입

- `RPT-010` 라우트는 `/admin/reports`(메인: 만들기와 내 리포트 목록, 2026-11-01)와 `/admin/reports/[id]`(작성) 두 개다. 둘 다 admin guard 안에 두고, 사이드바의 `홈으로 › 분석` 아래에 `리포트` 항목을 둔다. 2026-10-27 사용자 지적으로 옛 앱 셸 사이드바와 고아 라우트 `/admin/materials`를 삭제했다.
- `RPT-011` 리포트 메인(Figma `ClassPin` 2227:2258): ① 어떤 자료로 만들까요?(폴더 → 자료 네이티브 select, 강의가 끝나지 않은 자료는 고를 수 없다) ② 어떤 형태로 만들까요?(템플릿 카드 4개, RPT-036) ③ 추가로 요청할 내용(선택, 500자) → `AI로 리포트 만들기`. 아래 **내 리포트 n**은 `GET /api/admin/reports` 카드 격자다(문서 아이콘, 제목, `템플릿 · 폴더`, 작성 중·초안 실패 표시, 상대 시각 `방금 수정됨`·`n분 전`·`n시간 전`·`어제`·날짜, 최근 수정순). 같은 자료로 다시 만들면 새 리포트가 하나 더 생긴다(RPT-001). 카드 오른쪽 위 휴지통 버튼(accessible name `<제목> 리포트 삭제`)은 확인 다이얼로그(폴더 삭제와 같은 모양, Esc·바깥 클릭·취소로 닫힘, 실패는 다이얼로그 안에 표시) 후 `DELETE /api/admin/reports/[id]`로 리포트를 지우고 목록에서 뺀다(되돌릴 수 없음, 2026-11-02 사용자 요청).
- `RPT-012` 진입점: ① 사이드바 `리포트` ② 분석 대시보드의 `AI 리포트 만들기`와 내보내기 팝업의 `AI 리포트로 이어서 작성` ③ 강의 종료 리포트의 `리포트 작성`. ②③은 `/admin/reports?material=<자료 id>`로 가서 그 자료(와 폴더)를 미리 고른다(2026-11-01). 자료의 강의가 끝나지 않았으면 만들 수 없다(기존 `LECTURE_NOT_ENDED` 유지).
- `RPT-013` 작성 화면은 왼쪽 문서 편집, 오른쪽 AI 채팅의 2분할이다. 경계는 라이브 플레이어 질문 패널과 같은 방식으로 크기를 조절하고, 키보드로도 조절할 수 있다. 좁은 화면에서는 위아래로 쌓는다. 2026-11-02 Figma `ClassPin` 2224:2222로 바꿨다: 왼쪽 폴더 사이드바(다른 관리 화면과 같은 컴포넌트, 이 화면에서는 아이콘만 보이게 접힌 채 시작), 가운데 문서 캔버스 박스, 오른쪽 AI 채팅 박스(420px)의 3단이며 두 박스는 1px border·radius 16이고 페이지 배경 위에 16px 간격으로 놓인다. 채팅 크기 조절은 없앴고, 채팅 머리의 닫기 버튼과 캔버스 머리의 `AI 리포트 도우미 열기` 버튼으로 열고 닫는다. 닫으면 캔버스가 그 폭까지 넓어진다. 1024px 이상은 열린 채, 그 아래는 닫힌 채 시작한다. 버튼을 누르면 포커스는 반대쪽 버튼(닫기 → 열기 버튼, 열기 → 채팅 입력창)으로 간다. 뒤로 링크는 사이드바 `리포트`로 대신한다.
- `RPT-014` 머리줄은 리포트 제목, 저장 상태(`저장됨`/`저장 중`/`저장 실패`), `내보내기 ▾`(PDF·DOCX·PPTX·MD)를 둔다. 머리줄의 `되돌리기`와 인사이트 대시보드 링크는 2026-10-31 사용자 요청으로 뺐다. 되돌리기는 변경안 카드(RPT-106)에만 남는다.

## 3. 문서 모델

```ts
type ReportDocument = {
  title: string;
  /** 초안 생성 시점의 코드 집계. 편집 대상이 아니며 내보내기의 수치 표·카드가 이것을 쓴다. */
  metrics: { at: string; slides: number; questions: number; pins: number;
    reactions: number; durationMinutes: number | null; audience: number | null; peakAudience: number | null };
  /** text는 리포트 서식(RPT-024) 문자열이다. */
  sections: { id: string; title: string; text: string; /** 1-based 슬라이드 번호. 있으면 내보내기에 그 슬라이드 이미지를 붙인다. */ slide?: number }[];
};
```

- `RPT-020` 섹션은 제목 한 줄과 리포트 서식 본문이다. 본문의 줄바꿈과 `- ` 목록 줄은 내보내기에서 그대로 유지한다.
- `RPT-021` 섹션 추가와 삭제를 제공한다. 삭제는 섹션 제목 오른쪽 휴지통 버튼(마우스를 올리거나 키보드 포커스가 들어오면 보임, 터치 화면은 항상 보임, 이름 `섹션 n 삭제`)이며 확인 없이 지우고, 문서 끝에 `‘제목’ 섹션을 지웠어요 · 되돌리기`를 보인다. 되돌리기는 같은 자리로 되살리며, 다음 삭제나 페이지 이동까지 유지된다(화면 안 기억, 서버 되돌리기 RPT-043과 별개). 삭제한 뒤 포커스는 그 자리를 이은 섹션(없으면 앞 섹션)으로 간다(2026-11-02 사용자 요청으로 삭제를 되살림). 위아래 이동·슬라이드 연결은 계속 AI 변경안으로 한다.
- `RPT-022` 제한: 섹션 300개, 섹션 본문 2만 자, 문서 전체 50만 자. 서버가 다시 검증한다.
- `RPT-024` 리포트 서식은 본문 문자열 안의 작은 마크다운 부분집합이다. 저장 형식이 문자열 그대로라 저장·409·변경안·되돌리기·제한(RPT-022, 기호 포함 글자 수)은 바뀌지 않는다.
  - `**굵게**`, `<i>기울임</i>`, `<u>밑줄</u>`, `<big>크게</big>`, `<small>작게</small>`, `[글자](https://주소)`: 한 문장 안에서도 쓸 수 있는 인라인 서식. 크기는 보통을 포함해 3단계다. 서로 겹쳐 쓸 수 있다(굵고 큰 글자). 바깥부터 크기 → 링크 → 기울임 → 밑줄 → 굵게 순서로 쓴다. 링크 주소는 공백·따옴표·꺾쇠·괄호 없는 `http://`·`https://` 주소만 링크가 되고, 그 밖(`javascript:` 등)은 글자 그대로 보인다(2026-11-02 사용자 요청으로 기울임·밑줄·링크 추가).
  - 표: GFM 파이프 표(`| 항목 | 값 |` 머리 줄, `|---|---|` 구분 줄, 본문 줄). 첫 줄은 머리 행이다. 칸 안에는 인라인 서식만 쓴다. 최대 8열 50행.
  - 이 밖의 기호(`#`, 이미지, 다른 HTML 태그)는 글자 그대로 보인다. 화면은 파싱한 결과를 이스케이프해서 그리며 저장된 HTML을 그대로 넣지 않는다.
  - 파서는 순수 함수 하나(`parseReportText`)이고 편집기·네 내보내기·Node 테스트가 함께 쓴다. 서버 검증(RPT-022)은 문자열 길이만 본다. 잘못된 표는 글자 그대로 보일 뿐 저장을 막지 않는다.
- `RPT-023` 수치 중 `audience`·`peakAudience`는 §8 기록이 없으면 null이고, 화면과 내보내기에 `기록 없음`으로 표시한다. 참여율은 분모 데이터가 없어 넣지 않는다. 답변 기능이 숨김 상태라 미답변·답변됨·해결됨·답변 수도 넣지 않는다(2026-10-29 사용자 요청).

## 4. 초안 생성

- `RPT-030` 리포트를 만들면 행을 `drafting` 상태로 저장하고, 기존 생성 route처럼 Next `after()`에서 슬라이드 렌더 → `analyzeInsight` → 초안 변환을 실행한다. 일일 생성 한도, 실행 중 취소, 15분 정체 판정은 기존 값을 그대로 쓴다.
- `RPT-031` 초안 변환은 순수 함수 하나(`draftFromAnalysis(body, metrics)`)로 만들고 Node 테스트를 둔다. 섹션 순서:
  1. **개요**: 수치 요약 한 문단. 수치 자체는 `metrics`에 있다.
  2. **AI가 정한 본문 섹션**(RPT-035).
  3. **주제별 분석**: `groups`마다 섹션 하나. 요약과 대표 질문 최대 5개를 인용한다.
  4. **슬라이드별 분석**: 슬라이드마다 섹션 하나(`slide` 연결). 주제, 질문 요약 또는 내용 정리, 쟁점, 제안, 공감 많은 순 질문 최대 10개와 그 답변, 나머지는 `외 n개`.
- `RPT-032` 분석 중에는 편집기를 읽기 전용으로 두고 진행 상태와 취소 버튼을 보여준다. 페이지를 떠났다가 돌아와도 상태를 이어서 보여준다. 진행 상태는 실제 단계(슬라이드 준비 → 슬라이드 분석 n/전체 장 → 본문 작성)를 따른다. 슬라이드 분석이 끝나면 개요와 슬라이드별 섹션을 읽기 전용 미리보기로 먼저 보이고, 본문 자리는 스켈레톤으로 둔다(2026-11-02 사용자 요청). 미리보기는 서버 메모리에만 두고 `GET /api/admin/reports/[id]`의 `progress`로만 내려주며 저장하지 않으므로, 문서가 생기기 전에는 아무것도 저장되지 않는다. 서버 로그 `[report-draft]`는 단계별 소요 시간만(내용 없이) 남긴다.
- `RPT-033` 분석이 실패하거나 취소되면 `다시 시도`와 `수치만으로 시작`을 제공한다. 수치만으로 시작하면 1번 섹션과 질문 원문만 담은 슬라이드별 섹션으로 초안을 만든다.
- `RPT-034` (2026-11-02 사용자 요청으로 삭제) 문서가 있는 리포트의 `초안 다시 만들기`와 그 횟수 제한(리포트당 2회, `REDRAFT_LIMIT`)을 없앴다. 문서를 새로 쓰려면 AI 채팅의 변경안을 쓰거나 같은 자료로 리포트를 새로 만든다(RPT-001). `instructor_reports.redrafts` 칼럼(마이그레이션 `20261029090000`)은 기존 데이터라 지우지 않고 더 이상 읽거나 쓰지 않는다. 예전에 다시 만들기가 실패해 `failed` 상태로 남은 리포트도 문서가 있으면 그대로 편집할 수 있다.
- `RPT-035` **자료에 맞춘 리포트 양식(2026-10-31 사용자 결정).** 리포트 양식은 고정 틀이 아니라 AI가 자료에 맞게 정한다.
- `RPT-036` **템플릿(2026-11-01 사용자 결정).** 강사가 메인에서 고른 템플릿과 추가 요청을 `instructor_reports.template`·`request`(마이그레이션 `20261101100000_instructor_report_templates.sql`)에 저장하고, 초안(실패한 첫 초안의 `다시 시도` 포함)에 쓴다. 제목은 `{자료} · {템플릿명}`이다. 템플릿은 AI 구성 단계에 지시 한 줄을 더하고(자료 종류·폴더 목적 규칙 RPT-035는 그대로), 코드가 뒤에 붙이는 섹션을 정한다.
  - **보고용**(기본 선택, 2026-11-02 사용자 결정으로 `경영진 보고용`에서 일반화. 저장 값은 `executive` 그대로): 독자는 강의를 듣지 않은 제3자(기관 담당자·상사·고객사)이고, 읽고 결과를 확인한 뒤 후속 조치를 정한다. 섹션 5개를 이 순서와 제목으로 고정하고 AI가 구성을 정하지 않는다(RPT-035 예외). 문체는 개조식(`~함`·`~임` 등 명사형 종결), 분량은 A4 1~2장.
    1. `개요`(코드): 강의명, 일시(LIVE 시작 시각), 진행 시간, 대상·목적(폴더 이름 · 사용 목적, 미분류면 `미분류`). 값이 없으면 `기록 없음`.
    2. `참여 결과`(코드 + AI): 참여자 수(최대 동시), 질문 수와 1인당 질문 수(참여자 기록이 있을 때), 핀이 찍힌 슬라이드 수/전체(비율), 공감 수를 코드가 넣고, 그 아래에 AI가 해석 1~2줄을 쓴다.
    3. `청중 관심사 Top 3`(코드): AI 주제 묶음(groups)을 질문 수 많은 순으로 3개, 주제마다 요약과 대표 질문 1개(공감 많은 순). 묶음이 없으면 그렇다고 한 줄 쓴다.
    4. `결론`(AI): 이번 강의에서 확인된 것 3줄 이내.
    5. `후속 조치 제안`(AI): 담당자가 승인·결정할 수 있는 조치 최대 3개.
    - 넣지 않는다: 슬라이드별 상세 분석과 질문 원문 대량 인용(수업 개선용의 몫), 답변 여부(답변 기능 숨김), 다른 강의와의 비교, `성공적` 같은 단정.
    - AI 합치기 단계는 sections를 정확히 3개(참여 결과 해석·결론·후속 조치 제안) 순서대로 내고, 코드는 제목과 무관하게 순서로 받아 고정 제목을 붙인다. 모자라면 빈 본문으로 둔다. 수치만으로 시작(AI 없음)은 다른 템플릿과 같은 수치 초안이다. 초안 미리보기(RPT-032)에는 `개요`만 보인다(나머지는 본문 단계가 끝나야 생긴다). 이미 만든 리포트의 제목(`… · 경영진 보고용`)은 그대로 둔다.
  - 수업 개선용: 질문이 몰린 슬라이드·이유·개선점, 섹션 3~5개 / 주제 묶음과 질문 있는 슬라이드만 붙인다.
  - 한 장 요약: A4 한 장, 섹션 2~3개·각 5줄 이내 / 아무것도 붙이지 않는다.
  - 빈 문서에서 시작: AI를 부르지 않고 개요 섹션 하나로 시작한다. AI 키가 없어도 되고 하루 초안 한도(2회)에 들어가지 않는다. AI 본문이 필요하면 AI 채팅으로 요청한다.
  - 추가 요청은 강사가 쓴 글이라 `redactInsightText`를 거쳐 따옴표 안에 넣고 "위 규칙과 충돌하지 않는 범위에서 반영"하라고 지시한다.
  - 템플릿 전의 리포트는 `template`이 null이고 목록에 "자료 맞춤"으로 보인다. 동작은 예전(RPT-035)과 같다.
  - 자료 종류는 AI가 스스로 판단한다(슬라이드 분석의 `category`). 판단 근거로 자료가 속한 폴더의 이름과 사용 목적(기타면 목적 이름)을 프롬프트에 넣는다. 미분류 자료는 자료만 보고 판단한다. 폴더 이름은 강사 입력이므로 데이터로만 취급한다.
  - 합치기 단계에서 AI가 본문 섹션 3~7개(`sections: {title, text}[]`)의 구성·제목·내용을 정한다. 예: 대학 강의면 흐름·혼란 지점·개선 제안, 창업 캠프 발표면 사업 항목 점검·심사 관점 질문·다음 발표 보완점. 본문은 리포트 서식(RPT-024)으로 쓰고, 항목 비교가 표로 더 읽기 쉬우면 표를 넣을 수 있다(AI만 표를 넣는 규칙 그대로). 숫자 통계, 발표 성공·투자 가치 같은 단정은 쓰지 않는다.
  - 코드는 RPT-022 길이 제한과 최대 7개만 지킨다. AI 섹션이 하나도 없으면 개요 뒤에 바로 근거 섹션이 온다.
  - 근거 섹션(주제별 묶음, 슬라이드별 분석)은 질문 원문 인용과 슬라이드 연결이 필요해 코드가 그대로 만든다. 대시보드 주제별 묶음(DSH-035)도 같은 `groups`를 쓴다.
  - 기존 `overall`(요약·주목할 슬라이드·개선 제안)은 `sections`로 대체한다. 저장된 옛 `analysis`는 대시보드가 `groups`만 읽으므로 그대로 둔다. 기존 리포트는 옛 양식 그대로 두고, 새 양식이 필요하면 리포트를 새로 만든다.
## 5. 편집과 저장

- `RPT-040` 입력이 멈추고 1초 뒤 자동 저장한다. 저장 요청에는 마지막으로 받은 `updatedAt`을 함께 보내고, 서버의 값과 다르면 409를 돌려준다.
- `RPT-041` 409를 받으면 덮어쓰지 않는다. `다른 곳에서 수정됨`을 알리고 `내 내용으로 저장` 또는 `최신 내용 불러오기`를 고르게 한다.
- `RPT-042` 저장이 실패하면 편집 내용을 메모리에 유지하고 재시도한다. 저장하지 못한 변경이 있으면 페이지를 떠나기 전에 브라우저 경고를 띄운다.
- `RPT-043` `되돌리기`는 1단계다. 문서를 통째로 바꾸는 동작(AI 변경안 적용) 직전의 문서를 서버의 `previous_document`에 저장하고, 되돌리면 현재 문서와 맞바꾼다. 일반 타이핑은 브라우저 기본 undo에 맡긴다.

## 6. AI 채팅과 AI 편집

- `RPT-050` 기존 채팅 흐름을 그대로 옮긴다: provider 어댑터(`InsightAi.chat`), 텍스트 스트리밍, 질문 선점 후 실패 시 환불, 중지, 리포트당 동시 답변 1개, 90초 제한.
- `RPT-051` 고정 컨텍스트는 분석 결과 대신 **현재 문서**(섹션 번호·제목·본문)와 원본 데이터(슬라이드 번호·제목, 슬라이드별 질문 본문·상태·공감·답변)다. 문서가 6만 자를 넘으면 섹션 제목만 넣고, 사용자가 말한 섹션과 슬라이드의 본문만 붙인다.
- `RPT-052` 슬라이드 근거(RPT-006): 메시지에 슬라이드 번호가 있으면 미리 붙이고(`slidesMentioned`), 그 밖에는 모델이 `view_slides`로 요청한다. 한 답변에 최대 6장. 원본은 강사 JWT로만 읽는다.
- `RPT-053` 모델에 `propose_document` 도구를 준다. 문서를 고쳐 달라는 요청이면 모델이 이 도구로 변경안을 낸다. 변경안은 `{ replace: {id,title,text}[], insert: {after,title,text,slide?}[], remove: id[] }`이며, 문서 전체를 다시 쓰는 요청도 이 형식으로 표현한다. 서버는 존재하지 않는 id, 범위 밖 슬라이드, RPT-022 제한 위반을 거절하고 모델에 다시 내게 한다(1회).
- `RPT-054` 변경안이 있는 답변에는 바뀌는 섹션 수와 `문서에 적용` 버튼을 보여준다. 적용하면 문서가 새로 작성되고(RPT-043 되돌리기 가능), 변경안이 만들어진 뒤 사용자가 같은 섹션을 고쳤으면 적용 전에 덮어쓰기를 확인받는다. 적용은 채팅 횟수에 포함하지 않는다.
- `RPT-056` AI는 섹션 본문에 리포트 서식(RPT-024)을 쓴다. 표는 수치·비교·목록을 정리해 달라는 요청이나 표가 더 읽기 쉬운 경우에만 넣는다. 채팅 답변 자체는 지금처럼 평문과 `**굵게**`만 쓴다.
- `RPT-055` speaker note, 참여자 식별자, 이메일은 모델에 보내지 않는다. 기존 질문 비식별 처리를 유지한다.
- `RPT-057` 입력창 안의 첨부 버튼으로 질문마다 파일 1개(PDF, PNG·JPG, TXT·MD·CSV; 10MB, 이미지 5MB 이하)를 붙인다. 형식은 이름이 아니라 파일 바이트(PDF·PNG·JPEG 서명, 그 밖에는 올바른 UTF-8 글자)로 서버가 다시 판단하고, 글자 파일은 앞 5만 자만 비식별 처리해 보낸다. 파일은 저장하지 않고 그 질문에만 AI에 보낸다. 대화 기록에는 파일 이름만 남고 다음 질문에서는 다시 보내지 않는다. 입력창 위쪽에 파일 이름 칩(Figma `ClassPin` 2224:2314)과 빼기 버튼을 보인다(2026-11-02 승인).
- `RPT-058` 입력창의 `슬라이드·질문 데이터 포함`(기본)·`문서만 사용` 선택(네이티브 select)을 질문마다 보낸다. 문서만 사용이면 원본 질문 목록, 슬라이드 자동 첨부, `view_slides`를 빼고 문서(수치 포함)와 첨부만 보낸다. 선택은 저장하지 않는다.
- `RPT-059` 입력창 바로 위에 추천 요청 칩(Figma `ClassPin` 2224:2305)을 둔다. AI를 부르지 않고 코드가 고른다: `더 간결하게`, `표로 정리`, 질문이 가장 많은 슬라이드의 `슬라이드 n 원인`. 칩은 입력창을 채우기만 하고 보내지 않는다(질문 횟수 보호). 편집기에 그래프가 없으므로 `그래프 추가`는 두지 않는다.

## 7. 내보내기

- `RPT-060` 생성이 끝난 리포트는 언제든 내보낼 수 있다. 입력은 저장된 문서이며, 내보내기 전에 저장하지 않은 변경을 먼저 저장한다. 강사당 동시 내보내기 1개, 미리보기 제공은 기존 동작을 유지한다. 내보내기 팝업은 분석 대시보드와 같은 컴포넌트이며 형식 카드 모양은 Figma `ClassPin` 2236:2842를 따른다(2026-11-01).
- `RPT-061` **PDF·DOCX(작성한 그대로)**: A4 세로. 제목 → 수치 표 → 섹션을 편집기 순서대로. 슬라이드가 연결된 섹션은 본문 위에 슬라이드 이미지를 페이지 폭에 맞춰 넣는다. 본문 글자는 작게 8.5pt·보통 10.5pt·크게 14pt, 굵게는 굵은 글꼴이다. 표는 페이지 폭의 격자이고 머리 행은 굵게, 칸 너비는 같게 나눈다. 표가 페이지를 넘으면 행 경계에서 넘기고 다음 페이지에 머리 행을 다시 그린다. 기울임은 기울임 글꼴(PDF는 나눔고딕에 기울임체가 없어 12도 기울인 글자), 밑줄은 밑줄, 링크는 브랜드 색·밑줄의 누를 수 있는 링크(PDF는 URI 주석)다.
- `RPT-062` **PPTX(재구성)**: 16:9. 표지(제목, 자료 이름, 날짜) → 수치 카드 1장 → 섹션마다 1장. 슬라이드가 연결된 섹션은 왼쪽 이미지, 오른쪽 본문이고, 연결이 없으면 본문 전체 폭이다. 본문이 장에 들어갈 줄 수를 넘으면 문단 경계에서 다음 장으로 넘기고 제목에 `(계속)`을 붙인다. 글자를 자동으로 줄이지 않는다. 본문 글자는 작게 11pt·보통 14pt·크게 18pt다. 표는 PowerPoint 표로 넣고 한 행을 한 줄로 센다. 한 장에 다 들어가지 않는 표는 행 경계에서 나누고 이어지는 장에 머리 행을 다시 넣는다.
- `RPT-063` **MD(재구성)**: `# 제목`, 수치 표, 섹션마다 `## 제목`과 본문. 굵게와 표는 마크다운 그대로 두고, 글자 크기 태그는 지운다(MD에는 크기가 없다). 이미지는 넣지 않고, 슬라이드가 연결된 섹션은 제목 아래에 `슬라이드 n` 참조를 넣는다. `<i>`는 `*기울임*`이 되고 `<u>`는 지운다(MD에는 밑줄이 없다). 링크는 그대로다.
- `RPT-064` 재구성 규칙은 코드로 고정한다. 내보내기는 AI를 호출하지 않으며, 같은 문서는 항상 같은 파일이 된다. A4 문서와 PPTX·MD는 배치가 다르지만 담는 문장과 수치는 같아야 한다.

## 8. 강의 참여자 수 저장

- `RPT-070` 플레이어의 접속자 집계(`useLiveAudienceCount`)는 LIVE 동안 본 탭 id의 누적 수와 최대 동시 접속 수를 함께 센다. 값은 기존 heartbeat를 그대로 쓰며 새 broadcast를 추가하지 않는다.
- `RPT-071` 강사가 플레이어에서 강의를 종료해 저장에 성공하면, 그 두 값과 `started_at`·`ended_at`을 `POST /api/admin/lectures/[id]/audience`로 보낸다. route는 강사 JWT로 REST 소유권을 확인한 뒤 서버 권한으로 저장한다. 같은 강의를 다시 LIVE로 열고 종료하면 마지막 회차 값으로 덮어쓴다(`started_at`과 같은 규칙).
- `RPT-072` 한계: 값은 탭 기준 근사치이며 출석이 아니다. 강의 창이 처음부터 끝까지 열려 있었을 때만 정확하다. 자동 종료(60분 이탈)나 다른 경로로 끝난 강의는 기록이 없다. 정확한 값이 필요하면 BE 집계로 옮긴다.

## 9. 데이터, API, 권한

FE forward-only 마이그레이션 하나로 두 테이블을 만든다. 둘 다 RLS를 켜고 `anon`/`authenticated` 권한을 회수하며, 서버(service_role)만 읽고 쓴다. route는 매 요청 강사 JWT로 소유자를 확인하고, 소유자 id를 요청 본문에서 받지 않는다(기존 `ai_insight_reports`와 같은 패턴).

```sql
instructor_reports(id uuid pk, owner_id uuid not null, material_id uuid not null,
  status text check (status in ('drafting','failed','ready')), error text,
  document jsonb, previous_document jsonb, messages jsonb not null default '[]',
  created_at timestamptz, updated_at timestamptz, unique (owner_id, material_id))
lecture_audience_records(lecture_id uuid pk, owner_id uuid not null, started_at timestamptz, ended_at timestamptz,
  audience int not null check (audience >= 0), peak_audience int not null check (peak_audience >= 0), recorded_at timestamptz)
```

## 10. 지울 것과 확장 방안

지울 것: `app/component/insight-workspace.tsx`와 그 CSS, `/admin/insights` 페이지, `app/api/admin/ai-reports/*` route, 분석 결과 기준의 export 모델(`reportModel`, `insightExportSections`), 자료 카드의 "준비된 리포트가 있을 때만 아이콘" 조건. `analyzeInsight`, provider 어댑터, 슬라이드 렌더, REST 소유 자료 읽기, `view_slides`는 유지한다.

확장 방안(지금 만들지 않음):
- 서식 확장: 기울임·색·제목 단계, 강사가 직접 넣는 표가 필요해지면 RPT-024에 문법을 더하고 형식별 변환을 추가한다.
- PIN 주변 crop: AI가 PIN이 가리킨 요소를 자주 틀리면 `view_slides` 결과에 crop 이미지를 더한다.
- BE 집계 참여자 수와 참여율: 질문한 고유 참여자 수를 BE가 제공하면 참여율을 정의한다.

## 11. 접근성과 오류

- `RPT-090` 모든 컨트롤에 accessible name과 focus-visible을 둔다. 섹션 편집, 이동, 슬라이드 연결, 패널 크기 조절, 채팅, 적용, 되돌리기, 내보내기를 키보드로 할 수 있어야 한다.
- `RPT-091` 저장 상태, 분석 진행, AI 응답 완료는 차단 팝업 없이 live region으로 알린다.
- `RPT-092` 오류에는 내부 오류나 AI 제공자 정보를 노출하지 않고, 사용자가 할 수 있는 다음 행동(재시도, 불러오기)을 안내한다. 실패가 마지막 저장 문서를 덮어쓰지 않는다.

## 13. 디자인과 레이아웃

색·글꼴·간격·모서리·그림자는 OhPin 디자인 시스템(`DESIGN.md`, `app/_design-system/tokens.css`)만 쓴다. 참고 서비스에서는 배치만 가져온다. 2026-10-27 사용자 Chrome에서 Readray(구 릴리스AI) 노트 화면과 유니브AI PDF·AI 튜터 화면을 확인했다.

참고한 배치:
- Readray: 왼쪽 목차 rail, 가운데 읽기 폭으로 제한한 문서, 섹션 번호 배지(`01`) + 큰 제목 + 페이지 칩(`p.1`), 본문 속 원본 이미지, 화면 아래 떠 있는 입력창("질문하거나 수정을 요청하세요").
- 유니브AI: 왼쪽 원본 / 오른쪽 작업 패널의 2분할, 패널 위 pill 탭, 대화 답변을 제목·목록이 있는 문서처럼 표시, 패널 아래 고정 입력창.

### 작성 화면 배치

```
┌ 머리줄: ← 인사이트 · 리포트 제목 · 저장됨 ··· 내보내기▾ ┐
├ 목차 rail ┬──────── 문서 (가변) ────────┬─ 경계 ─┬── AI 채팅 (360~560px) ──┐
│ 01 강의 개요│  리포트 제목 (H1)               │ ‖ 리사이즈 │ 대화 (문서형 답변)        │
│ 02 전체 요약│  자료 카드: 파일명 · n장 · 날짜   │       │  └ 변경안 카드 [문서에 적용]│
│ 03 …       │  수치 카드 행                    │       │                          │
│ (접기)     │  01  섹션 제목      [슬라이드 3]  │       │ ┌ 입력창 ──────────────┐ │
│            │  슬라이드 이미지                 │       │ │ 질문하거나 수정을 요청 │ │
│            │  본문 (자동 높이 textarea)       │       │ └ 남은 질문 3/5 · 보내기┘ │
└────────────┴──────────────────────────────┴───────┴──────────────────────────┘
```

- `RPT-100` 문서 열은 PDF 내보내기와 같은 A4 페이지다(최대 794px = 210mm@96dpi, PDF 595pt의 1.334배). 화면 배경은 `--color-bg-page`, 페이지는 `--color-bg-surface`에 1px `--color-border`. 2026-10-29 사용자 요청으로 미리보기와 편집 화면의 형태를 같게 맞췄다.
- `RPT-101` 목차 rail(240px)은 섹션 번호와 제목 목록이다. 현재 보이는 섹션을 `--color-brand` 글자와 `--color-brand-subtle` 배경으로 표시하고, 누르면 그 섹션으로 이동한다. 접을 수 있고, lg 미만에서는 기본으로 접힌다. 2026-11-02부터 목차는 캔버스 박스 안 왼쪽(220px)에 열리며, 1024px 이상에서는 열린 채, 그 아래에서는 서랍으로 닫힌 채 시작한다(같은 날 사용자 요청으로 열림을 기본으로 되돌림).
- `RPT-102` 페이지 머리는 PDF와 같다: `OhPin 리포트`(13/700, `--color-brand`) → 리포트 제목(28/700) → `파일명 · 날짜`(13, secondary) → 2열 수치 표. 섹션은 제목(22/700, 줄바꿈되는 제목) → 슬라이드가 연결되면 `슬라이드 n`(12/700, brand) → 슬라이드 이미지(페이지 폭) → 본문(14/22). 섹션 번호 배지와 칩은 쓰지 않는다(목차에만 번호). 2026-11-02 Figma `ClassPin` 2224:2333으로 바꿨다: 회색 캔버스 위 700px 종이(padding 40/48, radius 12), `AI 강의 리포트` 칩(빈 문서 템플릿은 `강의 리포트`) → 제목 → `날짜 · 진행 n분 · 참여 n명 · 질문 n건` → KPI 카드 네 개(총 질문, 참여자, 핀이 찍힌 슬라이드 n/전체, 공감 수) → `질문이 몰린 슬라이드` 막대(질문 수 상위 3장, 코드가 그림, 읽기 전용) → 섹션(`n.` 번호 + 제목 17/700, 본문 15/24). 핀이 찍힌 슬라이드와 막대는 지금의 자료 데이터로 그리므로 편집 화면에만 있고, 내보내기는 지금처럼 수치 표를 쓴다.
- `RPT-103` 편집은 제자리에서 한다. 제목은 테두리 없는 input, 본문은 서식이 보이는 편집 영역(contentEditable, Body 14/22, 크게 18/28·작게 12/18)이며, 포커스할 때만 `--focus` 링을 보인다. 편집할 수 있는 동안 문서 열 위에 서식 도구(굵게 `Ctrl/⌘+B`, 크게, 보통, 작게)를 고정해 두고, 본문에서 글자를 선택하기 전에는 비활성으로 둔다. 도구는 마지막으로 선택한 본문 글자에 적용하므로 키보드로 선택한 뒤 도구로 옮겨 가도 된다. 도구는 accessible name과 눌림 상태(`aria-pressed`)를 둔다. 붙여넣거나 끌어 놓은 내용은 서식 없이 글자만 남긴다. 표는 편집기에서 읽기 전용 블록이다: 표 추가·삭제 버튼은 없고 칸을 직접 고칠 수 없다. 표를 만들거나 고치거나 지우려면 AI에게 요청한다(2026-10-30 사용자 요청으로 표 삭제 버튼을 뺐다). 2026-11-02부터 서식 도구는 문서 열 맨 위에 붙은 44px 막대(Figma 2224:2357)다: 글자 스타일 select(제목 18/28·본문 15/24·작게, 저장 형식의 크게·보통·작게와 같다), 굵게·기울임·밑줄(`Ctrl/⌘+B/I/U`, 눌림 상태 표시), 글머리 기호(커서가 있는 줄 앞에 `- `), 표(AI 채팅 입력창을 표 요청으로 채운다. 표는 여전히 AI만 넣는다), 링크(막대 안 주소 입력칸, http(s)가 아니면 입력칸 아래 오류. 글자를 고르지 않았으면 주소를 글자로 넣는다. 커서가 링크 안이면 같은 버튼이 `링크 빼기`), 오른쪽 안내 문구. 차트·이미지는 저장 형식과 저장소가 따로 필요해 보류했다(2026-11-02).
- `RPT-104` 수치 표의 항목·값·날짜는 `metricRows`/`reportDate` 하나를 편집 화면과 네 내보내기가 함께 쓴다. 숫자는 `tabular-nums`, `기록 없음`은 `--color-text-tertiary`.
- `RPT-105` AI 채팅 패널은 `--color-bg-surface`, 왼쪽 1px border. 사용자 메시지는 오른쪽 `--color-bg-subtle` 말풍선(radius 18), AI 답변은 말풍선 없이 문서처럼 Body 14/22로 그린다. 입력창은 패널 아래 고정, radius 18, `--shadow-sm`, 아래에 `남은 질문 n/5`와 보내기·중지 버튼. 2026-11-02부터 채팅 머리는 `AI 리포트 도우미`(스파크 아바타)·`새 대화`·닫기 버튼이다(RPT-013).
- `RPT-106` 변경안은 답변 아래 카드로 보인다: `섹션 3개 수정 · 1개 추가`, 바뀌는 섹션 제목 목록, `문서에 적용`(primary) 버튼. 적용 후 카드는 `적용됨 · 되돌리기`로 바뀐다.
- `RPT-107` 초안 생성 중에는 문서 열에 섹션 모양 skeleton과 진행 문구·취소 버튼을 보여준다. 채팅 입력은 비활성화한다.
- `RPT-108` 1024px 미만은 문서 위, 채팅 아래로 쌓고 목차는 머리줄의 메뉴 버튼으로 연다. 768px 미만은 채팅을 하단 시트로 연다.
- `RPT-109` 머리 줄은 뒤로 · 목차 · 제목(RPT-110) · 저장 배지(저장됨이면 `방금 수정됨`·`n분 전`, 저장 중·실패·충돌은 그 상태) · AI 변경 되돌리기/다시 적용(RPT-043의 한 단계 맞바꾸기, 다시 적용은 이 페이지에서 되돌린 뒤에만) · `공유`(내보내기 팝업, RPT-060)다. AI 변경안을 적용하면 바뀐 섹션에 파란 배경과 `방금 AI가 수정함` 표시를 다음 문서 전체 변경이나 새로고침까지 보인다(Figma 2224:2439).
- `RPT-110` 제목을 누르면 전환 팝오버(Figma `ClassPin` 2227:2667)가 열린다: `이 자료의 리포트`(지금 리포트는 체크), `다른 자료로 새 리포트`(자료 검색, 강의가 끝난 다른 자료. 리포트가 있으면 가장 최근 리포트를 열고, 없으면 `/admin/reports?material=`로 가서 그 자료를 고른다), `새 리포트 만들기`(`/admin/reports`). Esc와 바깥 클릭으로 닫히고 Esc는 제목 버튼으로 포커스를 돌린다.
