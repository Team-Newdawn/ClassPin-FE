# 반론 점검과 위험 요인

- 상태: 2026-10-23 기준. 다중 모델 실험 후 다시 점검한다.

## 체크포인트 1: 연구 질문·방법 (판정: REVISE → 설계 보강으로 해소 예정)

### 치명적 문제: 예비 실험 A·B 비교의 교란

- A 조건(PDF)은 좌표를 정수 %로 반올림했다(`Math.round(p.x / W * 100)`, 가로 1% ≈ 14.5px). B 조건(이미지)은 정확한 픽셀을 받았다.
- Claude 문서에 따르면 PDF는 서버에서 페이지마다 이미지로 바뀌고 텍스트가 함께 들어간다. 래스터 크기는 사용자가 정할 수 없어 좌표를 페이지에 신뢰성 있게 대응시킬 수 없다.
- 따라서 예비 결과(밀집 2쪽 A 72.1% vs B 95.4%)는 입력 형태 효과가 아니라 **좌표 정밀도·좌표계 정합 효과일 가능성이 크다.**
- 대응: 다중 모델 설계에서 정밀도(정수 %·소수 %·0~1000)와 입력 형태를 교차하고, 좌표계 어긋남 조건으로 원인을 직접 검증한다.

### 주요 문제

- 채점: 예비 실험은 Claude Sonnet이 자유 서술 답을 채점했다(같은 계열 판정자). → 요소 ID 폐쇄형 응답으로 자동 채점, 자유 서술 부분집합은 사람 2인 채점(κ 보고).
- 일반화: 한국어 피치덱 1개, 2쪽. → 합성 슬라이드 10장(표·차트·다이어그램·텍스트) + 실제 2쪽.
- 모델: Haiku 하나. → Claude·GPT·Gemini 각 2개 층.
- 천장 효과: 저밀도 조건은 전부 100%. → 밀도 30/70/150.
- 현실성: 질문 문장을 일반 문장으로 고정해 위치만 단서가 되게 했다. 통제 목적상 유지하되, 실제형 문장 조건은 후속(E1b)으로 둔다.

### 보통 문제

- zoom 도구 미사용(0회)은 한 프롬프트·4회 관찰이다. "관찰"로만 쓰고 RQ3에서 체계적으로 측정한다.
- 모델 업데이트로 결과가 바뀔 수 있다. 모델 ID·실행 날짜를 기록하고 설계를 실행 전에 고정(사전 등록)한다.

## 체크포인트 2: 문헌 종합 (판정: PASS)

- 반대 근거(Document Haystack: 긴 문서에서 이미지 입력 성능 하락)를 포함했다.
- "최적 좌표 형식은 모델마다 다르다"(Readout Limit 논문)는 우리 주장에 불리할 수 있으나 가설 H5로 정면 검증한다.

## 체크포인트 3: 최종 취약점 (판정: 수정 후 통과 가능)

- 가장 강한 반론: "상용 모델 하나로 만든 엔지니어링 메모". 대응 세 가지(다중 모델, 좌표계 어긋남 인과 조건, 벤치마크 공개)가 모두 없으면 워크숍 수준이다.

## 윤리·위험

- 학생 데이터: RQ1~2는 합성 데이터만 사용. RQ3에 실제 리포트를 쓰면 질문 원문 익명화, 동의, 기관 심의(IRB) 확인이 필요하다. 기본안은 합성 리포트.
- 외부 API 전송: 실제 피치덱을 GPT·Gemini로 보내면 각 제공자의 데이터 정책을 따른다. Gemini 무료 등급은 입력이 제품 개선에 쓰일 수 있으므로 유료 등급 키 또는 합성 슬라이드만 사용한다.
- 이해관계: 저자가 ClassPin 개발자임을 논문에 밝힌다.
- AI 사용 고지: 문헌 조사와 실험 코드 작성에 AI 도구(Claude)를 사용했음을 밝힌다.
