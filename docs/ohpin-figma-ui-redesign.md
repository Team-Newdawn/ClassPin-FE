# OhPin Figma UI 개편 설계안

작성일: 2026-10-02. 상태: 사용자 승인 (2026-10-02, “구현 해보자”). UI 개편을 먼저 구현한다.

## 1. 기준과 작업 순서

- `OHUI-001`: 사용자 승인 Figma UI·디자인 시스템을 기존 경로와 API 위에 구현하고, 본 문서의 보존·제외·검증 조건을 적용한다.

디자인 기준은 [ClassPin Figma, 15:2](https://www.figma.com/design/DXR54m0Qh6LgYZqZ6xET9u/ClassPin?node-id=15-2)다. 구체적인 화면 프레임과 Color 디자인 시스템을 확인했다. 기존 코드의 UI → controller → session store → REST service 경로를 확인했으며, 구조를 다시 만들지 않고 현재 경로와 인증·업로드·데이터 처리를 재사용한다.

사용자가 요청한 순서는 **설계 확정 → 디자인과 UI부터 구현 → 프런트엔드 기능 변경**이다. 1차 UI 작업과 2차 기능 작업은 아래처럼 구분한다. 기능 요구를 삭제하는 구분이 아니라, UI를 먼저 검토할 수 있게 하는 구현 순서다.

회차별 분리, 시작 전 청중 대기, LIVE에서 다른 자료로 이동한 뒤 서버 기준 자동 종료는 사용자의 지시에 따라 이번 구현에서 제외한다(브라우저 임시 종료는 9.4). 제출한 질문 삭제도 REST API 배포 이후로 미룬다. 기존 데이터나 인증 방식을 바꾸는 작업은 포함하지 않는다.

## 2. 사용자 결정 반영

| 항목 | 설계 기준 |

| 업로드 | 여러 파일을 선택하면 즉시 업로드·변환한다. 별도 업로드 시작 버튼을 요구하지 않는다. |
| 인사이트 | 사이드바 메뉴에서는 제거한다. 폴더 내부 인사이트 탭과 집계 범위 선택은 유지한다. |

| PIN 묶음 | 가까운 PIN을 묶는다. 선택해도 슬라이드는 읽을 수 있고, 나머지 PIN만 약하게 표시한다. |
| 언어 | 한국어·영어 전환을 유지한다. 새 문구도 두 언어로 제공한다. |
| 폴더 색상 | Blue·Sky·Navy·Slate 네 종류를 사용한다. 기존 색상 값도 새 팔레트에 대응시켜 보여 준다. |
| 종료 리포트 | 상세 AI 리포트와 별도다. 질문·공감·페이지별 분포와 AI 요약을 갖는 간단한 리포트다. |

## 3. 화면별 변경 설계

### 3.1 로그인·가입 안내

기준 프레임(2026-10-05 사용자 지정): 로그인 `182:32786`, 가입 `182:32818`.

- 밝은 Navy 배경, 상단 OhPin 로고, 중앙 흰 카드로 변경한다.
- 현재 Google OAuth와 로그인 이후 이동을 그대로 재사용한다. 가입 안내도 같은 Google 인증 흐름을 사용한다.
- 청중은 로그인 없이 QR 또는 공유 링크로 참여한다는 안내를 카드 안에 둔다.
- 한국어·영어 전환과 로그인 실패·진행 상태를 유지한다.
- 로그인 카드는 환영 제목·Google 로그인·문의 안내·수강생 QR 참여 안내·회원가입 전환으로 구성한다. 가입 카드는 무료 계정 안내·Google 가입·3단계 시작 가이드·수강생 안내·약관 문구·로그인 전환을 제공한다.
- 별도의 비밀번호 가입이나 랜딩 페이지는 추가하지 않는다. 약관·문의 링크는 실제 연결 주소가 있는 경우에만 제공한다. 사용자가 주소 없는 상태의 안내 문구 표시와 링크 연결 보류를 승인했다(2026-10-05).

후속 폴더 UI 기준(2026-10-02 사용자 지정): 그리드 카드 `161:4962`, 강의 폴더 리스트 `161:6090`을 우선한다. 카드는 256×212 기준, 상단 문서 레이어와 높이 132의 포켓, 제목·집계·시각 및 28px 메뉴를 사용한다. 리스트는 네이티브 표(폴더·자료·슬라이드·질문·업데이트), 65px 행, 36px 색상 아이콘, 하단 새 폴더 만들기 행으로 구성한다. 좁은 화면에서는 표 영역만 가로 스크롤한다. 최근순/이름순을 네이티브 선택으로 제공한다. 현재 `FolderSummary.updatedAt`은 폴더 생성 및 자료 추가 시각의 최댓값이므로 표시·정렬 기준을 도움말로 밝히고 실제 수정 시각으로 주장하지 않는다. 시각이 없으면 —을 표시한다. 미분류의 표시 색상은 Figma처럼 Slate로 한다. 저장 모델·기존 폴더 색상 인덱스·목적·미분류 정책 및 폴더 삭제 시 자료 보존을 유지한다.

- Figma의 ‘공감 허용’, ‘이모지 반응’, ‘질문 PIN 공개’가 기존 전역 정책과 일치하는지 확인한다. 현재 API에 없는 정책을 작동하는 스위치처럼 만들지 않는다.

- ‘준비 중·청중 입장 전’과 같은 문구는 제외한다. 이번 작업은 청중 대기 정책을 구현하지 않으므로 ‘자료 준비’라는 실제 화면 용도를 표시한다.

### 3.6 PIN과 질문 팝오버

- PIN의 원래 좌표와 질문 데이터는 유지하고 표시 단계에서만 묶는다.
- 묶는 기준(2026-10-03): 실제 캔버스 크기로 계산한 화면 거리에서, PIN이 가장 가까운 묶음의 중심(소속 PIN 평균 위치)으로부터 32px 이내면 그 묶음에 합류한다. 중심 기준이라 줄지어 있는 PIN이 하나로 번지지 않는다. 묶음은 그 중심에 표시한다.
- 강사 LIVE 플레이어와 발표 화면(슬라이드쇼)은 PIN 조작과 디자인이 같다(2026-10-03): PIN 클릭 시 상세 대화상자와 슬라이드 어둡게 덮기, 선택 원 없음, 아래의 묶음 표시·펼치기·AI 요약 팝오버, 같은 말풍선. 발표 화면에서는 상세 대화상자나 묶음 팝오버가 열려 있는 동안 PIN 공개·자동 넘김·키보드 슬라이드 이동을 멈추고, 새 질문 강조와 공감 불꽃 효과는 발표 화면에만 둔다. 강의 관리 페이지의 `핀만 / 핀 + 질문` 선택은 같은 브라우저의 발표 화면에 즉시 반영되고 다시 열어도 유지된다(브라우저 저장소 사용, 다른 기기의 발표 화면에는 반영되지 않는다). 기본값은 `핀만`이다.
- 강사 LIVE 플레이어의 묶음은 질문 개수가 있는 하나의 표시(`1243:1016`, 32px 원과 옅은 파란 후광)로 보여 주고, 그림자는 마우스를 올리거나 포커스할 때만 보인다. 선택하면 개별 PIN이 묶음 중심에서 각자의 실제 좌표로 이동해 번호와 함께 보이고(확대·재배치 없음, 2026-10-03), 개별 질문·공감 수·AI 요약이 있는 팝오버를 연다. 팝오버 목록에서 질문을 고르면 상세 대화상자를 열지 않고, 그 PIN이 애니메이션으로 커지며 맨 앞으로 나오고 목록 항목이 선택 상태가 된다. 상세 대화상자는 펼친 PIN을 직접 눌렀을 때 연다(2026-10-04).
- `핀 + 질문` 말풍선: PIN 하나는 본문만(`1243:1214`), 묶음은 대표 질문의 유형 칩·본문·`외 N개`(`1243:1216`)로 보여 준다. 강사 플레이어에서는 클릭한 PIN 둘레의 파란 선택 원을 표시하지 않는다. 발표 화면의 PIN·묶음 표시는 기존대로 둔다.
- 선택한 PIN / 묶음은 파란색으로 강조한다. 강사 LIVE 플레이어에서는 1260:946·1264:958 기준으로 슬라이드에 어두운 덮개를 씌우고 선택한 PIN·묶음·라벨만 덮개 위에 남긴다. 발표·참여 화면은 덮개 없이 다른 PIN의 투명도만 낮춘다.
- 팝오버가 슬라이드를 과도하게 가리지 않게 가장자리에서 위치를 보정한다. Escape·닫기 버튼으로 닫고, 키보드 포커스를 선택한 PIN으로 돌려준다.
- 강사 LIVE 플레이어의 묶음 팝오버는 3.5의 AI 요약 라우트를 사용한다. 요약을 받지 못하면 실패 안내만 보여 주고 생성한 것처럼 보이는 문구는 넣지 않는다. 발표·참여 화면의 묶음 목록은 기존대로 유지한다.

- 질문 작성은 슬라이드 위 위치 선택과 하단 작성 패널로 구성한다. 기존 질문 유형·최대 길이·위치 이동·빈 PIN 허용 규칙을 유지한다.
- 참여자 화면의 선택된 PIN은 바깥 장식 원 없이 PIN만 표시한다(2026-10-15 사용자 요청). 키보드 포커스 표시는 유지한다.
- 슬라이드에는 평소 PIN을 표시하지 않는다. 내 질문도 보낸 뒤 바로 숨긴다. 질문 카드(내 질문·다른 사람 질문 모두)를 누르면 그 슬라이드로 이동해 그 질문의 PIN과 본문 라벨만 보여 주고, 다시 누르면 숨긴다. 수정 창은 열지 않는다. 한 번에 PIN 하나만 보이므로 묶음 숫자는 표시하지 않는다. 아직 질문하지 않은 참여자에게는 슬라이드 위 탭 안내를 보여 준다.
- 질문 작성 시트(2026-10-03): 슬라이드는 어두운 덮개 위에 남아 핀을 끌어 옮길 수 있다. 시트는 제목·슬라이드 번호, 유형 칩, 300자 입력, “글 없이 보내도 ‘여기가 궁금해요’ 핀으로 전달돼요” 안내, 보내기 버튼으로 구성한다. 마커 선택과 핀 삭제 버튼은 두지 않고 닫기로 취소한다. 글 없이 보내면 본문은 `여기가 궁금해요`로 저장한다.
- 제출하면 시트를 닫고 `질문이 슬라이드에 꽂혔어요` 토스트를 띄운다. 발표자와 다른 페이지에 있으면 `발표자는 Np · 따라가기` 버튼, 같으면 `발표자 화면 따라가는 중` 상태를 보여 준다.
- 내 질문 카드에는 `내 질문` 표시와 `⋯` 메뉴를 둔다. 메뉴의 질문 수정은 기존 기능을 유지하고, 질문 삭제는 API가 생길 때까지 비활성과 이유를 표시한다.
- 본인 질문에는 공감할 수 없다(2026-10-15 사용자 요청). 강사로 로그인한 브라우저에서도 `/join`은 익명 참여자 세션으로 질문을 조회해 `is_mine`을 판별하고, 본인 질문의 공감 버튼을 비활성화하며 공감 요청도 보내지 않는다.
- 슬라이드 뒤 배경과 질문 카드의 톤을 Figma에 맞춘다. 강사 답변·해결에 의존하는 화면 동작은 제거한다.
- 이모지 반응·공감의 오류 처리와 중복 요청 방지를 유지한다. 하단 버튼은 모바일 안전 영역을 고려하고 마지막 질문을 가리지 않게 여백을 둔다.
- 반응하기는 아이콘 버튼 하나로 열고 닫는 이모지 4개 팝오버로 둔다. 질문 목록을 숨기면 `이 슬라이드 질문 N개가 숨겨져 있어요` 카드만 남긴다.
- 노트북·태블릿 가로(761px 이상 가로 화면, 2026-10-17 사용자 승인): 화면 높이에 맞춘 두 칸 구성을 유지한다. PIN을 찍으면 `1548:1541`의 360px 질문 팝업을 PIN 옆에 열고 화면 가장자리에서 위치를 보정한다. PIN 끌기·300자 제한·빈 질문 전송·저장 실패 후 재시도·Escape와 닫기 버튼을 유지한다.
- 태블릿 세로와 모바일(2026-10-17 사용자 승인): 슬라이드 아래에 질문 목록을 배치하고 PIN을 찍으면 화면 아래 전체 폭 바텀 시트를 연다. 방향을 바꿔도 질문 초안·PIN 좌표는 유지한다. 작은 화면·화상 키보드에서는 시트 내부를 스크롤해 전송 버튼에 접근할 수 있어야 한다.
- 질문 카드(2026-10-17 사용자 승인, `1550:289`): API의 `is_mine`에 따라 어두운 `내 질문` 배지를 표시한다. 클릭한 질문은 흰 배경과 파란 테두리로 강조한다. 다른 참여자의 소유권을 추측하거나 작성자 식별자를 노출하지 않는다.
- 아직 시작 전 대기 정책을 적용하지 않으므로 기존 청중 입장 동작을 유지한다.

### 3.8 간단한 종료 리포트

기준 프레임: `161:9282`, 개편 `Mw7TekAU6bxju63dFfJdQJ / 1271:2`(2026-10-03).

- 1271:2 반영: 상단 바(뒤로가기 버튼·`강의 리포트`·자료 제목·PDF로 내보내기), 범위 안내 줄, 단위가 붙은 지표 카드(받은 질문 N개·공감 N회·질문이 가장 많은 N페이지), 세로 막대 `페이지별 질문 수`(최다 페이지 강조, 0은 얇은 선, 총 페이지 수, 최다 페이지 안내 문장), 연한 파란 AI 요약 카드(번호 항목). 날짜·진행 시간·참여 인원은 데이터가 없어 표시하지 않고 범위 안내로 대신한다. 슬라이드 제목은 일반 이름뿐이라 안내 문장에 넣지 않는다. 페이지가 많으면 막대 영역만 가로로 스크롤한다.

- 상단 자료 제목·돌아가기·PDF 내보내기, 세 개의 지표 카드, 페이지별 질문 막대그래프, AI 요약 패널로 구성한다.
- 돌아가기 버튼은 해당 자료의 폴더(`/admin/folders/{folderId}`)로 이동한다. 미분류 자료는 `/admin/folders/unfiled`로 이동한다(2026-10-14 사용자 요청).
- 지표는 질문 수, 공감 수 합계, 질문이 가장 많은 페이지다. 빈 질문·동률·삭제된 슬라이드가 있는 경우의 표시 기준도 정한다.
- 상세 AI 리포트의 초안·수정·승인·확정 정책을 이 간단한 리포트에 적용하지 않는다.
- 1차에서는 이 레이아웃과 데이터 입력 계약을 만든다. 현재 자료 전체의 질문을 이번 회차의 질문으로 표시하지 않는다.
- 회차 범위·시작/종료 시각·참여 인원은 백엔드가 제공할 때 연결한다. 데이터가 없으면 해당 항목을 숨기거나 제공 전 상태로 표시한다.
- 2차 AI 연결 시에는 실제 모델 응답만 요약으로 표시한다. 로딩·실패·재시도·미설정 상태를 구분한다. 질문 텍스트를 모델 명령으로 취급하지 않고 근거 페이지를 유지한다.
- 저장형 종료 리포트(2026-10-18 사용자 결정, 구현 예정): owner가 강의를 종료하고 리포트를 생성하면 지표·페이지별 분포·AI 결과·생성 언어를 함께 저장한다. owner/editor/viewer는 저장본을 조회하며 editor/viewer는 생성·재시도·수정할 수 없다. 리포트 열기·새로고침·언어 변경으로 모델을 호출하지 않고, owner에게만 종료 후 생성·실패 재시도를 제공한다. 기존 `리포트를 열면 생성하고 저장하지 않는다`는 동작을 대체하며, 상세 계약·BE API·중복 방지·실패 처리는 [계정 구조 적용 지침 §4](account-structure-implementation.md#4-종료-리포트-owner-생성저장-editorviewer-조회)를 따른다.
- AI 입력·표현은 기존 기준을 유지한다. 서버가 자료 전체 누적 질문 중 공감순 상위 200개를 snapshot으로 고정하고 `핵심 요약 / 많이 헷갈린 페이지 / 공감이 많은 질문 / 다음 강의 개선점` 네 섹션을 생성한다. 분량은 질문 수에 맞추고(10개 미만 1~2개, 50개 미만 2~4개, 그 이상 최대 6개씩) 근거 페이지를 붙이며 강의 내용을 추측하지 않는다. 레이아웃과 AI 카드 내부 스크롤(모바일 최대 화면 60%, PDF에서는 전체 펼침)은 유지한다. 저장된 지표와 AI 결과를 함께 표시하고, 미생성·생성 중·완료·미설정·실패를 구분한다.
- PDF는 간단한 리포트 자체의 내보내기다. 별도 승인형 상세 AI 리포트의 PDF 기능과 혼합하지 않는다. 구현 방식은 현재 PDF 기능 재사용 여부를 먼저 확인한 뒤 정한다.

## 4. 새 디자인 시스템 코드

별도 UI 라이브러리나 Tailwind를 추가하지 않는다. 현재 plain CSS와 CSS Modules를 사용한다. 공유 토큰과 실제 여러 화면에서 반복되는 컴포넌트만 공통화한다.

### 4.1 색상

| 의미 | Figma 값 |
| --- | --- |
| 브랜드 / 기본 강조 | Blue 600 `#0F62FE` |
| 브랜드 배경 | Blue 50 `#EEF4FF` |
| 페이지 배경 | Navy 50 `#F4F6FA` |
| 카드 / 입력 배경 | White `#FFFFFF` |
| 본문 글자 | Navy 900 `#141F38` |
| 보조 글자 | Navy 500 `#53627F` |
| 경계선 | Navy 150 `#DDE2EC` |
| 무대 배경 | Navy 950 `#0B1226` |
| 폴더 Blue / 옅은 면 | `#0F62FE` / `#EEF4FF` |
| 폴더 Sky / 옅은 면 | `#5B92FF` / `#DCE8FF` |
| 폴더 Navy / 옅은 면 | `#141F38` / `#E9EDF4` |
| 폴더 Slate / 옅은 면 | `#7483A0` / `#F4F6FA` |

상태 색상은 Figma의 성공·주의·오류 토큰을 사용한다. 그라데이션은 로고·브랜드 그래픽에만 사용한다. 기존 색상 변수를 새 의미 토큰으로 연결해 아직 바꾸지 않은 화면에도 톤이 일관되게 적용되도록 한다. 기존 폴더의 저장 값은 보존하고 네 가지 표시 팔레트로 매핑한다. 신규 폴더는 네 색상만 선택한다.

### 4.2 크기·모양·컴포넌트

- 간격은 4 / 8 / 12 / 16 / 24 / 32px을 기본으로 쓴다. Figma의 해당 프레임 치수에 맞춰 예외를 둔다.
- 제목은 홈 28px, 일반 섹션 18~20px, 본문 14px, 보조 정보 12px을 기준으로 한다. 현재 한국어·영어 글꼴 경로를 재사용한다.
- 버튼은 기본 40px, 모바일 조작 영역은 최소 44px이다. 큰 질문 작성 버튼은 Figma처럼 더 높게 둔다.
- 입력·버튼·메뉴는 작은 라운드, 카드·모달은 더 큰 라운드를 쓴다. 공통 토큰은 해당 Figma 컴포넌트에서 추출한다.
- 기본 / 보조 / 위험 버튼, 아이콘 버튼, 입력·검색, 탭, 토글, 상태 배지, 질문 카드, 모달과 빈 상태를 공유한다. 기존 컴포넌트를 먼저 고친다.
- 로고와 Figma의 고유 그래픽은 원본 SVG를 사용한다. 실제 슬라이드는 업로드한 자료다. 디자인 예시 슬라이드와 예시 사용자 데이터를 제품 데이터로 넣지 않는다.
- 기능별 CSS는 해당 route·component에 둔다. 전역 CSS에는 디자인 토큰과 공통 primitive만 둔다.

## 5. 반응형·접근성

데스크톱 기준은 Figma의 1440px, 청중 모바일 기준은 375px이다. 사이드바는 데스크톱에서 약 248px, 폴더 그리드는 해당 폭에서 네 열, 자료 그리드는 세 열을 기준으로 한다. 실제 사용자 화면을 고려해 열 수를 줄인다.

좁은 화면에서는 자료 목록을 접고 무대와 질문을 세로로 배치한다. 버튼·탭을 숨겨 필수 동작이 사라지지 않게 한다. 모바일 가로 화면과 짧은 높이에서도 질문 작성 패널을 스크롤할 수 있어야 한다.

탭·스위치는 실제 의미와 상태를 읽을 수 있어야 한다. 모달 포커스 관리, Escape 닫기, 포커스 복귀, 로딩·오류 안내, 키보드 탐색을 보존한다. 폴더 색상과 LIVE 상태는 색만으로 구분하지 않는다. PIN은 터치·키보드로 선택할 수 있어야 한다.

## 6. 구현 단위와 검토 순서

| 단계 | 구현 내용 | 검토 기준 |
| --- | --- | --- |
| 1A | 토큰, 로고, 공유 버튼·입력·탭·토글, 로그인 | 색상·글꼴·크기와 인증 흐름 |
| 1B | 홈, 폴더 카드·목록, 폴더 생성, 폴더 상세, 업로드 모달 외형 | 데스크톱 Figma 비교, 목적·색상·검색·기존 CRUD 유지 |
| 1C | 자료 준비, LIVE·발표 화면, 질문 카드, 강사 답변·해결 UI 제거 | 노트·패널 조절·키보드·QR·PIN 선택 |
| 1D | 청중 모바일 화면, 질문 작성·수정·반응 UI, 리포트 레이아웃 | 모바일 크기·따라가기·입력·안전 영역·정확한 데이터 상태 |
| 2A | 파일 선택 즉시 다중 업로드·변환 | 개별 진행·실패, 한 파일 실패 후 나머지 처리, 성공 자료 보존 |
| 2B | PIN 거리 묶음, 선택 강조, 자동 발표 토글, 질문 범위·정렬 | 기존 자동 발표 타이밍·새 질문 이동·수동 조작·팝오버 일시정지 |
| 2C | 간단한 리포트 집계, AI 요약 연결, PDF | 실제 데이터 근거, 빈 상태·오류, 상세 AI 리포트와 독립 |

업로드는 기존 resumable Storage → sourcePath 변환 → 자료 생성 경로를 재사용한다. 파일을 선택하자마자 큐 처리를 시작한다. 개별 파일 진행 상태·성공·실패를 보여 주고 실패한 항목을 다시 시도할 수 있게 한다. 성공 자료를 모달 닫기로 삭제하지 않으며, 변환 도중 화면 이동으로 처리가 끊기지 않게 한다. 여러 자료를 올릴 때 매 파일마다 자료 화면으로 자동 이동하지 않는다.

## 7. 코드 변경 위치

- 공통 디자인: `app/globals.css`, `app/component`의 로고·워크스페이스 헤더·폴더 사이드바·슬라이드 캔버스와 새 토큰 파일.
- 로그인·홈: `app/(view)/login`, `app/(view)/admin/dashboard`.
- 폴더·자료 목록: `app/(view)/admin/folders/[id]`.
- 준비·LIVE·발표: `app/(view)/admin/session/[id]`, `present`.
- 청중: `app/(view)/join/[code]`.
- 업로드: `app/_controller/use-material-upload.ts`와 공통 업로드 모달. 기존 변환 service 재사용.
- PIN·리포트 집계: 필요한 작은 순수 함수만 `app/_model`에 둔다.

새 저장소 계층, 신규 상태 관리 라이브러리, 디자인 시스템 문서 사이트는 만들지 않는다. UI 작업에서 REST DTO·Auth·Storage·Realtime 경계를 바꾸지 않는다. 참가자에게 발표자 노트를 전달하지 않는 기존 보안 조건을 유지한다.

## 9. 백엔드 후속 계약

이번에 제외한 기능은 다음 데이터·정책이 준비된 뒤 별도 구현한다.

- 자료와 독립된 강의 회차 식별자, 해당 회차에 속한 질문·참여자·리포트 조회 범위.
- 자료 이탈 시각·복귀 시각과 서버 기준 만료. (2026-10-15 사용자 결정, 임시) 서버 계약 전까지 앱 안 이탈은 아래 9.4의 브라우저 타이머로 종료한다.
- 본인 미답변 질문만 삭제하는 endpoint와 서버의 권한·상태 검사.
- API에 없는 반응·PIN 공개 정책의 저장·조회와 participant 적용 범위.

### 9.1 LIVE 경과 시간 (2026-10-03 제안)

- (2026-10-13 구현) BE `ohpin_update_lecture_settings`가 status를 `live`로 바꿀 때마다 `started_at = now()`를 기록하고, 강사·청중 강의 응답과 Realtime 강의 행에 `started_at`이 이미 포함된다. 클라이언트는 `ClassSession.startedAt`으로 경과 시간을 계산하고, 강의 시작 직후에는 응답 전까지 클라이언트 시각을 임시로 쓴다. 아래 트리거·`endedAt` 제안은 남은 후속이다.

- DB: `lectures.started_at`, `ended_at` 칼럼은 이미 있으나 채워지지 않는다. 새 마이그레이션으로 `before update of status on lectures` 트리거를 추가해 `live`로 바뀔 때 `started_at = now()`, `ended_at = null`, `live`에서 `ended`로 바뀔 때 `ended_at = now()`를 서버 시각으로 기록한다. 다시 시작하면 경과 시간은 0부터 다시 센다(회차가 생기면 회차로 옮긴다).
- REST: `PATCH /instructor/lectures/{id}` 응답, `GET /instructor/courses` 강의 행, 청중 `.../state` 응답과 Realtime 강의 행에 `startedAt`, `endedAt`을 포함한다. 클라이언트는 `ClassSession.startedAt`으로 `LIVE mm:ss`를 계산한다.
- 이 값이 생기면 `started_at is null`이면 시작 전, 아니면 종료로 구분해 청중 대기 화면과 리포트 노출을 정확히 나눈다.

### 9.2 참여 인원 (2026-10-03 제안)

- (2026-10-15 사용자 요청) 참여자 창 닫기·새로고침·페이지 이탈 시 같은 방송 토픽에 퇴장 신호를 보내 강사 화면에서 즉시 제외한다. 종료 중에도 전달되도록 `fetch`의 `keepalive`를 사용한다. 퇴장 이후 늦게 도착한 심박은 무시하고, 뒤로 가기 캐시로 돌아오면 새 접속 id로 다시 센다. 비정상 종료·통신 단절은 기존 심박 만료로 보정하며 Presence는 사용하지 않는다.
- (2026-10-13 구현, 임시) BE 변경 없이 Realtime broadcast 심박으로 센다. 참여 화면은 LIVE이고 화면이 보이는 동안 탭마다 임의 id로 `lecture-audience:{lectureId}` 토픽에 1분마다 `here` 신호를 보내고, 이 토픽은 강사 작업 공간만 구독한다. 강사는 최근 2.5분 안에 신호를 보낸 id 수를 `N명 참여 중`으로 표시한다. Presence는 입장·퇴장마다 모든 참여자에게 변경을 보내 N² 메시지가 되므로 쓰지 않는다(로컬 Realtime 측정: 참여자 5명에서 참여자당 presence 메시지 2~5개). 탭 단위 근사치이며 위조 신호를 막지 않는다. 리포트용 정확한 인원은 아래 테이블 계약이 필요하다.

- DB: `lecture_participants(lecture_id uuid references lectures on delete cascade, participant_id uuid references auth.users on delete cascade, joined_at timestamptz default now(), last_seen_at timestamptz default now(), primary key (lecture_id, participant_id))`와 `(lecture_id, last_seen_at)` 인덱스. RLS: 익명 참여자는 자기 행만 insert/update, 강의 소유자만 select.
- REST: `PUT /participant/lectures/{id}/presence`(참여 화면이 30초마다 호출, `last_seen_at` 갱신, 204). `GET /instructor/lectures/{id}/participants` → `{ "active": n }`(최근 60초 안에 갱신한 참여자 수). 플레이어가 15~30초마다 조회한다.
- 시작 전 `N명 입장 대기 중`을 보여 주려면 청중 참여 화면이 시작 전 강의에서도 대기 화면을 유지해야 하므로 9.1이 선행되어야 한다.
- 대안: DB 없이 Supabase Realtime Presence로 실시간 접속 수만 셀 수 있다. 리포트에 참여 인원을 남기려면 위 테이블이 필요하다.

### 9.3 페이지 추가·복제 (2026-10-03 제안)

- 질문은 `slide_id`를 참조하므로 페이지를 끼워 넣어도 기존 질문 위치는 유지된다. 서버는 한 트랜잭션에서 뒤 페이지의 `page_index`를 1씩 밀고 새 행을 넣어야 한다(`unique (material_version_id, page_index)` 충돌을 피하도록 역순 갱신 또는 지연 제약 사용).
- 뒤에 새 페이지 추가 / `+` 칸: 이미 있는 `POST /api/instructor/versions/{id}/slides`(`AppendSlidesRequest { slides: [{ id, imagePath }] }`, 현재 프런트 미사용)에 `afterSlideId: uuid | null`을 추가해 끝이 아닌 위치에도 넣게 한다 → 바뀐 슬라이드 행 목록. 빈 페이지는 현재 “이미지 경로 또는 PDF 페이지 중 정확히 하나” 규칙을 어기므로, 서버가 흰 이미지를 `lecture-slides`에 올려 `image_path`로 쓰거나 `slides.kind`(`image`·`pdf_page`·`blank`) 칼럼과 검사 조건을 추가해야 한다. 텍스트 슬라이드 작성기는 복원하지 않는다.
- 페이지 복제: `POST /instructor/slides/{slideId}/duplicate` → 바로 뒤에 같은 `image_path`/`source_page_index`와 강사 노트를 복사한 새 슬라이드. 질문·반응은 복사하지 않는다. Storage 객체를 공유하면 삭제 시 참조 수를 확인해야 하므로 복사본 업로드를 권장한다.
- 두 endpoint 모두 소유자 검사, 응답에 바뀐 `page_index` 목록 포함, 청중 화면 갱신을 위한 Realtime 이벤트가 필요하다.

### 9.4 플레이어 이탈 자동 종료 (2026-10-15 사용자 결정, 임시)

- LIVE 강의의 플레이어(`/admin/session/{id}`)를 앱 안에서 떠나면(뒤로 가기·다른 화면·다른 자료) 그 탭이 60분 타이머를 시작하고, 끝나면 강의 종료 버튼과 같은 `status = ended`를 저장한다. 같은 탭에서 그 플레이어로 돌아오면 취소한다. 종료 요약 창과 리포트 이동은 없다.
- 플레이어는 열려 있는 동안 `player:{id}` 공유 Web Lock을, 발표 창은 기존 `presentation:{id}` Lock을 잡는다. 60분이 지났을 때 둘 중 하나라도 다른 탭에 열려 있으면 종료하지 않고, 모두 닫힌 뒤부터 다시 60분을 센다.
- 브라우저 타이머이므로 탭·브라우저를 닫거나 앱 밖으로 나가면 LIVE가 유지된다. 백그라운드 탭과 절전에서는 늦어질 수 있고, 종료 저장 실패는 재시도하지 않는다. 이 한계는 위의 서버 기준 만료 계약으로 대체한다.

이 설계는 사용자 구현 지시로 승인되었다. PRD·프런트엔드 아키텍처·DESIGN.md와 함께 적용하며, 구현 검증 결과는 별도로 기록한다.

## 2026-10-19 PIN 선택 표시 변경 (사용자 요청 승인)

- 강의 관리 플레이어와 발표 화면에서 개별 PIN을 누르면 중앙 상세 팝업 대신 해당 말풍선을 흰 배경과 진한 글자로 강조한다. 강의 관리와 슬라이드쇼 모두 배경을 어둡게 흐리고 선택한 PIN·말풍선은 그 위에 선명하게 표시한다. PIN만 보기에서도 선택한 PIN의 본문을 펼치고, PIN+질문은 다른 말풍선을 유지하며 선택한 것만 강조한다. 말풍선 순환 모드에도 같은 선택 표시를 적용한다.
- 선택 중 순환·실시간 도착 표시·자동 넘김을 멈추고 같은 PIN 재클릭·빈 슬라이드 클릭·Escape로 해제하면 이어간다. 직접 슬라이드를 바꾸면 선택을 해제한다. 전체 본문 표시·겹침 방지·공간 부족 시 축소를 유지한다. 이 절은 3.5·3.6의 개별 PIN 클릭 시 중앙 상세 대화상자를 여는 동작을 대체한다.
- 묶음을 누르면 기존 PIN 좌표로 펼치고 요약·질문 목록 팝오버를 유지한다. 펼친 개별 PIN을 누르면 이 팝오버에서 같은 질문을 강조하고, 긴 목록에서는 해당 항목이 보이도록 스크롤한다. 목록 항목 선택과 PIN 강조는 기존 동일 상태를 사용한다. 참여자의 본인 질문 수정과 데이터·권한 경계를 유지한다.

## 2026-10-19 PIN 아이콘 변경 (사용자 제공 SVG 승인)

- 사용자가 제공한 `assets/icons/pin.svg`를 공통 PIN 정적 파일 `public/assets/design/question-pin.svg`에 원본 그대로 적용한다. 강의 관리·슬라이드쇼·참여자 PIN과 작성 중 PIN, 묶음에서 펼친 개별 PIN에 같은 이미지를 사용한다. 기존 좌표·클릭/드래그 영역·묶음 개수와 번호·키보드 포커스·선택 강조·실시간 도착 모션을 유지한다. 원형 CSS 대체 그림을 제거하고 SVG의 비율·그라데이션·그림자를 보존한다.
- (추가 사용자 요청) 단일 PIN과 묶음 PIN은 같은 화면에서 같은 opacity를 사용한다. 관리 화면은 기존 묶음 기준 0.9, 선택한 PIN·묶음·펼친 PIN은 1로 표시하고 슬라이드쇼는 기존 묶음 기준 1을 유지한다. 단일 PIN에만 더해지던 0.3 감소와 이미지/컨테이너의 투명도 중첩을 제거하며 배경 흐림과 도착 fade-in은 유지한다.

### 2026-10-19 겹친 PIN 아이콘과 개수별 크기

- 사용자 요청에 따라 닫힌 PIN 묶음에도 제공된 `pin.svg`를 사용하고 겹친 개수를 표시한다. 기존 개수별 크기 계산(2개 32px, 개수마다 4px 증가, 최대 56px)을 재사용한다. 클릭 영역은 최소 44px로 유지한다.
- 강의 관리, 슬라이드쇼, 참여자 페이지의 공용 PIN 렌더러에 적용한다. 각 화면의 기존 질문 공개 범위와 선택·펼치기 동작을 유지한다.

- (2026-10-19 사용자 정정) 개수 표시는 Flutter의 Stack처럼 PIN 이미지 위 중앙에 숫자를 포개는 방식이다. 별도 원형 배지를 제거하고, 기존 개수별 PIN 크기·opacity·접근 가능한 개수 이름·선택/펼치기 동작은 유지한다.

### 2026-10-19 PIN 좌표 고정

- 사용자 요청에 따라 말풍선 겹침 조정은 말풍선에만 적용한다. 단일 PIN은 저장된 좌표에, 닫힌 묶음 PIN은 포함된 PIN들의 원래 좌표 평균에 고정한다.
- 묶음을 펼치면 각 PIN은 자신의 원래 좌표에 표시한다. 펼침·도착·선택 강조 애니메이션은 그 자리에서 재생하며, 확대 때문에 좌표 간격이나 중심이 바뀌지 않는다. 강의 관리·슬라이드쇼·참여자 공용 렌더러에 적용한다.

- (2026-10-19 화면 재현 보완) 닫힌 묶음 버튼에 상대 위치 규칙을 공유하지 않는다. 묶음 버튼과 펼친 묶음은 같은 슬라이드 절대 좌표계를 사용하고, 상대 위치는 참여자 묶음의 summary 내부 숫자 배치에만 사용한다. 기본 Turbopack 개발 서버에서도 접힘/펼침 중심을 비교해 검증한다.

### 2026-10-19 배포 PIN 이미지 캐시

- 제공된 PIN SVG의 내용은 유지한다. 운영 도메인의 SVG 응답은 최대 4시간 캐시되므로, 단일 PIN·묶음·펼친 PIN·참여자 초안 모두 같은 내용 해시 버전(`?v=732542ce`)을 포함한 이미지 주소를 사용한다. SVG 내용을 바꾸면 이 버전도 새 내용 해시로 함께 바꾼다.

## 2026-10-20 리모컨 표시 옵션 및 작은 QR 보완 (사용자 요청 승인)

리모컨의 질문 표시 ON/OFF 및 세 모드(핀만·핀+질문·슬라이드쇼 모드)와 QR 여섯 위치·S/M/L·슬라이드쇼 직접 조정을 `docs/lecture-roles-and-remote.md`의 2026-10-20 계약대로 구현한다. 이 범위의 발표 선호는 서버에 저장해 별도 기기에도 전달하며 기존 브라우저 선호는 이전 자료의 기본값으로 보존한다. QR 64px에서는 SVG와 참여 코드가 카드 너비를 넘지 않도록 크기에 맞춰 배치한다.

## 2026-10-21 강의 관리·슬라이드쇼 PIN 반응형 (사용자 요청 승인)

- 두 화면의 PIN 이미지는 실제 슬라이드 폭의 3.2%로 표시한다(슬라이드 폭 1000px에서 기존 32px). 묶음 PIN의 개수별 크기와 펼친 PIN도 같은 슬라이드 비율로 조절한다.
- 클릭 영역은 최소 44px을 유지한다. 기존 선택 확대 배율, opacity, 좌표·묶음 기준·펼침 동작과 말풍선 자동 배치를 유지하며, 참여자와 썸네일의 크기 정책은 바꾸지 않는다.

## 2026-10-22 참여자 코멘트 작성·PIN 앵커 (사용자 요청 승인)

- 참여자 작성 팝업과 진입 버튼은 `코멘트 남기기`를 사용하고, 입력 안내·전송·수정·접근성 문구도 중립적인 코멘트 표현으로 맞춘다. 질문 모델·API·빈 PIN 허용 규칙은 유지한다.
- 참여자 목록도 제목·개수·내 코멘트 배지·수정/삭제 메뉴·빈 상태·숨김 안내·정렬/범위 접근성 이름에 `코멘트`를 사용한다(2026-10-22 후속 사용자 요청 승인).
- 강의 관리 오른쪽 패널의 `실시간 질문`은 `실시간 코멘트`, 질문 표시 옵션의 `PIN+질문`은 `PIN+코멘트`, `말풍선`은 `버블`로 표시한다(2026-10-22 후속 사용자 요청 승인). 같은 모드의 공용 번역도 맞추고 표시 모드 값·저장·동작은 유지한다. 이 범위 밖 강사 화면의 질문 문구는 유지한다.
- 참여자 화면에서 작성 중이거나 선택해 표시한 PIN은 SVG 여백을 포함해 왼쪽 아래 꼭짓점이 선택한 슬라이드 좌표에 오도록 정렬한다. 좌표 저장·드래그·키보드 이동·44px 클릭 영역과 반응형 팝업 동작을 유지한다.
