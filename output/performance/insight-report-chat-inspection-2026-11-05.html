01 / DISPOSITION

종합 판정

공용 분석 재사용 효과 확인. 한 번 분석한 결과를 다시 쓰므로 반복 작업이 줄었습니다. 다만, 처음 시작할 때와 여러 요청이 겹칠 때는 개선이 필요합니다.

  • 개선 확인: 저장된 분석 결과를 쓰면 슬라이드를 다시 분석하지 않습니다. 그 결과를 가져오는 데 50~60ms가 걸렸습니다.
  • 잔여 지연: 기존 분석을 가져와도 리포트의 본문은 AI가 새로 씁니다. 이 작업에는 4.91~6.20초가 걸렸습니다.
  • 불일치 재현: 같은 자료를 처음 열어 달라는 요청 2건이 동시에 오면, 분석이 2회 시작되는 조건을 시험에서 확인했습니다. 먼저 시작한 작업이 등록된 뒤에는 뒤의 요청이 그 작업을 함께 기다렸습니다.
  • 챗 점검: ‘데이터 제외’를 골라도 서버는 원본 자료 전체를 먼저 읽습니다. 특정 슬라이드를 물으면 그 슬라이드를 이미지로 준비하는 시간도 필요합니다.
  • 전환 판정: Rust 전면 전환은 보류합니다. 먼저 같은 일을 두 번 하지 않게 하고, 필요한 자료만 읽으며, 어느 단계가 오래 걸리는지 나누어 측정하는 편이 낫습니다.

전문 용어를 읽는 방법 — 필요할 때 펼쳐 보기
  • 공용 분석·캐시: 한 번 만든 분석 결과를 보관했다가 다른 화면이나 리포트가 다시 쓰는 방식입니다. 같은 문제를 매번 새로 풀지 않고, 보관한 풀이를 꺼내 보는 것과 비슷합니다.
  • 서버·로그·API/HTTP: 서버는 요청을 받아 처리하는 컴퓨터나 프로그램입니다. 로그는 그 작업 기록입니다. API는 프로그램끼리 요청과 답변을 주고받는 창구이고, HTTP는 웹에서 이를 주고받는 방식입니다. 이 보고서에서 GET은 상태 읽기, POST는 작업의 시작·재사용 요청 등에 쓰입니다.
  • 분석 지문·해시: 입력이나 파일을 구분하는 표시입니다. 비교 대상과 같은지 확인할 때 씁니다.
  • 사전 처리·비동기 처리: 사전 처리는 본작업 전의 사용자 확인·자료 읽기입니다. 비동기 처리는 접수 응답 뒤에도 뒤에서 계속하는 작업입니다.
  • 병렬 처리·큐: 병렬 처리는 여러 작업을 함께 진행하는 방식입니다. 큐는 순서대로 일하기 위한 대기줄입니다.
  • 렌더링·파싱: 렌더링은 자료를 화면이나 이미지로 그리는 일입니다. 파싱은 받은 데이터를 프로그램이 읽을 수 있게 해석하는 일입니다.
  • DB·프로세스·RSS: DB는 데이터를 저장하는 곳입니다. 프로세스는 실행 중인 프로그램입니다. RSS는 그 프로그램이 실제 메모리에 올려 둔 데이터의 양입니다.
  • 폴링·스트리밍·TTFT: 폴링은 정해진 간격으로 상태를 다시 묻는 방식입니다. 스트리밍은 만들어진 답변부터 조금씩 보여 주는 방식입니다. TTFT는 첫 답변이 보일 때까지의 시간입니다.
  • 격리 재현·시정 권고·재점검: 격리 재현은 실제 서비스와 분리된 시험에서 같은 현상을 확인하는 일입니다. 시정 권고는 어떻게 고칠지에 대한 제안이고, 재점검은 고친 뒤 다시 확인할 조건입니다.
  • 시간·메모리 단위: ms는 1초를 1,000개로 나눈 단위이고, s는 초입니다. MiB·GiB는 메모리 크기를 나타내는 단위입니다.
02 / CONFIGURATION

구성 변경 확인

점검 항목이전 분석 전제현재 코드성능 판정
분석 소유 단위리포트를 만들 때마다 슬라이드를 다시 분석material_analyses에 자료별 결과를 저장합니다. 지문, 즉 분석에 쓴 입력을 구분하는 표시가 같으면 결과를 다시 씁니다.같은 자료로 리포트를 다시 만들 때 이미지 준비와 AI 분석을 줄일 수 있습니다.
공통 분석슬라이드를 분석한 다음 결과를 합침질문을 주제별로 묶는 일과, 이미지를 준비해 슬라이드를 분석하는 일을 함께 진행합니다.둘 다 끝나야 하므로, 더 오래 걸리는 쪽이 전체 시간을 결정합니다.
슬라이드 호출슬라이드를 20장씩 묶고, 최대 6개 묶음을 동시에 처리5장 단위·자료당 최대 24개 동시AI에 보내는 묶음을 작게 나누어 함께 처리합니다. 단, 24개는 서버 전체의 최대 개수가 아닙니다.
영어 번역분석 시간과 번역 시간을 충분히 나누어 보지 못함공통 분석 결과를 ready, 즉 ‘준비 완료’로 저장한 뒤 영어 번역을 따로 진행합니다.영어 번역이 끝나기 전에도 한글 결과를 쓰고 리포트 본문을 작성할 수 있습니다.
리포트 본문분석 결과와 질문 묶음을 함께 정리저장된 공용 분석을 바탕으로, 리포트마다 본문만 새로 씁니다.분석 결과를 다시 써도 본문을 만들기 위한 AI 호출 1회는 남습니다.
AI 챗이전 점검에서는 챗 시간을 따로 측정하지 않음문서를 고치지 않고 질문에 답하는 Q&A입니다. 겹치는 문서·질문은 줄이고, AI에 보내는 내용의 양도 제한합니다. 답변은 스트리밍으로, 만들어지는 글부터 보여 줍니다.AI가 읽어야 할 내용의 양은 줄였습니다. 질문을 보낸 뒤 첫 토큰, 즉 답변의 첫 글자가 나올 때까지의 시간은 아직 측정하지 않았습니다.
분석 이미지분석에 쓸 페이지 이미지를 따로 만듦플레이어와 내보내기가 쓰는 1920px 페이지 JPEG 캐시를 함께 씁니다. 캐시는 다시 쓰려고 보관한 결과입니다. 이후 AI가 읽을 크기로 줄이고 글자를 추출합니다.보관한 이미지가 있으면 다시 그리는 일이 줄어듭니다. 다만 이미지 크기를 줄이고 글자를 읽어 내는 작업은 여전히 필요합니다.

근거: E01~E08. 분석 지문은 ‘지난번과 같은 입력인가’를 확인하는 표시입니다. 자료 버전, 슬라이드 순서, 질문/답변, 폴더 목적, AI 공급자/모델, 프롬프트 버전으로 만듭니다. 공감 수와 답변 상태는 넣지 않습니다.

처리 경로 점검

최초 공용 분석 — 처음 한 번 결과를 만드는 순서

① 사전 확인
  • 강사인지, 자료의 주인인지 확인
  • courses·folders 전체 목록 읽기
  • 분석 지문을 비교해 새 작업이 필요한지 판단
② 병렬 작업 — 두 일을 함께 진행
질문 묶기

슬라이드 분석

두 작업이 모두 끝나면 ready(준비 완료)로 저장합니다. 각 결과는 먼저 끝난 것부터 화면에 보여 줍니다.

③ 후속 분기 — 필요한 일을 따로 진행
  • 리포트: 본문 AI → 문서 저장
  • 대시보드: 영어 번역 → 별도 저장

완료 지배 경로는 ‘전체 시간을 결정하는 작업 순서’입니다. 먼저 사전 처리를 합니다. 그다음 함께 진행한 질문 묶기와 슬라이드 분석 중 더 늦게 끝난 쪽을 기다립니다. 리포트는 여기에 본문 작성과 마지막 저장 시간이 더해집니다.

기능현재 경로잔여 대기 요인
대시보드화면이 가진 강의 정보 확인 → 분석 POST(시작·재사용 요청) → 3초마다 GET(상태 확인)처음에는 전체 자료 읽기, 공용 분석, 영어 번역이 필요합니다. 질문이 없는 대시보드는 분석을 시작하지 않습니다.
리포트 재사용사용자 확인 → 원본 전체 읽기·분석 지문 비교 → 저장 결과 가져오기 → AI가 본문 작성결과를 다시 쓰기 전에도 원본을 읽습니다. 본문은 매번 AI가 새로 씁니다.
챗 — 문서만사용자·리포트 확인 → 원본 전체 읽기 → 이번 질문을 DB에 기록 → 문서 내용을 AI에 전달 → 답변을 조금씩 표시‘데이터 제외’를 골라도 원본 읽기가 먼저 일어납니다.

구성

재점검
번역에 30초 넘게 걸리는 경우, 번역 실패, 숨겨진 탭, 화면을 다시 여는 경우를 시험합니다. 이때 공통 분석까지 새로 시작하지 않는지 확인합니다.

유지 확인 — 원래 목적대로 움직이는 부분

  • 리포트를 취소해도 공통 분석은 다른 화면·리포트가 쓰도록 계속 진행해 저장합니다. 따라서 작업이 남아 있다는 이유만으로 메모리 누수라고 판단하지 않습니다.
  • 영어 번역은 공통 결과가 나온 뒤 하는 후처리입니다. 번역이 끝날 때까지 한글 결과 사용이나 리포트 본문 작성을 막지 않습니다.
  • AI가 읽는 문맥, 즉 참고 내용에서 중복을 줄였습니다. 문서가 60,000자를 넘으면 선택한 섹션 위주로 보내고, 대화 이력은 약 20,000자로 제한합니다.
  • Claude 챗에는 프롬프트 캐시를 1시간 쓰는 설정이 있습니다. 프롬프트는 AI에 보내는 지시와 참고 내용입니다. 실제로 얼마나 재사용됐는지는 챗 로그가 없어 확인하지 못했습니다.
  • material_analyses 마이그레이션(저장소 구조를 바꾸는 작업 파일)에서 접근 권한을 확인했습니다. RLS와 일반 역할의 접근 차단을 설정하고 서버 역할만 쓰게 했습니다. RLS는 데이터 행마다 접근을 제한하는 장치입니다. 실제 서비스에 적용됐는지는 이번 점검에서 확인하지 않았습니다.

5 · 동시 부하·메모리같은 자료와 서로 다른 자료를 대상으로 1·2·4작업을 비교합니다. Node와 보조 변환 프로그램의 RSS, 진행 중인 AI 호출 수, 대기줄 길이, 타임아웃(시간 제한 초과)을 기록합니다.자료 크기와 시험 환경을 함께 적고, 완료 시간·오류율·최대 RSS를 판단

  • 저장된 분석을 가져오는 데는 이미 수십 ms만 걸립니다. 지금 남은 큰 대기 중 하나는 외부 AI가 본문을 쓰는 시간입니다.
