## 1. 범위

- `DSH-001` 대시보드 하나는 강의(자료) 하나를 다룬다. 경로는 `/admin/insights/[id]`(`id` = 강의 id, `ClassSession.id`). 진입은 분석 목록(§7)이다. 리포트 작성은 대시보드 머리의 `AI 리포트 만들기`로 간다(2026-11-01).
- `DSH-002` 포함: 머리(경로·자료 전환·날짜·진행 시간), 개요(전광판), 슬라이드별 PIN 질문 흐름, 슬라이드별 핀 분석, 질문 분석(질문 유형·유형별 분석).
- `DSH-003` 제외: 이모지 반응 그래프, LIVE 회차 비교, 질문 감정 분류, 폴더 안 강의 비교, 미답변·답변·해결 수(2026-10-29). 익명 질문 비율은 모든 질문이 `is_anonymous = true`로 저장돼 항상 100%라 넣지 않는다(2026-11-01). 슬라이드별 핀 참여 인원은 넣지 않는다. 참여자 단위 지표(참여율, 질문한 참여자, 공감·핀 참여자, 1인당 평균 질문)와 머리의 `참여 n명`, 요약 배너는 강사에게 필요하지 않다는 피드백으로 뺐다(2026-11-04). 분당 PIN·참여자 선 그래프, 슬라이드 노출 시간 표, 슬라이드별 시계열, 키워드 워드 클라우드도 Figma 개편으로 뺐다(2026-11-01).
- `DSH-004` 시간 데이터(머리의 진행 시간, 리포트 수치)는 마지막 LIVE 회차 기준이다. 같은 강의를 다시 LIVE로 열면 기록을 새로 쓴다(`started_at`과 같은 규칙).

## 2. 강의 타임라인 기록 (FE만 변경, BE 변경 없음)

- `DSH-010` 강사 플레이어가 LIVE 동안 1분마다 `{at, audience, slide}`(현재 접속 탭 수, 화면 슬라이드 1-based)를 쌓는다. 슬라이드가 바뀔 때마다 `{at, slide}`를 쌓는다. 값은 기존 heartbeat 집계와 플레이어가 보는 `currentSlide`에서 얻으며 새 broadcast를 추가하지 않는다. 2026-11-01부터 대시보드는 표본·전환을 그리지 않고 종료 시각과 참여자 수만 쓴다. 기록은 리포트 수치와 이후 분석을 위해 유지한다.
- `DSH-011` 플레이어는 5분마다, 그리고 강의 종료 저장 직후에 지금까지의 기록 전체를 `POST /api/admin/lectures/:id/audience`로 보낸다(덮어쓰기). 실패해도 수업을 막지 않는다. 탭을 닫으면 마지막 전송 이후 최대 5분이 빠진다.
- `DSH-012` 서버는 강의 소유권을 강사 JWT로 `GET /api/instructor/lectures/{id}/state`에 물어 확인한다(내 강의가 아니면 그 응답에 `id`가 없다). 전체 강의 그래프를 읽지 않는다. 표본 1,440개(24시간), 슬라이드 전환 5,000개를 넘거나 값이 범위를 벗어나면 400.
- `DSH-013` 한계: 값은 탭 기준 근사치이고 출석이 아니다.

## 3. 데이터와 API

- `DSH-020` `lecture_audience_records`에 `samples jsonb`, `slide_changes jsonb`(기본 `[]`)를 더한다. `instructor_reports`에 초안 분석 결과 `analysis jsonb`를 더한다(리포트용). 대시보드의 질문 유형과 슬라이드 내용 분석은 2026-11-04부터 리포트와 함께 쓰는 공통 분석 `material_analyses`(자료당 한 행, [리포트 명세 §4.1](instructor-report-authoring.md#41-공통-분석-2026-11-04-사용자-결정-대시보드와-리포트가-나눠-쓴다))를 읽는다. 예전 `lecture_question_groups`(강의당 한 행, 글자만 묶은 결과)는 더 읽지 않는다.
- `DSH-021` `GET /api/admin/lectures/:id/insights` → `{ record: { startedAt, endedAt, audience, peakAudience } | null }`. 호출자 `owner_id`로 거른다. 리포트 분석은 읽지 않는다(2026-11-04). REST 그래프를 읽지 않는다.
- `DSH-022` 질문·슬라이드·`startedAt`은 화면이 이미 가진 세션 스토어 데이터를 쓴다. 강의 종료 시각은 `record.endedAt`을 쓰고, 없으면 마지막 질문 시각까지를 강의 구간으로 본다.
- `DSH-023` (2026-11-04 삭제) 참여 집계 route `GET /api/admin/lectures/:id/participation`와 `participationCounts`를 지웠다. 대시보드는 BE 소유 테이블을 서버 권한으로 직접 읽지 않는다.

## 4. 계산 (순수 함수, `app/_model/insight-dashboard.ts`)

- `DSH-030` (2026-11-04, 시간대별 질문 흐름을 대체) 슬라이드별 PIN 질문 흐름: 가로축은 슬라이드 순서(`P.1`…`P.n`), 값은 그 슬라이드의 PIN(위치 있는 질문) 수다. 강의 중 같은 슬라이드로 돌아올 수 있어 시간 구간은 슬라이드를 대신하지 못한다는 피드백으로 바꿨다. 같은 값을 막대 또는 꺾은선으로 그리고, 그래프 위 `막대`·`꺾은선` 전환(`aria-pressed`, 기본 막대, 저장하지 않음)으로 고른다. 가장 많은 슬라이드는 진한 브랜드 블루다. 슬라이드가 많으면 칸 폭 40px 아래로 줄이지 않고 가로로 스크롤한다. 슬라이드가 없으면 그래프 대신 이유를 쓴다.
- `DSH-031` (2026-11-04) 개요는 야구 전광판처럼 숫자 칸 네 개 한 줄이다. 도넛·설명 문장·요약 줄은 없다. 칸마다 이름, 큰 값, 작은 보조 값이다. 접기는 DSH-045를 따른다.
  - 질문: 전체 질문 `n건`, 보조 `공감 n`.
  - 최다 슬라이드: 질문이 가장 많은 슬라이드 `P.n`, 보조 `n건`. 질문이 없으면 `없음`.
  - 핀 찍힌 슬라이드: `n / 전체`, 보조 `핀 n개`.
  - 최다 주제: 가장 큰 질문 유형(DSH-034)의 제목, 보조 `n건`. 질문 유형이 아직 없으면 이름을 `최다 공감 질문`으로 바꿔 그 질문(40자에서 자름)과 `공감 n`을 보이고, 질문이 없으면 `없음`.
- `DSH-032` 요약 문장은 AI를 부르지 않고 위 수치로 만든다. 라벨은 `요약`이다. 개요에는 요약 문장이 없다. 평가하는 말("높은 편")은 쓰지 않는다. PIN 질문 흐름: PIN 질문이 가장 많은 첫 슬라이드(없으면 "아직 슬라이드에 찍힌 PIN 질문이 없어요"). 슬라이드: 질문이 많은 상위 두 슬라이드의 비중. 질문 분석: 가장 큰 질문 유형, 없으면 공감이 가장 많은 질문.
- `DSH-033` (2026-11-04) 슬라이드 내용 분석은 공통 분석(RPT-121)의 슬라이드별 `questionSummary`다. 그 분석은 슬라이드 이미지·추출 글자·PIN 위치를 함께 본다(예전에는 질문 글만 본 대시보드 전용 요약이었다). 질문이 있는 슬라이드만 보인다. 라벨은 `AI 요약`이다. 분석 중·실패·AI 설정 없음은 DSH-034와 같은 문구(“내용 분석”)로, 그 슬라이드에 분석이 없으면 "이 슬라이드의 내용 분석이 없습니다"를 보인다. 강의가 아직 끝나지 않았으면 "강의가 끝나면 분석해요"를 보인다.
- `DSH-034` 질문 유형은 질문의 주제 묶음이다. 질문 유형(`category`)은 전체 숨김 계약 때문에 항상 한 값이라 쓰지 않는다. 묶음마다 현재 존재하는 질문 수와 전체 질문 대비 비율을 막대로 보이고, 남은 질문이 없는 묶음은 뺀다.
  - 출처 (2026-11-04 공통 분석): 대시보드가 열릴 때 `POST /api/admin/materials/:materialId/analysis`(RPT-125)를 한 번 부르고, 결과가 다 올 때까지 3초마다 `GET`으로 상태를 읽는다. 분석이 끝나고 영어(DSH-044)가 아직 없으면 번역 제한 시간 90초에 맞춰 최대 30번 더 읽는다(2026-11-06: 10번·30초에서 늘림). 묶음은 공통 분석의 질문 묶기 결과(RPT-121)라 리포트의 질문 유형과 같다. 질문 묶기는 글자만이라 슬라이드 분석보다 먼저 끝나므로 질문 유형이 먼저 보이고 내용 분석은 뒤에 채워진다.
  - 화면: 묶는 동안 "질문을 주제별로 묶는 중이에요…", AI 설정이 없으면 "AI 설정이 없어 질문 유형을 만들 수 없습니다", 실패하면 "질문 유형을 만들지 못했습니다. 잠시 후 다시 열어 주세요", 질문이 없으면 "질문이 없어 질문 유형이 없습니다"를 보인다.
  - 재사용 (2026-11-06 사용자 확인): 첫 진입에서 분석한 내용 분석·질문 분석 결과를 DB에 저장한다. 두 번째 이후 진입은 입력 지문이 같고 완료된 저장본이 있으면 AI를 호출하지 않는다. 질문·슬라이드 등 분석 입력이 바뀌면 재분석한다. 브라우저를 닫거나 새로고침해도 저장본을 재사용하며, 동시에 열면 진행 중인 같은 실행에 합류한다.
  - 비용: 공통 분석의 지문(RPT-124)이 바뀐 뒤 처음 열 때 공통 분석 1회(슬라이드 5장마다 이미지 호출 1번 + 묶기 1번)와 영어 번역 1회. 같은 자료로 리포트를 만들면 공통 분석은 다시 하지 않는다.
- `DSH-035` (2026-11-04) 질문 분석은 전체 질문 목록 대신 질문 유형별 분석을 보인다(슬라이드별 핀 분석이 위치 기준이라면 이 구역은 주제 기준이다). 유형 막대는 버튼(`aria-pressed`)이고, 처음에는 가장 큰 유형이 골라져 있다. 고른 유형마다 AI 요약(DSH-034 묶음의 `summary`, 추가 AI 호출 없음), 나온 슬라이드(`P.n (건수)`, 슬라이드 순), 그 유형의 질문 전체(공감순, 목록 안에서 스크롤; 2026-11-04 사용자 요청으로 대표 질문 3개를 대체)를 보인다. 질문 검색·슬라이드 필터·정렬·페이지는 없다(2026-11-04 사용자가 검색도 뺐다).

## 5. 화면 (Figma `ClassPin` 2235:2458)

- `DSH-040` 폴더 트리 사이드바 안에 둔다. 위에서부터: 머리(뒤로 가기 → 분석 목록, 경로 `분석 › 폴더 › 자료`, 제목과 같은 폴더 자료 전환 네이티브 select, `날짜 · 진행 n분`, `AI 리포트 만들기`) → 개요(전광판, DSH-031) → 슬라이드별 핀 분석(2026-11-04: 수치는 아래 PIN 질문 흐름이 보이므로 이 구역에는 요약 문장·썸네일 숫자·핀/질문/공감 수가 없다. 왼쪽: 슬라이드 위 PIN 위치, 이전·다음, 썸네일 줄 `P.n`; 오른쪽: 내용 분석(DSH-033), 그 슬라이드의 PIN 목록(공감순). PIN이 없으면 "이 슬라이드에는 찍힌 PIN이 없습니다". 카드 폭이 888px보다 좁으면 위아래로 쌓는다) → 슬라이드별 PIN 질문 흐름(DSH-030) → 질문 분석(DSH-035). 2026-11-06 사용자 결정: 슬라이드별 PIN 분석을 슬라이드별 PIN 질문 흐름보다 위에 배치한다.
- `DSH-041` `AI 리포트 만들기`는 리포트 메인(`/admin/reports?material=<자료 id>`, RPT-011·012)으로 가서 이 자료를 미리 고른다. 템플릿과 요청은 거기서 고른다.
- `DSH-042` (2026-11-06) 대시보드는 내보내기를 제공하지 않는다. 전체·구역별 버튼, 미리보기 팝업, 문서 생성 코드와 전용 `POST /api/admin/insights/export` 라우트를 삭제한다. `AI 리포트 만들기` 이동(DSH-041)과 별도 리포트 내보내기는 유지한다.

- `DSH-045` (2026-11-04) 모든 구역(개요·슬라이드별 PIN 질문 흐름·슬라이드별 핀 분석·질문 분석)은 제목 버튼(`aria-expanded`, `aria-controls`)으로 접고 편다. 처음에는 모두 펼쳐져 있고 접은 상태는 저장하지 않는다.
- `DSH-046` (2026-11-04 사용자 결정) 질문 유형·슬라이드 내용 분석의 AI 호출(DSH-033/034)은 오래 걸린다(예전 글자만 묶기: 질문 100개 기준 약 45초; 공통 분석의 슬라이드 분석은 렌더를 포함해 1~2분). 기다리는 동안 슬라이드별 핀 분석의 내용 분석 자리와 질문 분석의 질문 유형·유형 분석 자리에 "아직 분석 중이에요. 조금만 기다려 주세요."(`role=status`)와 반짝이는 스켈레톤(질문 유형은 막대 모양)을 보이고, 질문 분석의 요약 줄은 결과가 올 때까지 숨긴다. 움직임 줄이기 설정이면 반짝임을 멈춘다.
- `DSH-044` (2026-11-04) 대시보드 문구는 한국어·영어(`app/_model/i18n.ts`의 `insight.*`)이고 언어 선택을 따른다. AI가 만든 질문 유형 이름·요약과 슬라이드 내용 분석의 영어는 대시보드 전용 번역(RPT-122 `dashboard.en`)이다. 공통 분석이 끝난 뒤 한 번 만들어 저장하고, 화면은 언어에 맞는 쪽을 보인다(언어를 바꿔도 AI를 다시 부르지 않고 묶음도 같다). 번역이 오기 전에는 영어 화면도 한국어를 보인다. 질문 본문과 폴더·자료 이름은 원문 그대로다.
- `DSH-043` 기록이 없는 항목은 비워 두지 않고 이유를 쓴다. 모든 컨트롤에 accessible name과 focus-visible을 둔다. 슬라이드 선택과 페이지 이동은 키보드로 할 수 있어야 한다.

## 7. 분석 목록 (Figma `ClassPin` 2222:10840)

- `DSH-050` 경로는 `/admin/insights`. 폴더 트리 사이드바 안에 두고, 사이드바의 `홈으로` 아래에 `분석` 항목을 둔다. 새 API 없이 세션 스토어의 자료·폴더와 브라우저의 열람 기록만 쓴다.
- `DSH-051` 머리: `분석` 제목과 `자료 · 폴더 검색` 입력. 검색어가 자료 제목이나 폴더 이름에 들어 있는 자료만 두 구역 모두에 남긴다.
- `DSH-052` **최근 분석**: 최근에 대시보드(`/admin/insights/[id]`)를 연 자료다(2026-11-01 사용자 결정, 리포트 유무와 무관). 열 때마다 강의 id와 시각을 계정별 브라우저 저장소(`useBrowserPreferences`, `recent-analyses`)에 남기고 최신 20개만 둔다. 목록은 최근에 연 순서로 최대 4개 카드(첫 슬라이드 썸네일, 제목, `폴더 · 질문 n · 날짜`, `분석 보기` 버튼)를 보이고, 연 자료가 없으면 구역 전체를 숨긴다. 기록은 브라우저마다 따로이고 브라우저 저장소를 지우면 사라진다. 기기를 바꿔도 같은 목록이 필요하면 서버 저장으로 옮긴다.
- `DSH-053` **자료별 분석**: 모든 자료를 카드 격자로(썸네일, 제목, `질문 n건 · 날짜`). 카드 전체가 대시보드 링크이며 accessible name은 자료 제목이다. 폴더 선택(전체·폴더별·미분류, 자료 수 표시, 네이티브 select)으로 거른다. 순서는 최근 강의순(`startedAt`, 없으면 `createdAt`) 하나뿐이다.
- `DSH-054` 목록에는 리포트 버튼이 없다. 리포트는 대시보드에서 연다(DSH-041).
- `DSH-055` 자료가 없으면 "폴더에 자료를 올리면 분석을 볼 수 있어요"를, 검색·폴더 결과가 없으면 "조건에 맞는 자료가 없습니다"를 보인다.
