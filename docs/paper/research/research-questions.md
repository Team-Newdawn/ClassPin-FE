# 연구 질문과 기여

- 상태: 확정(2026-10-23), 실험 결과에 따라 문구 조정 가능
- 근거: `../literature/literature-map.md`, `../experiments/2026-10-pilot-claude/README.md`

## 문제

강의 중 학생이 슬라이드의 특정 지점에 질문(PIN)을 남긴다. 강사용 분석은 VLM이 각 PIN이 슬라이드의 어떤 요소(표 칸, 막대, 문구, 아이콘)를 가리키는지 알아야 가능하다. PIN은 한 장에 수십~수백 개가 몰릴 수 있고, 질문 문장만으로는 대상을 알 수 없는 경우가 많다("이건 무슨 뜻인가요?").

## 연구 질문

### RQ1(중심): 좌표를 어떤 기준과 표기로 줘야 하는가

PIN이 밀집한 슬라이드에서 좌표 표기(정확한 픽셀, 정수 %, 소수 %, 0~1000 정규화, x·y 순서), 좌표계 정합(모델이 보는 이미지와 좌표 기준이 같은지), 입력 형태(직접 렌더한 이미지 vs 제공자 네이티브 PDF), 번호 표시 오버레이, 한 호출에 넣는 슬라이드 수(2026-10-24 추가)가 PIN→요소 대응의 정확도·실행 간 안정성·비용을 어떻게 바꾸는가? 그 효과가 모델(Claude·GPT·Gemini)마다 다른가?

### RQ2(부속): 직접 렌더링 + 텍스트 레이어가 PDF 입력을 대체하는가

직접 렌더한 페이지 이미지에 추출 텍스트(깨진 레이어 필터 포함)를 붙이면 제공자 네이티브 PDF와 같은 글자 판독 정확도를 내는가? RQ1의 "좌표계를 아는 입력"을 정당화하는 조건으로 다룬다.

### RQ3: 대화에서 슬라이드를 언제 보여줄 것인가

분석 텍스트만, 항상 첨부, 규칙 기반 선첨부 + 도구 요청(현재 방식)이 근거 있는 정답률과 토큰을 어떻게 바꾸는가? 모델이 근거가 필요한데 도구를 쓰지 않는 비율은 얼마인가?

## 기여(목표)

1. "좌표 → 대상" 방향의 밀집 PIN 대응 과제와 공개 가능한 합성 벤치마크(요소 영역 정답 자동 생성).
2. 좌표 정밀도, 좌표계 정합, 입력 형태를 분리한 통제 실험과 다중 모델 비교.
3. 실제 서비스 파이프라인(20쪽 청크, 10만 토큰 상한, 부분 실패 허용)의 비용·지연 보고.
4. (RQ3) 도구 미사용 현상을 규칙 기반 선첨부로 보완하는 대화 설계의 평가.

## 범위

- 포함: 슬라이드형 문서(16:9 중심), 한국어·영어 텍스트, 표·차트·문구·아이콘 요소, 상용 API 모델.
- 제외: 학습·미세조정, 동영상 강의, 실제 학생 데이터(RQ1~2는 합성 데이터로 한다), PIN 군집 의미 분석(후속 RQ4).

## FINER 평가

| 기준 | 평가 | 근거 |
|---|---|---|
| Feasible | 높음 | 합성 데이터라 정답이 자동으로 생기고, 전체 비용 추정 $45~80 |
| Interesting | 높음 | "PDF가 더 낫다"는 통념과 제공자별 좌표 관례 차이를 정면으로 다룬다 |
| Novel | 중간 | 설명→좌표(GUI grounding)는 많고, 좌표→대상·밀집 조건은 이번 검색 범위에서 드물다 |
| Ethical | 높음(RQ1~2) | 합성 데이터. RQ3에서 실제 리포트를 쓰면 익명화·동의 필요 |
| Relevant | 높음 | 서비스 설계 결정(이미지+픽셀 PIN)의 근거 |
