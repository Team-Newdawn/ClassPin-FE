기존 `/admin/insights` 분석 화면을 없애고, 같은 분석 결과를 **편집 가능한 리포트 초안**으로 바꾸는 작성 페이지를 만든다. 인사이트 대시보드는 별도 문서로 다룬다.

## 1. 결정 (2026-10-26)

- `RPT-001` 리포트 하나는 자료(파일) 하나를 다룬다. 한 자료에 리포트를 여러 개 만들 수 있다(예: 요청을 바꿔 가며). 2026-11-02 사용자가 자료당 하나 규칙을 풀었다(마이그레이션 `20261102090000`). 리포트는 모두 그 자료의 전체 질문을 근거로 하며, 회차별 질문 범위는 BE 회차 데이터가 생긴 뒤에 다룬다.
- `RPT-002` 확정 단계가 없다. 초안 생성이 끝난 뒤에는 언제든 내보낼 수 있다(편집은 RPT-008로 없앴다). 기존 AIR-PROD-012/013/078(확정 전 다운로드 금지, 직접 편집 금지)을 대체한다.
- `RPT-003` (2026-11-04 삭제, RPT-008) 편집기는 섹션 목록과 리포트 서식(RPT-024)을 지원한다. 굵게·기울임·밑줄·링크와 글자 크기는 강사가 직접 넣고, 표는 AI만 넣는다(2026-10-30 사용자 요청).
- `RPT-004` AI 채팅은 리포트당 사용자 질문 5회로 제한한다. 요금제가 생기면 그때 바꾼다. 초안 생성, 문서 적용, 되돌리기는 횟수에 포함하지 않는다. "새 대화"는 대화 내용만 지우고 횟수는 그대로 둔다(기존 규칙 유지). 누르면 브라우저 기본 확인창 대신 리포트 삭제와 같은 확인 다이얼로그(`ReportConfirmDialog`, 포커스는 취소, Esc·바깥 클릭으로 닫힘)를 연다(2026-11-04).
- `RPT-005` 초안은 기존 AI 분석(`analyzeInsight`)을 1회 실행해 만든다. 분석 화면만 없애고 분석 파이프라인은 초안 생성기로 재사용한다.
- `RPT-006` AI 편집에 넘기는 근거는 슬라이드 단위로 자른다. 요청과 관련된 슬라이드의 원본 이미지, 추출 텍스트, 그 슬라이드의 질문·답변·공감·PIN 좌표를 함께 보낸다(기존 `view_slides` 방식). PIN 주변 crop은 확장 방안이다.
- `RPT-007` 총 참여자 수는 플레이어가 세던 접속 탭 수를 강의 종료 시 FE 소유 테이블에 저장해 얻는다(§8). BE 변경은 없다.
- `RPT-008` (2026-11-04 사용자 결정) **리포트는 읽기 전용이다.** 캔버스의 편집 기능(제목·섹션 제목·본문 편집, 서식 도구, 섹션 추가·삭제·되돌리기, 자동 저장과 409 충돌 처리, `PATCH`)과 AI 변경안(`propose_document`, 문서에 적용, AI 변경 되돌리기·다시 적용, "방금 AI가 수정함")을 모두 없앴다. AI 채팅은 리포트와 강의 데이터에 대한 질의응답만 한다(RPT-050). 파일 첨부(RPT-057)와 `슬라이드·질문 데이터 포함`·`문서만 사용` 선택(RPT-058), 질문 5회 제한(RPT-004), 새 대화는 그대로다. `previous_document` 칼럼은 기존 데이터라 지우지 않고 더 이상 읽거나 쓰지 않는다. 섹션 아래의 목차·내보내기·초안 진행 표시는 그대로다.

## 2. 화면과 진입

- `RPT-010` 라우트는 `/admin/reports`(메인: 만들기와 내 리포트 목록, 2026-11-01)와 `/admin/reports/[id]`(작성) 두 개다. 둘 다 admin guard 안에 두고, 사이드바의 `홈으로 › 분석` 아래에 `리포트` 항목을 둔다. 2026-10-27 사용자 지적으로 옛 앱 셸 사이드바와 고아 라우트 `/admin/materials`를 삭제했다.
- `RPT-011` 리포트 메인(Figma `ClassPin` 2227:2258): ① 어떤 자료로 만들까요?(폴더 → 자료 네이티브 select, 강의가 끝나지 않은 자료는 고를 수 없다) ② 원하는 리포트를 설명해 주세요(선택, 여러 줄 입력 500자, RPT-036; 항상 들어가는 구역을 안내 문구로 알린다) → `AI로 리포트 만들기`. 템플릿 고르기는 2026-11-04에 없앴다. 아래 **내 리포트 n**은 `GET /api/admin/reports` 카드 격자다(문서 아이콘, 제목, 폴더, 작성 중·초안 실패 표시, 상대 시각 `방금 수정됨`·`n분 전`·`n시간 전`·`어제`·날짜, 최근 수정순). 같은 자료로 다시 만들면 새 리포트가 하나 더 생긴다(RPT-001). 카드 오른쪽 위 휴지통 버튼(accessible name `<제목> 리포트 삭제`)은 확인 다이얼로그(폴더 삭제와 같은 모양, Esc·바깥 클릭·취소로 닫힘, 실패는 다이얼로그 안에 표시) 후 `DELETE /api/admin/reports/[id]`로 리포트를 지우고 목록에서 뺀다(되돌릴 수 없음, 2026-11-02 사용자 요청).
- `RPT-012` 진입점: ① 사이드바 `리포트` ② 분석 대시보드의 `AI 리포트 만들기`(강의 종료 리포트의 `리포트 작성`은 2026-11-04 종료 리포트 개편으로 삭제, 대신 `분석 페이지로 이동`). ②는 `/admin/reports?material=<자료 id>`로 가서 그 자료(와 폴더)를 미리 고른다(2026-11-01). 자료의 강의가 끝나지 않았으면 만들 수 없다(기존 `LECTURE_NOT_ENDED` 유지).
- `RPT-013` 작성 화면은 왼쪽 문서 편집, 오른쪽 AI 채팅의 2분할이다. 경계는 라이브 플레이어 질문 패널과 같은 방식으로 크기를 조절하고, 키보드로도 조절할 수 있다. 좁은 화면에서는 위아래로 쌓는다. 2026-11-02 Figma `ClassPin` 2224:2222로 바꿨다: 왼쪽 폴더 사이드바(다른 관리 화면과 같은 컴포넌트, 이 화면에서는 아이콘만 보이게 접힌 채 시작), 가운데 문서 캔버스 박스, 오른쪽 AI 채팅 박스(420px)의 3단이며 두 박스는 1px border·radius 16이고 페이지 배경 위에 16px 간격으로 놓인다. 채팅 크기 조절은 없앴고, 채팅 머리의 닫기 버튼과 캔버스 머리의 `AI 리포트 도우미 열기` 버튼으로 열고 닫는다. 닫으면 캔버스가 그 폭까지 넓어진다. 1024px 이상은 열린 채, 그 아래는 닫힌 채 시작한다. 버튼을 누르면 포커스는 반대쪽 버튼(닫기 → 열기 버튼, 열기 → 채팅 입력창)으로 간다. 뒤로 링크는 사이드바 `리포트`로 대신한다.
- `RPT-014` 머리줄은 리포트 제목, 저장 상태(`저장됨`/`저장 중`/`저장 실패`), `내보내기 ▾`(PDF·DOCX·PPTX·MD)를 둔다. 머리줄의 `되돌리기`와 인사이트 대시보드 링크는 2026-10-31 사용자 요청으로 뺐다. 되돌리기는 변경안 카드(RPT-106)에만 남는다.

## 3. 문서 모델

```ts
type ReportDocument = {
  title: string;
  /** 초안 생성 시점의 코드 집계. 편집 대상이 아니며 내보내기의 수치 표·카드가 이것을 쓴다. */
  metrics: { at: string; slides: number; questions: number; pins: number;
    reactions: number; durationMinutes: number | null; audience: number | null; peakAudience: number | null };
  /** text는 리포트 서식(RPT-024) 문자열이다. */
  sections: { id: string; title: string; text: string; /** 1-based 슬라이드 번호. 있으면 내보내기에 그 슬라이드 이미지를 붙인다. */ slide?: number }[];
};
```

- `RPT-020` 섹션은 제목 한 줄과 리포트 서식 본문이다. 본문의 줄바꿈과 `- ` 목록 줄은 내보내기에서 그대로 유지한다.
- `RPT-021` (2026-11-04 삭제, RPT-008) 섹션 추가와 삭제를 제공한다. 삭제는 섹션 제목 오른쪽 휴지통 버튼(마우스를 올리거나 키보드 포커스가 들어오면 보임, 터치 화면은 항상 보임, 이름 `섹션 n 삭제`)이며 확인 없이 지우고, 문서 끝에 `‘제목’ 섹션을 지웠어요 · 되돌리기`를 보인다. 되돌리기는 같은 자리로 되살리며, 다음 삭제나 페이지 이동까지 유지된다(화면 안 기억, 서버 되돌리기 RPT-043과 별개). 삭제한 뒤 포커스는 그 자리를 이은 섹션(없으면 앞 섹션)으로 간다(2026-11-02 사용자 요청으로 삭제를 되살림). 위아래 이동·슬라이드 연결은 계속 AI 변경안으로 한다.
- `RPT-022` 제한: 섹션 300개, 섹션 본문 2만 자, 문서 전체 50만 자. 서버가 다시 검증한다.
- `RPT-024` 리포트 서식은 본문 문자열 안의 작은 마크다운 부분집합이다. 저장 형식이 문자열 그대로라 저장·409·변경안·되돌리기·제한(RPT-022, 기호 포함 글자 수)은 바뀌지 않는다.
  - `**굵게**`, `<i>기울임</i>`, `<u>밑줄</u>`, `<big>크게</big>`, `<small>작게</small>`, `[글자](https://주소)`: 한 문장 안에서도 쓸 수 있는 인라인 서식. 크기는 보통을 포함해 3단계다. 서로 겹쳐 쓸 수 있다(굵고 큰 글자). 바깥부터 크기 → 링크 → 기울임 → 밑줄 → 굵게 순서로 쓴다. 링크 주소는 공백·따옴표·꺾쇠·괄호 없는 `http://`·`https://` 주소만 링크가 되고, 그 밖(`javascript:` 등)은 글자 그대로 보인다(2026-11-02 사용자 요청으로 기울임·밑줄·링크 추가).
  - 표: GFM 파이프 표(`| 항목 | 값 |` 머리 줄, `|---|---|` 구분 줄, 본문 줄). 첫 줄은 머리 행이다. 칸 안에는 인라인 서식만 쓴다. 최대 8열 50행.
  - 이 밖의 기호(`#`, 이미지, 다른 HTML 태그)는 글자 그대로 보인다. 화면은 파싱한 결과를 이스케이프해서 그리며 저장된 HTML을 그대로 넣지 않는다.
  - 파서는 순수 함수 하나(`parseReportText`)이고 편집기·네 내보내기·Node 테스트가 함께 쓴다. 서버 검증(RPT-022)은 문자열 길이만 본다. 잘못된 표는 글자 그대로 보일 뿐 저장을 막지 않는다.
- `RPT-023` 수치 중 `audience`·`peakAudience`는 §8 기록이 없으면 null이고, 화면과 내보내기에 `기록 없음`으로 표시한다. 참여율은 분모 데이터가 없어 넣지 않는다. 답변 기능이 숨김 상태라 미답변·답변됨·해결됨·답변 수도 넣지 않는다(2026-10-29 사용자 요청).

## 4. 초안 생성

- `RPT-030` 리포트를 만들면 행을 `drafting` 상태로 저장하고, 기존 생성 route처럼 Next `after()`에서 공통 분석 확보 → 본문 작성 → 초안 변환을 실행한다(RPT-126; 2026-11-04 전에는 리포트마다 슬라이드 렌더 → `analyzeInsight`). 일일 생성 한도, 실행 중 취소, 15분 정체 판정은 기존 값을 그대로 쓴다.
- `RPT-031` (2026-11-04 사용자 결정) 리포트 형식은 하나이고 우리가 정한다: 자세하게, 인사이트 대시보드의 내용을 모두 담는다. 초안은 순수 함수 하나(`draftReport`)로 만들고 Node 테스트를 둔다. 섹션 순서:
  1. **개요**(코드): 강의명, 일시(LIVE 시작), 진행 시간, 대상·목적(폴더 이름 · 사용 목적, 미분류면 `미분류`)과 대시보드 전광판 표(DSH-031: 질문·공감, 최다 슬라이드, 핀 찍힌 슬라이드/전체·핀 수, 최다 주제). 값이 없으면 `기록 없음`·`없음`.
  2. **AI가 쓴 본문 섹션**(RPT-035, 강사 요청이 있으면 그 요청을 따른다, RPT-036).
  3. **슬라이드별 PIN 질문 흐름**(코드, DSH-030): 꺾은선 그래프만(RPT-037). 설명 문장과 표는 없다(2026-11-04).
  - **질문 유형**(코드, 묶음이 있을 때): 가로 막대 그래프만(RPT-037). 설명 문장과 표는 없다(2026-11-04).
  4. **질문 유형: {이름}**(코드, DSH-035): `groups`마다(질문 수 많은 순) 요약, 질문 수와 비율, 나온 슬라이드 `P.n (건수)`, 대표 질문 공감순 5개.
  5. **슬라이드 n · 주제**(코드, `slide` 연결): 모든 슬라이드. 질문 요약 또는 내용 정리, 쟁점, 제안, 그 슬라이드의 질문 전부(공감순, 답변 포함, 답변 상태는 넣지 않는다 RPT-023). 섹션 길이 한도(RPT-022)를 넘으면 잘린다.
  - 수치만으로 시작(RPT-033)은 1·3과 질문이 있는 슬라이드의 5(질문 원문만)다.
- `RPT-037` (2026-11-04 사용자 결정) **그래프.** 섹션은 `chart: { kind: "line" | "bar", points: { label, value }[] }`를 가질 수 있다(코드만 만든다; 서버는 종류, 600개 이하, 라벨 200자, 0 이상 유한수를 검사한다). 슬라이드가 수백 장이어도 한 폭에 들어가도록 PIN 흐름은 꺾은선(점은 40장 이하일 때만, 가장 많은 슬라이드만 강조, 축 라벨 약 10개), 질문 유형은 가로 막대(가장 큰 유형만 진한 파랑)다. 그래프 한 장을 SVG 한 번으로 그려(`app/_model/report-chart.ts`, 라벨 이스케이프) 편집기는 그대로 보이고, PDF·DOCX·PPTX는 2배 해상도 JPEG로 슬라이드 이미지 자리에 넣는다. MD에는 그래프가 없어 두 섹션은 제목만 남는다. PPTX에서 본문이 없는 그래프 섹션은 그래프를 슬라이드 전체 폭에 넣는다. 숫자는 그래프에만 있어 편집기에서 고칠 수 없고, AI 채팅도 그래프를 바꾸지 않는다.
- `RPT-032` 분석 중에는 편집기를 읽기 전용으로 두고 진행 상태와 취소 버튼을 보여준다. 페이지를 떠났다가 돌아와도 상태를 이어서 보여준다. 진행 상태는 실제 단계(슬라이드 준비 → 슬라이드 분석 n/전체 장 → 본문 작성)를 따른다. 슬라이드 분석이 끝나면 개요와 슬라이드별 섹션을 읽기 전용 미리보기로 먼저 보이고, 본문 자리는 스켈레톤으로 둔다(2026-11-02 사용자 요청). 미리보기는 서버 메모리에만 두고 `GET /api/admin/reports/[id]`의 `progress`로만 내려주며 저장하지 않으므로, 문서가 생기기 전에는 아무것도 저장되지 않는다. 서버 로그 `[report-draft]`는 단계별 소요 시간만(내용 없이) 남긴다.
- `RPT-033` 분석이 실패하거나 취소되면 `다시 시도`와 `수치만으로 시작`을 제공한다. 수치만으로 시작하면 1번 섹션과 질문 원문만 담은 슬라이드별 섹션으로 초안을 만든다.
- `RPT-034` (2026-11-02 사용자 요청으로 삭제) 문서가 있는 리포트의 `초안 다시 만들기`와 그 횟수 제한(리포트당 2회, `REDRAFT_LIMIT`)을 없앴다. 문서를 새로 쓰려면 AI 채팅의 변경안을 쓰거나 같은 자료로 리포트를 새로 만든다(RPT-001). `instructor_reports.redrafts` 칼럼(마이그레이션 `20261029090000`)은 기존 데이터라 지우지 않고 더 이상 읽거나 쓰지 않는다. 예전에 다시 만들기가 실패해 `failed` 상태로 남은 리포트도 문서가 있으면 그대로 편집할 수 있다.
- `RPT-035` **자료에 맞춘 리포트 양식(2026-10-31 사용자 결정).** 리포트 양식은 고정 틀이 아니라 AI가 자료에 맞게 정한다.
- `RPT-036` **강사 요청(2026-11-04 사용자 결정, 템플릿을 대체).** 강사가 메인에서 쓴 요청(선택, 500자)을 `instructor_reports.request`(마이그레이션 `20261101100000_instructor_report_request.sql`, 운영 적용 전 수정)에 저장하고 초안(실패한 첫 초안의 `다시 시도` 포함)에 쓴다. 요청은 AI가 쓰는 본문 섹션(RPT-031의 2)의 개수(1~7개)·구성·제목·내용·분량·문체를 가장 먼저 정한다. 코드가 만드는 구역(1·3·4·5)은 요청과 상관없이 항상 들어가며, 필요 없으면 강사가 편집기에서 지운다. 요청은 강사가 쓴 글이라 `redactInsightText`를 거쳐 따옴표 안에 넣고, 숫자 통계를 쓰지 않는 규칙과 자료·질문 안의 지시문을 따르지 않는 규칙은 요청보다 앞선다. 제목은 자료 제목이다. 예전 템플릿(보고용·수업 개선용·한 장 요약·빈 문서)과 `template` 칼럼은 없앴고, 이미 만든 리포트의 문서는 그대로 둔다. 리포트를 만든 뒤 고치는 것은 AI 채팅(RPT-05x)이 맡는다.
  - 자료 종류는 AI가 스스로 판단한다(슬라이드 분석의 `category`). 판단 근거로 자료가 속한 폴더의 이름과 사용 목적(기타면 목적 이름)을 프롬프트에 넣는다. 2026-11-04부터 이 판단은 공통 분석(RPT-121)에서 한 번 하고, 강사 요청은 본문 단계에만 넣는다. 미분류 자료는 자료만 보고 판단한다. 폴더 이름은 강사 입력이므로 데이터로만 취급한다.
  - 합치기 단계에서 AI가 본문 섹션 3~7개(강사 요청이 있으면 요청에 맞는 1~7개, RPT-036)(`sections: {title, text}[]`)의 구성·제목·내용을 정한다. 예: 대학 강의면 흐름·혼란 지점·개선 제안, 창업 캠프 발표면 사업 항목 점검·심사 관점 질문·다음 발표 보완점. 본문은 리포트 서식(RPT-024)으로 쓰고, 항목 비교가 표로 더 읽기 쉬우면 표를 넣을 수 있다(AI만 표를 넣는 규칙 그대로). 숫자 통계, 발표 성공·투자 가치 같은 단정은 쓰지 않는다.
  - 코드는 RPT-022 길이 제한과 최대 7개만 지킨다. AI 섹션이 하나도 없으면 개요 뒤에 바로 근거 섹션이 온다.
  - 근거 섹션(주제별 묶음, 슬라이드별 분석)은 질문 원문 인용과 슬라이드 연결이 필요해 코드가 그대로 만든다. 묶음과 슬라이드별 분석은 공통 분석(RPT-121)의 것이라 대시보드와 같다.
  - 기존 `overall`(요약·주목할 슬라이드·개선 제안)은 `sections`로 대체한다. 저장된 옛 `analysis`는 그대로 둔다. 기존 리포트는 옛 양식 그대로 두고, 새 양식이 필요하면 리포트를 새로 만든다.
## 4.1 공통 분석 (2026-11-04 사용자 결정, 대시보드와 리포트가 나눠 쓴다)

- `RPT-120` **결정.** 자료마다 슬라이드와 PIN 질문을 한 번 분석해 저장하고, 분석 대시보드와 리포트가 같은 결과를 쓴다. 대시보드에서만 필요한 것(영어)과 리포트에서만 필요한 것(본문 섹션)은 공통 결과를 입력으로 따로 만든다. 실행은 그 기능을 처음 쓸 때(대시보드를 열 때, 리포트를 만들 때)이고 강의 종료 때 미리 돌리지 않는다(아무도 열지 않는 강의 비용, 종료 경로가 여럿인 문제). 처음 열 때의 대기가 문제가 되면 플레이어의 종료 성공 뒤 RPT-125의 POST를 한 번 부르는 것으로 더한다. 분석은 강의가 끝난 자료만 한다(진행 중에는 질문이 계속 바뀐다).
- `RPT-121` **공통 결과.** 슬라이드 분석 호출(5장씩, 동시 최대 24개)과 질문 묶기 호출(글자만)을 동시에 보낸다.
  - 묶음 크기(2026-11-05 사용자 결정): 20장 → 5장. 정답을 아는 빽빽한 표 20장·PIN 60개 합성 자료, 조합마다 6회: PIN 대상 정답률 평균 20장 98.6%(직접 렌더)·81.9%(캐시 이미지, 답을 통째로 빼먹은 호출 1회), 10장 83.3%, 5장 95.3%. 답을 낸 호출만 보면 모두 약 98%이고, 빼먹은 호출은 묶음 크기와 무관하게 생겼다(5장이면 빈 슬라이드도 5장뿐). 대기 84~91초 → 42초(실제 15장 자료 50~60초 → 약 36초), 비용 약 30% 증가(20장 1회 1.7센트 → 2.2센트). 동시 상한 24는 묶음당 base64 이미지 약 5MB 기준으로 이전(20장 × 6)과 같은 메모리다.
  - 슬라이드 이미지(2026-11-05): 플레이어·내보내기가 쓰는 1920px 페이지 이미지 디스크 캐시(`/api/pdf/page`와 같은 파일)를 AI 크기로 줄여 쓰고, 글자는 같은 PDF에서 `pdftotext` 한 번으로 뽑는다(`analysisSlideImages`). 캐시에 없는 장만 한 장씩 렌더해 캐시에 남긴다. 15장 측정: pdftoppm 전체 렌더 16.1초 → 0.4초. 이미지 슬라이드는 기존대로 원본을 줄인다.
  - 슬라이드 분석 입력: 지시문을 앞에 두고 슬라이드마다 라벨·이미지·`<slide_text>`·그 슬라이드의 질문(PIN은 이미지 기준 픽셀, SB-2), 폴더 이름과 사용 목적. **강사 요청은 넣지 않는다**(리포트마다 달라 나눠 쓸 수 없다). 출력: `category`, 슬라이드마다 `{ slideId, page, topic, content(질문 없는 슬라이드), questionSummary, suggestion, issues: { title, summary, questionIds }[] }`.
  - 질문 묶기 입력: `[슬라이드 n] 질문`(앞 500개, `redactInsightText`). 출력: `groups: { title, summary, questionIds }[]` 3~7개, 빠진 질문은 `기타 질문`. 한국어만 쓴다.
- `RPT-122` **전용 결과.**
  - 대시보드 전용 `dashboard.en`: 묶음 제목·요약과 슬라이드 `questionSummary`의 영어(DSH-044). 공통 결과가 모두 나온 뒤 글자만 호출 1번. 영어가 오기 전에는 영어 화면도 한국어를 보인다. (2026-11-04 로컬 측정, 15장·질문 100개: 질문 묶기 약 42초, 슬라이드 분석 약 84초, 번역 약 13초; 같은 자료의 리포트는 본문 호출만 약 24초.)
  - 리포트 전용: 본문 섹션(RPT-035·036)을 리포트마다 만든다. 입력은 공통 결과(자료 종류, 슬라이드별 `topic`·`questionSummary`, 묶음 제목·요약·건수), 질문 목록, 폴더 목적, 강사 요청. 리포트 행의 `analysis`에는 지금처럼 공통 결과와 `sections`를 합친 사본을 저장해 문서와 맞춘다.
- `RPT-123` **저장.** FE 마이그레이션으로 `material_analyses`(자료당 한 행, `material_id` → `materials` cascade, `owner_id`, `fingerprint`, `status running|ready|failed`, `error`(안정된 코드만), `slides`(`{ category, failedPages, slides }`), `groups`, `dashboard`(`{ en }`), `provider`, `model`, `started_at`, `updated_at`)를 만든다. RLS를 켜고 `anon`/`authenticated` 권한을 회수한다(service_role 전용). 단계가 끝날 때마다 그 칼럼을 저장해 먼저 끝난 결과부터 보인다. `started_at`이 같은 실행만 쓰므로 오래된 실행이 새 결과를 덮지 않는다.
- `RPT-124` **다시 쓰는 조건.** `fingerprint`는 자료 버전 id, 슬라이드 id 순서, 질문(id·슬라이드·본문·위치·답변), 폴더 이름·목적 줄, 공급자·모델, 프롬프트 버전 상수의 sha256이다. 공감 수와 답변 상태는 프롬프트에 없어 넣지 않는다. 같으면 저장본을 쓰고, 다르면 전체를 다시 분석해 덮어쓴다. 바뀐 슬라이드만 다시 분석하는 것은 하지 않는다(끝난 강의는 질문이 거의 바뀌지 않는다; 필요해지면 슬라이드별 지문으로 더한다).
- `RPT-125` **API.** `POST /api/admin/materials/[id]/analysis`: 강사 JWT로 소유권과 REST 자료를 읽고 지문을 비교한다. 같고 `ready`면 결과를, 같고 `running`(15분 이내)이면 상태를 돌려준다. 그 밖에는 `running`으로 저장하고 Next `after()`에서 실행한 뒤 곧바로 현재 상태를 돌려준다. `GET` 같은 경로는 DB 행만 읽는다(화면이 3초마다 부른다). 같은 자료의 동시 요청은 서버 한 대 안에서 한 실행을 나눠 쓴다. 자료마다 행 읽기·저장을 한 번에 하나씩 하므로, 거의 같은 순간에 온 첫 요청 둘도 한 실행에 합류한다(2026-11-06: 전에는 약 80ms 안에 온 두 요청이 각각 실행했다). 원본 검사가 막은 이유(`ORPHAN_QUESTION`, `SOURCE_LIMIT` 등)는 응답은 `INVALID_SOURCE`(422) 하나로 두고 서버 로그에 남긴다. 하루 리포트 한도(RPT-030)에 세지 않는다. 끝나지 않은 강의는 `LECTURE_NOT_ENDED`(409), AI 설정이 없으면 `ANALYSIS_NOT_CONFIGURED`(503).
- `RPT-126` **리포트 초안.** RPT-030의 `슬라이드 렌더 → analyzeInsight`를 `공통 분석 확보(없거나 지문이 다르면 실행, 실행 중이면 그 실행을 기다림) → 본문 작성 → draftReport`로 바꾼다. 진행 상태(RPT-032)는 공통 분석이 도는 동안 그 실행의 슬라이드 분석 n/전체를 보이고, 공통 분석이 이미 있으면 바로 본문 작성 단계다. 공통 분석이 실패하면 리포트도 실패한다(RPT-033 그대로).
- `RPT-127` **지우는 것.** 대시보드 전용 묶기(`groupQuestions`의 슬라이드 요약·영어)와 `POST /api/admin/lectures/[id]/question-groups`, 리포트 합치기 단계의 묶음 만들기. `lecture_question_groups`는 더 읽지 않고, 테이블 삭제는 이 변경이 운영에 배포된 뒤 별도 마이그레이션으로 한다. 이미 만든 리포트와 그 `analysis`는 그대로 둔다.
- `RPT-128` **검증.** 지문(같은 입력은 같은 값, 공감 수만 바뀌면 같은 값, 질문 본문이 바뀌면 다른 값)과 실행 판단(ready·running·오래된 running·지문 변경)을 Node 테스트로 둔다. 로컬에서 대시보드를 먼저 연 뒤 리포트를 만들면 슬라이드 분석 호출 없이 본문 호출만 나가는지 `insight_ai_usage` 로그로 확인한다.

## 5. 편집과 저장

- `RPT-040` (2026-11-04 삭제, RPT-008) 입력이 멈추고 1초 뒤 자동 저장한다. 저장 요청에는 마지막으로 받은 `updatedAt`을 함께 보내고, 서버의 값과 다르면 409를 돌려준다.
- `RPT-041` (2026-11-04 삭제, RPT-008) 409를 받으면 덮어쓰지 않는다. `다른 곳에서 수정됨`을 알리고 `내 내용으로 저장` 또는 `최신 내용 불러오기`를 고르게 한다.
- `RPT-042` (2026-11-04 삭제, RPT-008) 저장이 실패하면 편집 내용을 메모리에 유지하고 재시도한다. 저장하지 못한 변경이 있으면 페이지를 떠나기 전에 브라우저 경고를 띄운다.
- `RPT-043` (2026-11-04 삭제, RPT-008) `되돌리기`는 1단계다. 문서를 통째로 바꾸는 동작(AI 변경안 적용) 직전의 문서를 서버의 `previous_document`에 저장하고, 되돌리면 현재 문서와 맞바꾼다. 일반 타이핑은 브라우저 기본 undo에 맡긴다.

## 6. AI 채팅과 AI 편집

- `RPT-050` (2026-11-04, RPT-008) AI 채팅은 질의응답만 한다: 도구는 `view_slides`(데이터 포함일 때)뿐이고, 문서를 고쳐 달라는 요청에는 고칠 수 없다고 알린 뒤 그 내용을 답으로 정리한다. 기존 채팅 흐름을 그대로 옮긴다: provider 어댑터(`InsightAi.chat`), 텍스트 스트리밍, 질문 선점 후 실패 시 환불, 중지, 리포트당 동시 답변 1개, 90초 제한.
- `RPT-051` 고정 컨텍스트는 분석 결과 대신 **현재 문서**(섹션 번호·제목·본문)와 원본 데이터(슬라이드 번호·제목, 슬라이드별 질문 본문·상태·공감·답변)다. 문서가 6만 자를 넘으면 섹션 제목만 넣고, 사용자가 말한 섹션과 슬라이드의 본문만 붙인다. 그 본문은 1시간 캐시에 두는 고정 컨텍스트가 아니라 그 질문 메시지에 붙인다(2026-11-06: 전에는 질문마다 고정 컨텍스트가 달라져 캐시를 매번 새로 썼다). 도구 단계에 최상위 자동 캐시를 더하는 안은 효과가 없어 넣지 않았다(2026-11-06 실측: 자동 캐시가 없어도 API가 두 번째 단계 끝을 5분 캐시에 쓰고(1,968 대 1,933토큰), 두 경우 모두 도구 결과가 들어간 단계는 system 앞부분이 172토큰 늘어 1시간 캐시를 읽지 못했다). 원본 질문 중 보내는 문서 본문에 이미 `- 질문` 줄로 들어 있는 것은 다시 넣지 않는다(2026-11-04: 리포트가 슬라이드별 질문 전체를 담으면서 같은 질문이 두 번 들어가 Haiku 10만 토큰 가격 구간에 질문 약 800개에서 닿던 것을 약 1600개로 늦춘다). 줄 전체가 같아야 빠지므로, 예전 형식·잘린 문서·리포트 작성 뒤에 생긴 질문은 그대로 들어간다. 질문 번호는 쓰지 않는다.
- `RPT-052` 슬라이드 근거(RPT-006): 메시지에 슬라이드 번호가 있으면 미리 붙이고(`slidesMentioned`), 그 밖에는 모델이 `view_slides`로 요청한다. 한 답변에 최대 6장. 슬라이드마다 이미지 바로 뒤에 그 슬라이드의 PIN 질문을 `- PIN (x, y)px: 질문 본문`으로 붙인다(2026-11-04, 번호로 질문 목록을 찾아가게 하던 방식을 대체). 원본은 강사 JWT로만 읽는다. 이미지는 공통 분석과 같은 경로(`analysisSlideImages`: 1920px 페이지 캐시를 AI 크기로 줄이고, 보이는 쪽의 글자만 뽑음)로 만들고, 캐시에 없는 장만 렌더해 캐시에 남기므로, 답변을 멈춰도 그 렌더는 플레이어가 다시 쓴다(2026-11-06 측정: 7번 슬라이드 9.3초 → 0.065초; 전에는 슬라이드를 지목한 질문의 첫 글자가 12~13초).
- `RPT-053` (2026-11-04 삭제, RPT-008) 모델에 `propose_document` 도구를 준다. 문서를 고쳐 달라는 요청이면 모델이 이 도구로 변경안을 낸다. 변경안은 `{ replace: {id,title,text}[], insert: {after,title,text,slide?}[], remove: id[] }`이며, 문서 전체를 다시 쓰는 요청도 이 형식으로 표현한다. 서버는 존재하지 않는 id, 범위 밖 슬라이드, RPT-022 제한 위반을 거절하고 모델에 다시 내게 한다(1회).
- `RPT-054` (2026-11-04 삭제, RPT-008) 변경안이 있는 답변에는 바뀌는 섹션 수와 `문서에 적용` 버튼을 보여준다. 적용하면 문서가 새로 작성되고(RPT-043 되돌리기 가능), 변경안이 만들어진 뒤 사용자가 같은 섹션을 고쳤으면 적용 전에 덮어쓰기를 확인받는다. 적용은 채팅 횟수에 포함하지 않는다.
- `RPT-056` (2026-11-04 삭제, RPT-008) AI는 섹션 본문에 리포트 서식(RPT-024)을 쓴다. 표는 수치·비교·목록을 정리해 달라는 요청이나 표가 더 읽기 쉬운 경우에만 넣는다. 채팅 답변 자체는 지금처럼 평문과 `**굵게**`만 쓴다.
- `RPT-055` speaker note, 참여자 식별자, 이메일은 모델에 보내지 않는다. 기존 질문 비식별 처리를 유지한다.
- `RPT-057` 입력창 안의 첨부 버튼으로 질문마다 파일 1개(PDF, PNG·JPG, TXT·MD·CSV; 10MB, 이미지 5MB 이하)를 붙인다. 형식은 이름이 아니라 파일 바이트(PDF·PNG·JPEG 서명, 그 밖에는 올바른 UTF-8 글자)로 서버가 다시 판단하고, 글자 파일은 앞 5만 자만 비식별 처리해 보낸다. 파일은 저장하지 않고 그 질문에만 AI에 보낸다. 대화 기록에는 파일 이름만 남고 다음 질문에서는 다시 보내지 않는다. 입력창 위쪽에 파일 이름 칩(Figma `ClassPin` 2224:2314)과 빼기 버튼을 보인다(2026-11-02 승인).
- `RPT-058` 입력창의 `슬라이드·질문 데이터 포함`(기본)·`문서만 사용` 선택을 질문마다 보낸다. 선택은 칩 버튼과 위로 열리는 메뉴(`popover`, `role=menu`/`menuitemradio`, 항목마다 한 줄 설명, 위·아래 화살표·Esc·바깥 클릭, 고르면 칩으로 포커스 복귀; 2026-11-04 네이티브 select를 대체)다. 문서만 사용이면 원본 질문 목록, 슬라이드 자동 첨부, `view_slides`를 빼고 문서(수치 포함)와 첨부만 보낸다. 선택은 저장하지 않는다.
- `RPT-059` 입력창 바로 위에 추천 요청 칩(Figma `ClassPin` 2224:2305)을 둔다. AI를 부르지 않고 코드가 고른다(2026-11-04부터 질문형): `세 줄 요약`, `다음 강의 개선점`, 질문이 가장 많은 슬라이드의 `슬라이드 n 원인`. 칩은 입력창을 채우기만 하고 보내지 않는다(질문 횟수 보호). 편집기에 그래프가 없으므로 `그래프 추가`는 두지 않는다.

## 7. 내보내기

- `RPT-060` 생성이 끝난 리포트는 언제든 내보낼 수 있다. 입력은 저장된 문서다. 슬라이드 이미지는 `/api/pdf/page`가 디스크에 두는 1920px 페이지 이미지(`pdfPageImage`, 14일; 2026-11-07 전에는 24시간)를 함께 써서, 플레이어에서 본 슬라이드나 같은 리포트의 두 번째 형식은 다시 그리지 않는다(2026-11-04 측정: 15장 기준 처음 약 12초, 그 뒤 약 0.7초). 처음 그릴 때는 서버 코어의 절반까지 동시에 그린다(시청자용 2개 제한과 따로). 이미지 슬라이드와 캐시가 없는 경우는 기존 렌더를 쓴다. 강사당 동시 내보내기 1개, 미리보기 제공은 기존 동작을 유지한다. 내보내기 팝업의 형식 카드 모양은 Figma `ClassPin` 2236:2842를 따른다(2026-11-01).
- `RPT-061` **PDF·DOCX(작성한 그대로)**: A4 세로. 제목 → 수치 표 → 섹션을 편집기 순서대로. 슬라이드가 연결된 섹션은 본문 위에 슬라이드 이미지를 페이지 폭에 맞춰 넣는다. 본문 글자는 작게 8.5pt·보통 10.5pt·크게 14pt, 굵게는 굵은 글꼴이다. 표는 페이지 폭의 격자이고 머리 행은 굵게, 칸 너비는 같게 나눈다. 표가 페이지를 넘으면 행 경계에서 넘기고 다음 페이지에 머리 행을 다시 그린다. 기울임은 기울임 글꼴(PDF는 나눔고딕에 기울임체가 없어 12도 기울인 글자), 밑줄은 밑줄, 링크는 브랜드 색·밑줄의 누를 수 있는 링크(PDF는 URI 주석)다.
- `RPT-062` **PPTX(재구성)**: 16:9. 표지(제목, 자료 이름, 날짜) → 섹션마다 1장(수치 카드 장은 RPT-065로 없앴다). 슬라이드가 연결된 섹션과 그래프 섹션은 왼쪽 이미지, 오른쪽 본문이고(이미지는 원래 비율 그대로 칸 안 가운데, 2026-11-04 찌그러짐 수정), 연결이 없으면 본문 전체 폭이다. 본문이 장에 들어갈 줄 수를 넘으면 문단 경계에서 다음 장으로 넘기고 제목에 `(계속)`을 붙인다. 글자를 자동으로 줄이지 않는다. 본문 글자는 작게 11pt·보통 14pt·크게 18pt다. 표는 PowerPoint 표로 넣고 한 행을 한 줄로 센다. 한 장에 다 들어가지 않는 표는 행 경계에서 나누고 이어지는 장에 머리 행을 다시 넣는다.
- `RPT-063` **MD(재구성)**: `# 제목`, 수치 표, 섹션마다 `## 제목`과 본문. 굵게와 표는 마크다운 그대로 두고, 글자 크기 태그는 지운다(MD에는 크기가 없다). 이미지는 넣지 않고, 슬라이드가 연결된 섹션은 제목 아래에 `슬라이드 n` 참조를 넣는다. `<i>`는 `*기울임*`이 되고 `<u>`는 지운다(MD에는 밑줄이 없다). 링크는 그대로다.
- `RPT-064` 재구성 규칙은 코드로 고정한다. 내보내기는 AI를 호출하지 않으며, 같은 문서는 항상 같은 파일이 된다. A4 문서와 PPTX·MD는 배치가 다르지만 담는 문장과 수치는 같아야 한다.
- `RPT-065` (2026-11-04 사용자 결정) 내보내기 파일에는 맨 위 수치 표(슬라이드·질문·PIN·공감·강의 시간·참여자·최대 동시 참여자)를 넣지 않는다. PDF·DOCX·MD의 수치 표와 PPTX의 `수치` 장을 모두 없앴다. 같은 내용은 개요 섹션(RPT-031)에 있다. 편집 화면 머리의 KPI 카드는 그대로다.

- `RPT-066` (2026-11-06 사용자 승인) **PDF 내부 PIN 데이터 첨부**: 리포트 본문·서식·슬라이드 이미지는 그대로 작성한다. PDF에 `ohpin-data.zip` 하나를 표준 Embedded File로 넣는다. ZIP은 `manifest.json`, `pins.json`, 실제 PDF에 그린 원본 슬라이드 이미지(`slides/slide-NNN.jpg`), `README.md`를 포함한다. PDF 페이지에 PIN 마커나 좌표 목록은 추가하지 않는다. 2026-11-06 추가 사용자 승인: PIN 첨부가 있는 PDF의 마지막 페이지 하단 여백에 흰색 5pt 텍스트로 첨부 읽기 안내를 한 번 넣는다. 새 페이지나 본문 재배치는 없고, 첨부가 없는 PDF에는 넣지 않는다. 안내는 `ohpin-data.zip`의 `pins.json`과 `manifest.json` 확인 및 첨부 접근 실패 시 위치 추정 금지를 명시한다. 이 텍스트는 선택·복사·추출될 수 있으며, 외부 AI의 첨부 자동 인식은 보장하지 않는다. 마지막 페이지에서의 텍스트 추출, 첨부 보존, 기존 본문·페이지 수·렌더 결과 유지 여부를 검증한다. 리포트 DOCX·PPTX·MD 내보내기는 기존 동작을 유지한다. 분석 대시보드 내보내기는 DSH-042에 따라 삭제한다.
  - 자료 소유권을 통과한 기존 REST 조회와 이미지 렌더 결과만 사용한다. 내보내기 시점의 자료 버전·슬라이드 ID를 보존한다. 이는 리포트 초안 작성 시점의 질문 스냅샷이 아니며, manifest와 README에 이 차이를 명시한다. 별도 DB 저장·AI 호출은 없다.
  - `schemaVersion: 0.2.0`. manifest는 실제 포함 슬라이드와 제외 슬라이드 번호, 자료·버전·강의 ID, 이미지 크기, 파일 크기·SHA-256을 담는다. 같은 슬라이드가 여러 번 나오면 `placements`에 각 섹션 ID, 최종 PDF 페이지 번호(1부터), 이미지 사각형(페이지 왼쪽 위 기준, pt)을 모두 기록한다. 차트 이미지는 슬라이드로 취급하지 않는다. 기존 슬라이드 수 불일치로 이미지가 생략되면 해당 슬라이드와 질문도 첨부에서 제외하고 누락 번호를 기록한다.
  - pins는 포함 슬라이드의 질문 원문, 원본 질문·슬라이드 ID, 생성 시각, 공감 수, 답변 원문·시각, `anchor`를 허용 목록으로 기록한다. point·box·path 좌표는 원본 이미지 기준 0~1 값을 그대로 보존한다. 위치가 없는 질문은 `anchor: null`로 보존한다. 작성자 식별자·이메일 필드·발표자 노트·Storage 경로·서명 URL·키는 넣지 않는다. 질문·답변 본문에 사용자가 적은 내용은 원문 그대로다.
  - 첨부 파일은 PDF 첨부 추출 기능으로 읽는다. 2026-11-06 호환성 수정: ZIP stream에 PDF 압축을 추가하지 않아 Python zipfile 등으로 PDF 전체를 직접 읽는 보조 경로도 유지한다. 표준 첨부 추출과 ZIP 직접 읽기가 같은 파일을 반환하는지 회귀 검사한다. PDF를 다른 앱에서 다시 저장하면 직접 읽기 경로가 깨질 수 있다. 첨부를 읽지 않는 외부 AI의 자동 인식은 보장하지 않는다. 같은 문서·소스 데이터·이미지를 입력하면 같은 PDF 바이트를 출력한다. 첨부 생성 실패는 내보내기 오류로 처리한다. 데이터 없이 성공한 것처럼 내려주지 않는다.
  - 검증: 실제 첨부 추출, SHA-256·원문·좌표 일치, 페이지·이미지 위치 연결, 반복 슬라이드 중복 제거, 차트 및 범위 밖 질문 제외, 비공개 필드 제외, PDF 본문·미리보기 다운로드 동일성, 기존 네 형식 회귀를 확인한다.

- `RPT-067` (2026-11-06 사용자 승인) **DOCX·PPTX 내부 PIN 데이터와 분석 안내**: 리포트 내보내기에도 PDF와 동일한 소유권·원문·좌표·비공개 필드 제외 규칙을 적용한다. 실제 포함된 슬라이드만 담은 `ohpin-data.zip`을 OOXML 패키지의 `ohpin/ohpin-data.zip`에 application-specific part로 저장하고, 패키지 relationship과 content type을 등록한다. 화면에 첨부 아이콘이나 PIN 마커를 추가하지 않는다. DOCX는 마지막 여백 문단, PPTX는 마지막 슬라이드 하단 여백에 흰색 분석 안내를 한 번 넣는다. 안내는 내부 첨부의 `pins.json`·`manifest.json` 확인과 접근 실패 시 위치 추정 금지를 포함한다. 첨부가 없는 내보내기와 MD는 그대로 유지한다.
  - PPTX placements는 출력 슬라이드 번호와 이미지 사각형(pt)을 기록한다. DOCX는 섹션 ID와 문서 이미지 순서(1부터)를 기록하고, 재배치되는 페이지 번호와 사각형은 null로 둔다. 원본 슬라이드 정규화 좌표는 모든 형식에서 그대로 보존한다.
  - 내부 ZIP·해시·질문 원문·좌표, 프롬프트 추출 및 마지막 위치, 기존 본문·슬라이드 수·렌더 결과를 검증한다. 이는 매크로나 자동 실행 기능이 아니다. 외부 AI의 자동 추출 및 다른 편집기에서 다시 저장한 뒤의 첨부 보존은 보장하지 않는다.

## 8. 강의 참여자 수 저장

- `RPT-070` 플레이어의 접속자 집계(`useLiveAudienceCount`)는 LIVE 동안 본 탭 id의 누적 수와 최대 동시 접속 수를 함께 센다. 값은 기존 heartbeat를 그대로 쓰며 새 broadcast를 추가하지 않는다.
- `RPT-071` 강사가 플레이어에서 강의를 종료해 저장에 성공하면, 그 두 값과 `started_at`·`ended_at`을 `POST /api/admin/lectures/[id]/audience`로 보낸다. route는 강사 JWT로 REST 소유권을 확인한 뒤 서버 권한으로 저장한다. 같은 강의를 다시 LIVE로 열고 종료하면 마지막 회차 값으로 덮어쓴다(`started_at`과 같은 규칙).
- `RPT-072` 한계: 값은 탭 기준 근사치이며 출석이 아니다. 강의 창이 처음부터 끝까지 열려 있었을 때만 정확하다. 자동 종료(60분 이탈)나 다른 경로로 끝난 강의는 기록이 없다. 정확한 값이 필요하면 BE 집계로 옮긴다.

## 9. 데이터, API, 권한

FE forward-only 마이그레이션 하나로 두 테이블을 만든다. 둘 다 RLS를 켜고 `anon`/`authenticated` 권한을 회수하며, 서버(service_role)만 읽고 쓴다. route는 매 요청 강사 JWT로 소유자를 확인하고, 소유자 id를 요청 본문에서 받지 않는다(기존 `ai_insight_reports`와 같은 패턴).

```sql
instructor_reports(id uuid pk, owner_id uuid not null, material_id uuid not null,
  status text check (status in ('drafting','failed','ready')), error text,
  document jsonb, previous_document jsonb, messages jsonb not null default '[]',
  created_at timestamptz, updated_at timestamptz, unique (owner_id, material_id))
lecture_audience_records(lecture_id uuid pk, owner_id uuid not null, started_at timestamptz, ended_at timestamptz,
  audience int not null check (audience >= 0), peak_audience int not null check (peak_audience >= 0), recorded_at timestamptz)
```

| API | 동작 |
|---|---|
| `GET /api/admin/reports` | 내 리포트 목록 |
| `POST /api/admin/reports` | `{ materialId }`. 소유권과 강의 종료 확인. 이미 있으면 기존 리포트를 돌려주고, 없으면 만들고 초안 생성 시작 |
| `GET /api/admin/reports/[id]` | 리포트 조회(문서, 상태, 대화) |
| `PATCH /api/admin/reports/[id]` | `{ document, updatedAt }` 저장. 불일치는 409 |
| `POST /api/admin/reports/[id]` | `action`: `retry`(문서가 없는 실패 리포트만)·`cancel`·`undo`·`chat`·`reset` |
| `DELETE /api/admin/reports/[id]` | 리포트 삭제 |
| `GET /api/admin/reports/[id]/export?format=pdf\|docx\|pptx\|md` | 내보내기 |
| `POST /api/admin/lectures/[id]/audience` | 참여자 수 기록(§8) |

- `RPT-080` 기존 `ai_insight_reports` 데이터와 테이블은 그대로 두고 새 화면에서 보이지 않는다. 삭제는 별도 승인이 필요하다.
- `RPT-081` 다른 강사와 익명 참여자는 리포트 목록·내용·대화·내보내기에 접근할 수 없다(404).

- `RPT-100` 문서 열은 PDF 내보내기와 같은 A4 페이지다(최대 794px = 210mm@96dpi, PDF 595pt의 1.334배). 화면 배경은 `--color-bg-page`, 페이지는 `--color-bg-surface`에 1px `--color-border`. 2026-10-29 사용자 요청으로 미리보기와 편집 화면의 형태를 같게 맞췄다.
- `RPT-101` 목차 rail(240px)은 섹션 번호와 제목 목록이다. 현재 보이는 섹션을 `--color-brand` 글자와 `--color-brand-subtle` 배경으로 표시하고, 누르면 그 섹션으로 이동한다. 접을 수 있고, lg 미만에서는 기본으로 접힌다. 2026-11-02부터 목차는 캔버스 박스 안 왼쪽(220px)에 열리며, 1024px 이상에서는 열린 채, 그 아래에서는 서랍으로 닫힌 채 시작한다(같은 날 사용자 요청으로 열림을 기본으로 되돌림).
- `RPT-102` 페이지 머리는 PDF와 같다: `OhPin 리포트`(13/700, `--color-brand`) → 리포트 제목(28/700) → `파일명 · 날짜`(13, secondary) → 2열 수치 표. 섹션은 제목(22/700, 줄바꿈되는 제목) → 슬라이드가 연결되면 `슬라이드 n`(12/700, brand) → 슬라이드 이미지(페이지 폭) → 본문(14/22). 섹션 번호 배지와 칩은 쓰지 않는다(목차에만 번호). 2026-11-02 Figma `ClassPin` 2224:2333으로 바꿨다: 회색 캔버스 위 700px 종이(padding 40/48, radius 12), `AI 강의 리포트` 칩 → 제목 → `날짜 · 진행 n분 · 참여 n명 · 질문 n건` → KPI 카드 네 개(총 질문, 참여자, 핀이 찍힌 슬라이드 n/전체, 공감 수) → `질문이 몰린 슬라이드` 막대(질문 수 상위 3장, 코드가 그림, 읽기 전용) → 섹션(`n.` 번호 + 제목 17/700, 본문 15/24). 핀이 찍힌 슬라이드와 막대는 지금의 자료 데이터로 그리므로 편집 화면에만 있고, 내보내기는 지금처럼 수치 표를 쓴다.
- `RPT-103` (2026-11-04 삭제, RPT-008) 편집은 제자리에서 한다. 제목은 테두리 없는 input, 본문은 서식이 보이는 편집 영역(contentEditable, Body 14/22, 크게 18/28·작게 12/18)이며, 포커스할 때만 `--focus` 링을 보인다. 편집할 수 있는 동안 문서 열 위에 서식 도구(굵게 `Ctrl/⌘+B`, 크게, 보통, 작게)를 고정해 두고, 본문에서 글자를 선택하기 전에는 비활성으로 둔다. 도구는 마지막으로 선택한 본문 글자에 적용하므로 키보드로 선택한 뒤 도구로 옮겨 가도 된다. 도구는 accessible name과 눌림 상태(`aria-pressed`)를 둔다. 붙여넣거나 끌어 놓은 내용은 서식 없이 글자만 남긴다. 표는 편집기에서 읽기 전용 블록이다: 표 추가·삭제 버튼은 없고 칸을 직접 고칠 수 없다. 표를 만들거나 고치거나 지우려면 AI에게 요청한다(2026-10-30 사용자 요청으로 표 삭제 버튼을 뺐다). 2026-11-02부터 서식 도구는 문서 열 맨 위에 붙은 44px 막대(Figma 2224:2357)다: 글자 스타일 select(제목 18/28·본문 15/24·작게, 저장 형식의 크게·보통·작게와 같다), 굵게·기울임·밑줄(`Ctrl/⌘+B/I/U`, 눌림 상태 표시), 글머리 기호(커서가 있는 줄 앞에 `- `), 표(AI 채팅 입력창을 표 요청으로 채운다. 표는 여전히 AI만 넣는다), 링크(막대 안 주소 입력칸, http(s)가 아니면 입력칸 아래 오류. 글자를 고르지 않았으면 주소를 글자로 넣는다. 커서가 링크 안이면 같은 버튼이 `링크 빼기`), 오른쪽 안내 문구. 차트·이미지는 저장 형식과 저장소가 따로 필요해 보류했다(2026-11-02).
