## 1. 범위

- `DSH-001` 대시보드 하나는 강의(자료) 하나를 다룬다. 경로는 `/admin/insights/[id]`(`id` = 강의 id, `ClassSession.id`). 진입은 분석 목록(§7)이다. 리포트 작성은 대시보드 머리의 `AI 리포트 만들기`로 간다(2026-11-01).
- `DSH-002` 포함: 머리(경로·자료 전환·날짜·진행 시간·참여자), 요약 배너, 개요(질문 현황·반응 현황), 시간대별 질문 흐름, 슬라이드별 핀 분석, 질문 분석(질문 유형·전체 질문), 구역별·전체 내보내기.
- `DSH-003` 제외: 이모지 반응 그래프, LIVE 회차 비교, 질문 감정 분류, 폴더 안 강의 비교, 미답변·답변·해결 수(2026-10-29). 익명 질문 비율은 모든 질문이 `is_anonymous = true`로 저장돼 항상 100%라 넣지 않는다(2026-11-01). 슬라이드별 핀 참여 인원은 BE `ClassPin-BE#10` B 이후로 미룬다. 개요의 참여자 단위 지표는 DSH-023으로 되돌렸다(2026-11-01). 분당 PIN·참여자 선 그래프, 슬라이드 노출 시간 표, 슬라이드별 시계열, 키워드 워드 클라우드도 Figma 개편으로 뺐다(2026-11-01).
- `DSH-004` 시간 데이터는 마지막 LIVE 회차 기준이다. 같은 강의를 다시 LIVE로 열면 기록을 새로 쓴다(`started_at`과 같은 규칙).

## 2. 강의 타임라인 기록 (FE만 변경, BE 변경 없음)

- `DSH-010` 강사 플레이어가 LIVE 동안 1분마다 `{at, audience, slide}`(현재 접속 탭 수, 화면 슬라이드 1-based)를 쌓는다. 슬라이드가 바뀔 때마다 `{at, slide}`를 쌓는다. 값은 기존 heartbeat 집계와 플레이어가 보는 `currentSlide`에서 얻으며 새 broadcast를 추가하지 않는다. 2026-11-01부터 대시보드는 표본·전환을 그리지 않고 종료 시각과 참여자 수만 쓴다. 기록은 리포트 수치와 이후 분석을 위해 유지한다.
- `DSH-011` 플레이어는 5분마다, 그리고 강의 종료 저장 직후에 지금까지의 기록 전체를 `POST /api/admin/lectures/:id/audience`로 보낸다(덮어쓰기). 실패해도 수업을 막지 않는다. 탭을 닫으면 마지막 전송 이후 최대 5분이 빠진다.
- `DSH-012` 서버는 강의 소유권을 강사 JWT로 `GET /api/instructor/lectures/{id}/state`에 물어 확인한다(내 강의가 아니면 그 응답에 `id`가 없다). 전체 강의 그래프를 읽지 않는다. 표본 1,440개(24시간), 슬라이드 전환 5,000개를 넘거나 값이 범위를 벗어나면 400.
- `DSH-013` 한계: 값은 탭 기준 근사치이고 출석이 아니다.

## 3. 데이터와 API

- `DSH-020` `lecture_audience_records`에 `samples jsonb`, `slide_changes jsonb`(기본 `[]`)를 더한다. `instructor_reports`에 초안 분석 결과 `analysis jsonb`를 더한다(질문 유형과 슬라이드 AI 요약의 출처). 리포트 없는 질문 유형은 `lecture_question_groups`(강의당 한 행: `question_ids`, `groups`, `provider`, `model`, service_role 전용, 2026-11-01)에 둔다.
- `DSH-021` `GET /api/admin/lectures/:id/insights` → `{ record: { startedAt, endedAt, audience, peakAudience } | null, topics: { title, summary, questionIds }[] | null, slides: { page, summary }[] | null, reportId: string | null }`. `slides`는 분석의 `slides[].questionSummary`다. 두 테이블 모두 호출자 `owner_id`로 거른다. REST 그래프를 읽지 않는다.
- `DSH-022` 질문·슬라이드·`startedAt`은 화면이 이미 가진 세션 스토어 데이터를 쓴다. 강의 종료 시각은 `record.endedAt`을 쓰고, 없으면 마지막 질문 시각까지를 강의 구간으로 본다.
- `DSH-023` (2026-11-01 사용자 결정) `GET /api/admin/lectures/:id/participation` → `{ questionAuthors, engaged, reactorsOrPinAuthors }`. 질문 작성자 수, 질문 또는 공감한 사람 수, 공감했거나 핀(위치 있는 질문)을 남긴 사람 수다. 강의의 모든 질문·공감을 센다(회차 구분 없음). 사용자 ID는 응답에 넣지 않는다.
  - 1단계(임시, FE): route가 강사 JWT로 소유권을 확인한 뒤(DSH-012와 같은 확인) 서버 권한으로 `questions(author_id, region_id)`와 `question_reactions(reactor_id)`를 1,000행씩 나눠 읽고 `participationCounts`로 센다. "업무 데이터는 BE를 거친다" 규칙의 예외이며 사용자가 승인했다.
  - 2단계: BE `ClassPin-BE#10` B(`GET /api/instructor/lectures/{id}/participation`, 같은 응답)가 배포되면 화면은 BE 프록시 주소를 부르고 1단계 route를 지운다.

## 4. 계산 (순수 함수, `app/_model/insight-dashboard.ts`)

- `DSH-030` 시간대별 질문 흐름: 강의 구간을 최대 6칸으로 나눈다(강의 분은 머리의 "진행 n분"과 같이 반올림, 칸 = `ceil(강의 분 / 6)`분, 최소 1분). 구간 안에 만든 질문(위치 유무와 무관)을 칸마다 센다. 강의 구간이 없으면(LIVE 기록 없음) 그래프 대신 이유를 쓴다.
- `DSH-031` 개요는 세 칸이다(Figma `ClassPin` 2235:2495). 칸마다 도넛 하나, 한 줄 설명, 수치 세 줄이다. 비율은 100%를 넘지 않게 자르고, 분모가 없으면 도넛 대신 "기록 없음"을 보인다.
  - 참여 현황: 도넛 = 질문 또는 공감한 사람 ÷ 총 참여자. 총 참여자(`record.audience`, 마지막 LIVE에서 본 탭 수, 탭 기준 근사), 질문한 참여자, 공감·핀 참여자.
  - 질문 현황: 도넛 = 질문한 참여자 ÷ 총 참여자. 전체 질문, 1인당 평균 질문(전체 질문 ÷ 질문한 참여자), 핀이 있는 질문 비율.
  - 반응 현황: 도넛 = 핀이 찍힌 슬라이드 ÷ 전체 슬라이드. 공감 수, 핀이 찍힌 슬라이드 수 / 전체, 슬라이드당 평균 핀.
  - 참여 집계(DSH-023)를 받지 못하면 그 값의 줄과 도넛만 "기록 없음"이고 나머지는 그대로 보인다. 총 참여자는 탭 수, 질문·공감한 사람은 브라우저 수라 새로고침·여러 탭이 있으면 비율이 실제보다 낮게 나올 수 있다.
- `DSH-032` 요약 문장은 AI를 부르지 않고 위 수치로 만든다. 라벨은 `요약`이다. 배너: 질문·공감 수와 질문이 가장 많은 슬라이드. 개요: 참여율, 질문한 참여자 비율, 핀·공감 참여자 비율(참여 집계가 없으면 핀 비율과 핀이 찍힌 슬라이드). 평가하는 말("높은 편")은 쓰지 않는다. 시간대: 질문이 가장 많은 칸. 슬라이드: 질문이 많은 상위 두 슬라이드의 비중. 질문 분석: 가장 큰 질문 유형, 없으면 공감이 가장 많은 질문.
- `DSH-033` 슬라이드 아래 한 줄은 리포트 분석의 `questionSummary`이고 이것만 `AI 요약` 라벨을 쓴다. 리포트가 없으면 이 줄을 숨긴다.
- `DSH-034` 질문 유형은 질문의 주제 묶음이다. 질문 유형(`category`)은 전체 숨김 계약 때문에 항상 한 값이라 쓰지 않는다. 묶음마다 현재 존재하는 질문 수와 전체 질문 대비 비율을 막대로 보이고, 남은 질문이 없는 묶음은 뺀다.
  - 출처 1: 리포트 분석의 `groups`(리포트가 있으면 이것만 쓴다). 단, 그 묶음이 지금 있는 질문을 하나도 담지 않으면(리포트를 만든 뒤 질문이 모두 지워진 경우) 리포트 분석이 없는 것으로 보고 출처 2와 슬라이드 AI 요약 숨김을 따른다.
  - 출처 2 (2026-11-01 사용자 결정, 리포트가 없거나 수치만으로 시작한 리포트일 때): 대시보드가 `POST /api/admin/lectures/:id/question-groups`를 부른다. 서버는 강사 JWT로 소유권(DSH-012와 같은 확인)과 강의 질문(`GET /api/instructor/lectures/{id}/questions`)을 읽고, 저장된 묶음이 지금 질문 id 집합과 같으면 그대로 돌려준다. 다르면 AI(`INSIGHT_AI_PROVIDER`, 리포트와 같은 공급자·모델)를 글자만으로 한 번 불러 3~7개 묶음으로 묶고 `lecture_question_groups`에 덮어쓴다. 질문 본문은 리포트와 같이 `redactInsightText`를 거친다. 같은 강의의 동시 요청은 서버 한 대 안에서 한 번의 호출을 나눠 쓴다. 질문 앞 500개만 AI에 보내고 나머지와 AI가 빠뜨린 질문은 "기타 질문"에 넣는다.
  - 화면: 묶는 동안 "질문을 주제별로 묶는 중이에요…", AI 설정이 없으면 "AI 설정이 없어 질문 유형을 만들 수 없습니다", 실패하면 "질문 유형을 만들지 못했습니다. 잠시 후 다시 열어 주세요", 질문이 없으면 "질문이 없어 질문 유형이 없습니다"를 보인다.
  - 비용: 질문 집합이 바뀐 뒤 대시보드를 처음 열 때마다 AI 호출 1회(질문 4개 기준 입력 약 1.2K·출력 약 170 토큰, 2026-11-01 로컬 측정).

## 5. 화면 (Figma `ClassPin` 2235:2458)

- `DSH-040` 폴더 트리 사이드바 안에 둔다. 위에서부터: 머리(뒤로 가기 → 분석 목록, 경로 `분석 › 폴더 › 자료`, 제목과 같은 폴더 자료 전환 네이티브 select, `날짜 · 진행 n분 · 참여 n명`, `AI 리포트 만들기`, `전체 내보내기`) → 요약 배너 → 개요(질문 현황·반응 현황 두 칸, 각각 도넛 하나와 수치 세 줄) → 시간대별 질문 흐름(막대, 가장 많은 칸만 진한 브랜드 블루) → 슬라이드별 핀 분석(왼쪽: 슬라이드 위 PIN 위치, 이전·다음, 썸네일 줄 `P.n · 질문 수`; 오른쪽: 핀·질문·공감 수, 공감순 질문, AI 요약) → 질문 분석(왼쪽: 질문 유형 막대; 오른쪽: 전체 질문, 검색, 필터 메뉴(Figma 2242:2144: 질문이 있는 슬라이드만 칩으로 보이는 `전체`·`P.n` 단일 선택과 `공감순`·`최신순` 정렬, 바깥 클릭·Esc로 닫힘), 10개씩 페이지).
- `DSH-041` `AI 리포트 만들기`는 리포트 메인(`/admin/reports?material=<자료 id>`, RPT-011·012)으로 가서 이 자료를 미리 고른다. 템플릿과 요청은 거기서 고른다.
- `DSH-042` 내보내기는 Figma `ClassPin` 2236:2842 팝업이다(2026-11-01 사용자 요청, 이전의 브라우저 인쇄 방식을 대체). 리포트 편집기와 같은 팝업 컴포넌트(`app/component/export-dialog.tsx`)와 같은 서버 생성기(`exportReport`, PDF·PPTX·DOCX·MD)를 쓴다.
  - 왼쪽은 실제 파일의 미리보기(페이지 썸네일·이전/다음)이고, 오른쪽은 형식 네 개와 포함 항목(분석 요약·개요·시간대별 질문 흐름·슬라이드별 핀 분석·질문 분석) 체크박스다. 구역의 `내보내기`는 그 항목만, 머리의 `전체 내보내기`는 모든 항목을 체크한 채 연다. 마지막 남은 항목은 해제할 수 없다. 항목이나 형식을 바꾸면 미리보기를 다시 만든다.
  - 아래쪽은 안내 문구, `AI 리포트로 이어서 작성`(DSH-041과 같은 이동), `내보내기`(파일 저장)다.
  - 화면이 이미 가진 수치와 문장으로 문서를 만들어 `POST /api/admin/insights/export?format=&preview=1`에 보낸다. 서버는 강사 JWT를 확인하고 문서 형태·길이만 검사하며(`parseExportDocument`, 리포트와 같은 한도), AI를 부르지 않는다. 강사당 동시 내보내기 1개는 리포트와 같다(RPT-060).
  - 문서는 리포트 내보내기 형식을 따른다: 제목 `{자료} 분석`, 날짜는 강의일, 맨 위 수치 표(리포트와 같은 7행)는 항목 선택과 상관없이 들어간다. 한 항목이 구역 길이 한도를 넘으면 `(2)`, `(3)` 구역으로 이어 쓴다. 전체 질문은 검색·필터와 상관없이 모두 공감순으로 넣는다.
  - 슬라이드 이미지는 넣지 않는다(서버가 자료 그래프를 읽지 않도록). Figma 문구 중 "참여율"과 "다음 강의 개선 제안"은 낼 수 없는 값이라 뺐다.
- `DSH-043` 기록이 없는 항목은 비워 두지 않고 이유를 쓴다. 모든 컨트롤에 accessible name과 focus-visible을 둔다. 슬라이드 선택과 페이지 이동은 키보드로 할 수 있어야 한다.

## 6. 검증

- Node 테스트: 기록 누적(1분 표본·전환), 강의 구간, 시간대별 질문 칸, audience/insights route(소유권, 입력 검증).
- Node 테스트: 내보내기 구역 나누기(`exportSections`), 내보내기 문서 검사(`parseExportDocument`), 질문 묶음 번호→id 변환(`questionGroups`), 참여 집계(`participationCounts`).
- 로컬 브라우저: 분석 목록 → 분석 보기 → 대시보드 각 구역, 슬라이드 이동, 질문 검색·필터·페이지, AI 리포트 만들기, 구역·전체 내보내기 팝업(형식 전환, 항목 체크, 미리보기, 파일 저장).
- `npm run lint`, `npm run build`, 새 마이그레이션의 로컬 DB 적용.

## 7. 분석 목록 (Figma `ClassPin` 2222:10840)

- `DSH-050` 경로는 `/admin/insights`. 폴더 트리 사이드바 안에 두고, 사이드바의 `홈으로` 아래에 `분석` 항목을 둔다. 새 API 없이 세션 스토어의 자료·폴더와 브라우저의 열람 기록만 쓴다.
- `DSH-051` 머리: `분석` 제목과 `자료 · 폴더 검색` 입력. 검색어가 자료 제목이나 폴더 이름에 들어 있는 자료만 두 구역 모두에 남긴다.
- `DSH-052` **최근 분석**: 최근에 대시보드(`/admin/insights/[id]`)를 연 자료다(2026-11-01 사용자 결정, 리포트 유무와 무관). 열 때마다 강의 id와 시각을 계정별 브라우저 저장소(`useBrowserPreferences`, `recent-analyses`)에 남기고 최신 20개만 둔다. 목록은 최근에 연 순서로 최대 4개 카드(첫 슬라이드 썸네일, 제목, `폴더 · 질문 n · 날짜`, `분석 보기` 버튼)를 보이고, 연 자료가 없으면 구역 전체를 숨긴다. 기록은 브라우저마다 따로이고 브라우저 저장소를 지우면 사라진다. 기기를 바꿔도 같은 목록이 필요하면 서버 저장으로 옮긴다.
- `DSH-053` **자료별 분석**: 모든 자료를 카드 격자로(썸네일, 제목, `질문 n건 · 날짜`). 카드 전체가 대시보드 링크이며 accessible name은 자료 제목이다. 폴더 선택(전체·폴더별·미분류, 자료 수 표시, 네이티브 select)으로 거른다. 순서는 최근 강의순(`startedAt`, 없으면 `createdAt`) 하나뿐이다.
- `DSH-054` 목록에는 리포트 버튼이 없다. 리포트는 대시보드에서 연다(DSH-041).
- `DSH-055` 자료가 없으면 "폴더에 자료를 올리면 분석을 볼 수 있어요"를, 검색·폴더 결과가 없으면 "조건에 맞는 자료가 없습니다"를 보인다.
