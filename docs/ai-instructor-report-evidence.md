# AI 강의자 리포트 근거 명세

- Artifact: `ai-report-evidence`
- Status: `reviewed`
- Source: `doc/pin_class_prd.md`, `docs/ai-instructor-report-product.md`
- Decision boundary: 공간 근거 묶음, 구조화 AI 출력, 출처 추적, 근거 충분성, revision 제약, 출시 차단 평가 기준

이 문서는 API, 데이터베이스, 작업 실행 인프라, AI 제공자 설정과 운영 정책을 정의하지 않는다.

## 1. 근거 단위와 판단 보류

- `AIR-EVID-001` 모든 분석 문장과 주요 결론은 생성 요청의 고정된 snapshot 안에 있는 원본 근거를 하나 이상 참조해야 한다.
- `AIR-EVID-002` PIN 기반 판단의 독립 근거 1건은 snapshot에 포함된 서로 다른 질문 레코드 1개다.
- `AIR-EVID-003` 공감 수, 답변, 질문 상태는 해당 질문 근거의 맥락과 강도를 보강하지만 별도의 독립 근거로 계산하지 않는다.
- `AIR-EVID-004` 질문 수, 공감 수, 상태별 수, 답변 유무와 같은 수치는 코드가 계산하며 AI가 재계산하거나 추정하지 않는다.
- `AIR-EVID-005` 관련 질문 근거가 2건 미만이면 PIN 기반 패턴이나 반복 혼란을 단정하지 않고 패턴 판단을 보류한다.
- `AIR-EVID-006` 질문 근거가 부족해도 슬라이드 이미지에 직접 근거한 자료 요약은 허용하되, 수강생 반응으로 확인된 결론처럼 표현하지 않는다.
- `AIR-EVID-007` 좌표 없는 슬라이드 전체 질문도 질문 근거 1건으로 계산하되 공간 위치를 추론하지 않고 `좌표 없음`으로 표시한다.

## 2. 공간 근거 묶음

- `AIR-EVID-010` 각 슬라이드 근거 묶음은 비식별화된 전체 이미지, 좌표가 표시된 비식별화 전체 이미지, 질문별 비식별화 좌표 주변 crop, 질문 본문, 카테고리, 상태, 시간순 답변 이력, 공감 수를 포함한다.
- `AIR-EVID-011` speaker note, 수강생 식별자, 이메일, 세션 식별자와 인증 정보는 근거 묶음에 포함하지 않는다.
- `AIR-EVID-012` point crop은 해당 좌표를 중심으로 슬라이드 너비와 높이의 각각 40%인 영역을 사용하고 이미지 경계 안으로 이동한다.
- `AIR-EVID-013` box와 path crop은 전체 좌표의 최소 경계 상자에 슬라이드 너비와 높이의 각각 10%를 사방 여백으로 더하고, 결과가 너비 또는 높이 40%보다 작으면 해당 축을 중심 기준으로 40%까지 확장한다.
- `AIR-EVID-014` crop 경계는 0~1 범위로 제한하며 원본 좌표 자체를 자르거나 보정하지 않는다. 유효 범위를 벗어난 좌표는 `좌표 없음`으로 바꾸지 않고 근거 검증 실패로 처리한다.
- `AIR-EVID-015` 좌표 없는 질문은 전체 슬라이드 이미지만 사용하며 marker 또는 주변 crop을 임의로 생성하지 않는다.
- `AIR-EVID-016` point, box, path의 원래 기하 형태를 오버레이에 유지하고, 오버레이가 원본 내용을 대체하거나 원본 이미지 파일을 변경해서는 안 된다.
- `AIR-EVID-017` 동일한 원본 이미지와 좌표에는 항상 동일한 crop 경계가 계산되어야 하며, 근거 묶음에는 원본 이미지 checksum과 정규화된 crop 경계를 기록한다.
- `AIR-EVID-018` 모델이 근거 범위나 crop을 다시 선택하게 하지 않는다.
- `AIR-EVID-019` 자료명, 질문과 답변 등 텍스트 필드의 이메일, 전화번호, 인증 token과 API key 형태 문자열은 모델 입력, 리포트, 근거 화면과 PDF에서 결정론적으로 가리고 원문과의 복원 mapping은 외부 AI에 보내지 않는다.

## 3. 슬라이드별 분석과 전체 합성

- `AIR-EVID-020` 선택 범위의 모든 슬라이드를 각각 독립된 멀티모달 분석 단위로 처리한다.
- `AIR-EVID-021` 질문이 없는 슬라이드도 원본 이미지에 근거한 자료 요약을 만들 수 있도록 분석 대상에서 제외하지 않는다.
- `AIR-EVID-022` 슬라이드 분석은 해당 슬라이드의 공간 근거 묶음과 코드가 계산한 사실만 입력으로 사용한다.
- `AIR-EVID-023` 각 슬라이드 분석은 자유 형식 본문이 아니라 검증 가능한 구조화 결과를 반환해야 한다.
- `AIR-EVID-024` 코드 검증을 통과한 슬라이드 결과만 자료별·선택 범위 전체 합성 입력으로 사용할 수 있다.
- `AIR-EVID-025` 전체 합성은 원본 이미지나 원본 질문을 새로 해석하지 않고 검증된 슬라이드 결과와 코드 집계만 사용한다.
- `AIR-EVID-026` 전체 합성에서 새 사실, 새 수치 또는 슬라이드 분석에 없는 근거 관계를 추가해서는 안 된다.
- `AIR-EVID-027` 한 슬라이드의 분석이 최종 실패하면 해당 슬라이드를 조용히 제외하거나 부분 리포트를 만들지 않고 전체 생성 요청을 실패 처리한다.
- `AIR-EVID-028` 슬라이드 처리 순서나 병렬 실행 순서가 최종 근거 식별자와 정렬 순서를 바꾸지 않아야 한다.
- `AIR-EVID-029` 자료별 결과와 전체 결과는 material version, slide, 질문 근거까지 역추적할 수 있어야 한다.

## 4. 공간 후보와 의미 관계

- `AIR-EVID-030` 서로 같은 슬라이드 위치 기반 결론을 지지할 수 있는 질문 후보는 같은 슬라이드 안에서만 만든다.
- `AIR-EVID-031` 코드는 슬라이드를 20×20 정규화 격자로 나누고, anchor가 차지하는 셀과 상하좌우·대각선으로 바로 인접한 8개 셀을 사용해 공간 후보를 만든다.
- `AIR-EVID-032` point는 좌표가 속한 셀을 사용하고, box와 path는 전체 경계 상자가 닿는 모든 셀을 사용한다.
- `AIR-EVID-033` 좌표 있는 두 질문은 점유 셀이 같거나 인접할 때만 의미 비교 후보가 될 수 있다.
- `AIR-EVID-034` 코드는 같은 슬라이드의 좌표 없는 질문끼리 별도 비공간 후보를 만들며, 이 질문들은 위치 기반 결론의 근거로 사용할 수 없다.
- `AIR-EVID-035` AI는 코드가 만든 후보마다 `같은 결론을 지지`, `모순`, `무관` 중 하나와 짧은 판정 이유를 구조화 출력으로 반환한다.
- `AIR-EVID-036` AI는 후보에 없던 질문 관계를 새로 만들거나 서로 다른 슬라이드의 질문을 하나의 공간 혼란으로 묶을 수 없다.
- `AIR-EVID-037` PIN 기반 결론에 포함된 모든 질문 쌍은 코드가 만든 공간 후보 또는 비공간 후보여야 하며 AI가 각각 `같은 결론을 지지`로 판정해야 한다.
- `AIR-EVID-038` 코드는 모든 참조 질문의 실존, snapshot 포함 여부, slide 일치, 공간 후보 포함 여부를 다시 검증한다.
- `AIR-EVID-039` AI가 판정한 의미 관계와 이유는 이후 합성과 revision에서 변경하지 않고 근거 기록으로 보존한다.

## 5. 모순과 근거 수준

- `AIR-EVID-040` 같은 주제에 서로 모순되는 질문 근거가 있으면 어느 한쪽을 자동으로 정답이나 다수 결론으로 선택하지 않는다.
- `AIR-EVID-041` 모순된 양쪽의 주장, 지지 질문 수, 공감 수와 원본 근거를 함께 표시하고 강사가 확인할 쟁점으로 제시한다.
- `AIR-EVID-042` 모순이 있는 PIN 기반 결론의 근거 수준은 질문 수와 관계없이 `제한적`으로 둔다.
- `AIR-EVID-043` 모순된 질문을 지지 근거 수에 합산하거나 공감 수로 모순을 해소해서는 안 된다.
- `AIR-EVID-044` 모순이 있는 주제의 개선 제안은 특정 해석을 전제로 하지 않고 설명 확인, 용어 명확화 또는 추가 예시처럼 양쪽을 검증할 수 있는 조치로 제한한다.
- `AIR-EVID-045` 모순이 없는 PIN 기반 패턴은 서로 다른 지지 질문이 2건 이상이고 모든 참조 검증을 통과했을 때만 `충분`으로 표시한다.
- `AIR-EVID-046` 질문 1건은 `제한적`인 개별 신호로 표시할 수 있지만 반복 혼란이나 공통 패턴으로 표현할 수 없다.
- `AIR-EVID-047` 질문 근거가 없으면 참여자 근거 수준을 `불충분`으로 표시하며, 자료 이미지에 직접 근거한 요약은 별도로 유지할 수 있다.
- `AIR-EVID-048` 섹션과 리포트의 참여자 근거 수준은 코드가 계산한다. 충분한 PIN 패턴이 하나 이상이고 표시된 제한적·모순 PIN 신호가 없으면 `충분`, 질문은 있으나 이 조건을 충족하지 못하면 `제한적`, 질문이 없으면 `불충분`이다.
- `AIR-EVID-049` 자료 관찰은 비식별화된 슬라이드 이미지가 내용을 직접 지지할 때만 `충분`으로 표시하며 참여자 근거 수준을 높이지 않는다.

## 6. 구조화 출력과 출처

- `AIR-EVID-050` 슬라이드 분석과 전체 합성은 버전이 명시된 strict JSON Schema를 사용하며 필수 필드 누락과 알 수 없는 필드를 허용하지 않는다.
- `AIR-EVID-051` canonical 분석 결과는 선택 snapshot, 자료와 슬라이드 참조, 자료 관찰, PIN 신호와 패턴, 모순 쟁점, 미답변 질문, 개선 제안, 근거 수준을 포함한다.
- `AIR-EVID-052` 표시 가능한 각 분석 문장과 개선 제안은 고유 claim 참조를 가지며 claim에는 종류, 본문, 근거 수준, slide 참조, 지지 질문 참조, 반대 질문 참조, metric 참조를 기록한다.
- `AIR-EVID-053` AI는 snapshot에 없는 식별자나 원문을 만들 수 없으며, 코드는 모든 참조가 snapshot의 정확한 원본과 일치하는지 검증한다.
- `AIR-EVID-054` AI가 수치를 서술하려면 코드가 제공한 metric 참조를 사용해야 하며 임의의 숫자를 직접 산출하거나 반올림할 수 없다.
- `AIR-EVID-055` 렌더러는 metric 참조를 검증된 값으로 치환하고, 수치가 원본 집계와 다르면 결과를 거부한다.
- `AIR-EVID-056` A형과 B형은 동일한 canonical claim과 정렬 순서를 서로 다른 레이아웃으로 렌더링하며 별도의 분석 결과를 저장하지 않는다.
- `AIR-EVID-057` B형 문장에서 여러 claim을 연결하면 각 문장이 사용하는 모든 claim 참조를 유지해야 한다.
- `AIR-EVID-058` 구조화 출력 검증 실패는 자동 보정이나 필드 삭제로 숨기지 않고 해당 분석 단위의 재시도 가능한 실패로 처리한다.
- `AIR-EVID-059` 외부 AI에는 database UUID 대신 snapshot 안에서만 유효한 순번 기반 material·slide·question alias를 전달하며, 실제 식별자와 alias의 mapping은 서버 내부에만 보존한다.

## 7. AI revision 제약

- `AIR-EVID-060` 첫 버전의 revision은 선택한 canonical 분석과 같은 snapshot 및 같은 claim 집합을 사용한다.
- `AIR-EVID-061` AI는 revision에서 문장 표현, claim 표시 순서, 강조, 길이와 포함할 claim의 선택만 변경할 수 있다.
- `AIR-EVID-062` revision은 claim의 의미, 종류, 근거 수준, 지지·반대 질문, 의미 관계, metric 참조와 원본 slide 참조를 추가·삭제·변경할 수 없다.
- `AIR-EVID-063` 섹션 수정 요청은 대상 섹션만 새 표현으로 만들고 나머지 섹션의 canonical claim 선택과 표현을 그대로 재사용한다.
- `AIR-EVID-064` 축약 과정에서 claim을 표시하지 않을 수는 있지만 canonical 분석과 근거 기록에서 삭제해서는 안 된다.
- `AIR-EVID-065` revision의 모든 문장에는 사용한 기존 claim 참조가 있어야 하며 참조되지 않은 새 사실, 수치, 해석 또는 개선 제안을 포함할 수 없다.
- `AIR-EVID-066` 수정 지시가 근거 재해석, 새 결론, 근거 수준 변경 또는 새 분석을 요구하면 허용된 부분만 조용히 처리하지 않고 revision 생성을 거부하며 제한 사유를 반환한다.
- `AIR-EVID-067` 실패하거나 거부된 revision은 현재 revision과 canonical 분석을 변경하지 않는다.
- `AIR-EVID-068` 성공한 revision은 수정 지시, 대상 범위, 사용한 claim 목록과 이전 revision 참조를 보존한다.
- `AIR-EVID-069` A형과 B형은 선택한 동일 revision의 claim 선택과 표현을 사용하며 서로 다른 revision을 만들지 않는다.

## 8. 생성 결과 검증

- `AIR-EVID-070` 모든 최초 생성과 revision 후보는 사용자에게 노출하기 전에 결정론적 코드 검증과 별도 AI 비평 검증을 순서대로 통과해야 한다.
- `AIR-EVID-071` 코드 검증은 schema, snapshot, source 참조, 원문 일치, 좌표, 공간 후보, 근거 수, metric 값, 근거 수준과 revision 변경 허용 범위를 검사한다.
- `AIR-EVID-072` 코드 검증에 실패한 후보는 AI 비평에 보내지 않고 재시도 가능한 실패로 처리한다.
- `AIR-EVID-073` AI 비평은 후보의 각 claim이 이미지와 질문 근거에 의해 지지되는지, 과장·인과 추정·모순 은폐·의미 변경·개인정보 노출이 없는지를 검사한다.
- `AIR-EVID-074` revision 비평은 새 표현이 원래 claim의 의미와 근거 수준을 바꾸지 않았는지 추가로 검사한다.
- `AIR-EVID-075` AI 비평은 후보를 직접 수정하거나 누락 claim을 생성하지 않고 claim별 판정과 제한된 실패 사유 코드만 반환한다.
- `AIR-EVID-076` 분석 문장이나 개선 제안 하나라도 비평을 통과하지 못하면 후보 전체를 사용자에게 노출하지 않는다.
- `AIR-EVID-077` 비평 결과의 claim 참조와 schema도 코드로 검증하며, 유효하지 않은 비평 응답은 통과로 간주하지 않는다.
- `AIR-EVID-078` 재시도 후에도 생성 또는 비평 검증에 실패하면 마지막 사용 가능한 revision을 유지하고 해당 작업을 실패 처리한다.
- `AIR-EVID-079` AI 비평 통과는 강사의 검토와 확정을 대신하지 않는다.

## 9. 생성 모델과 비평 모델 분리

- `AIR-EVID-080` 생성과 비평에는 서로 다른 고정 모델 계열을 사용해야 한다.
- `AIR-EVID-081` 생성 모델과 비평 모델의 식별자, 제공자, prompt 버전, schema 버전을 각 결과에 기록한다.
- `AIR-EVID-082` 비평 모델은 생성 모델의 숨은 추론을 전달받지 않고 snapshot 근거, 검증된 canonical 후보와 revision 지시만 평가한다.
- `AIR-EVID-083` 비평 모델을 사용할 수 없으면 같은 모델이나 다른 임의 모델로 대체하지 않고 검증 작업을 실패 처리한다.
- `AIR-EVID-084` 모델 설정 변경은 같은 입력의 재현 조건을 바꾸므로 기존 report version이나 revision을 갱신하지 않고 이후 생성 요청에만 적용한다.
- `AIR-EVID-085` 모델 계열 또는 prompt·schema 버전을 변경하려면 출시 차단 평가 세트를 다시 통과해야 한다.

## 10. 출시 차단 평가

- `AIR-EVID-090` 결정론적 검증 테스트는 point, box, path, 이미지 경계 crop, 좌표 없음, 잘못된 좌표, 질문 0건·1건·2건, 모순, 복수 자료, 잘못된 source 참조와 metric 불일치를 포함한다.
- `AIR-EVID-091` revision 테스트는 표현 변경, 순서 변경, 축약, 섹션 제한 수정과 함께 새 claim·새 수치·근거 수준·source 관계 변경 시도를 포함한다.
- `AIR-EVID-092` 개인정보 테스트는 수강생 식별자, 이메일, 세션 식별자, 인증 정보와 speaker note가 근거 묶음, 생성 출력, 비평 출력, A/B 보기와 PDF에 나타나지 않는지 검사한다.
- `AIR-EVID-093` 선택 snapshot의 모든 슬라이드에 최종 검증된 결과가 정확히 하나씩 포함되고, 누락·중복·부분 성공이 없는지 검증한다.
- `AIR-EVID-094` 유효하지 않은 source 참조, 원문 불일치, metric 불일치, 무근거 분석 문장, 숨겨진 모순 또는 금지된 revision 변경을 허용하는 결과는 출시 차단 실패다.
- `AIR-EVID-095` 결정론적 release fixture는 기대 결과와 100% 일치해야 한다.
- `AIR-EVID-096` AI 비평 fixture는 고정 설정으로 3회 연속 실행하며, 심각한 무근거·개인정보·모순 은폐·revision 의미 변경 fixture가 한 번이라도 통과하면 출시를 차단한다.
- `AIR-EVID-097` 각 정상 fixture는 3회 중 최소 2회 비평을 통과해야 하며, 이를 충족하지 못하면 과도한 차단으로 간주하고 출시를 차단한다.
- `AIR-EVID-098` A형과 B형의 claim, source, metric과 근거 수준이 서로 다르면 출시를 차단한다.
- `AIR-EVID-099` 위 평가를 통과하지 않은 모델, prompt 또는 schema 조합을 운영 생성에 사용할 수 없다.

## 11. 슬라이드 이미지 비식별화

- `AIR-EVID-100` 외부 AI 전송 전에 선택된 모든 원본 슬라이드 이미지를 서비스 내부의 로컬 OCR로 검사한다.
- `AIR-EVID-101` OCR 결과에서 이메일, 전화번호, 인증 token과 API key 형태의 문자열을 결정론적 패턴으로 탐지하고 해당 bounding box를 분석용 이미지 사본에서 가린다.
- `AIR-EVID-102` OCR 호출, 민감 문자열 탐지와 이미지 가림은 외부 AI 요청보다 먼저 완료되어야 하며 이 단계에 외부 AI나 외부 OCR 서비스를 사용할 수 없다.
- `AIR-EVID-103` 전체 이미지 오버레이와 crop은 비식별화가 끝난 이미지 사본에서 생성한다.
- `AIR-EVID-104` 원본 슬라이드 이미지와 기존 강의 자료는 변경하지 않으며, 원본은 리포트 근거 화면이나 PDF가 아니라 기존 강의 자료 화면에서만 계속 사용한다.
- `AIR-EVID-105` 외부 AI, 리포트 근거 화면과 PDF에는 비식별화된 이미지 사본만 사용할 수 있다.
- `AIR-EVID-106` 비식별화 기록에는 원본·사본 checksum, OCR 엔진·규칙 버전, 민감정보 종류와 정규화 bounding box만 남기며 인식된 원문 값은 저장하거나 log에 기록하지 않는다.
- `AIR-EVID-107` OCR, bounding box 생성 또는 이미지 가림이 한 슬라이드라도 실패하면 원본 이미지를 대신 전송하거나 해당 슬라이드를 제외하지 않고 전체 생성을 실패 처리한다.
- `AIR-EVID-108` OCR 오탐으로 필요한 강의 내용이 가려질 수 있음을 생성 전 안내하고, 첫 버전에는 리포트별 가림 해제 기능을 제공하지 않는다.
- `AIR-EVID-109` 출시 차단 fixture는 이미지 안의 이메일, 전화번호, JWT와 대표 API key 형태가 모델 입력용 이미지와 PDF에서 읽을 수 없게 가려지는지 검사한다.
