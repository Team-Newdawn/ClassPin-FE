# 시스템 절 재료: 인사이트 분석·대화 파이프라인

- 제품 설계의 원본은 `../../insights/insights-ai-foundation.md` 10절(흐름)과 11절(다중 공급자)이다. 이 문서는 논문에 쓸 요점만 모으고, 동작이 바뀌면 원본을 먼저 고친다.
- 그림: `insight-pipeline.html`(분석·대화 파이프라인, 2026-10-22 작성)

## 분석

1. 강사가 자료를 고르면 서버가 원본 PDF를 내려받아 poppler로 페이지마다 JPEG(16:9 기준 1455×818)와 텍스트 레이어를 만든다. 렌더는 한 번에 하나, CPU 절반 사용.
2. 텍스트 레이어는 읽을 수 있는 글자 비율로 걸러 깨진 레이어를 버린다(`readableText`).
3. 20쪽씩 묶어 병렬 호출한다. 각 호출은 페이지 이미지, `<slide_text>`, PIN 픽셀 좌표와 익명화된 질문을 받는다. 묶음은 10만 토큰 미만으로 유지(Haiku 5.5 장문 요금 경계).
4. 병합 호출 1회로 전체 요약과 강사 행동 제안을 만든다. 검증은 코드로만 한다(별도 비평 모델 없음).
5. 일부 묶음이 실패해도 나머지 결과를 저장하고 실패한 쪽을 표시한다(`failedPages`).
6. 호출마다 사용량을 기록한다(`insight_ai_usage`, 공급자·비싼 가격 구간 진입 여부 포함).
7. 공급자(Claude·OpenAI·Gemini)는 서버 설정으로 하나를 고르고, 위 흐름은 공급자 무관 코드가, JSON 호출·대화 스트림·이미지 크기·사용량 정리는 공급자별 어댑터가 맡는다(2026-10-24 기준 Claude 어댑터만 구현).

## 대화

1. 분석 결과를 번호 붙은 일반 텍스트 문맥으로 보낸다(대화 기록 20턴·약 2만 자 상한).
2. 메시지에 쪽 번호가 나오면 그 슬라이드를 미리 첨부한다(`slidesMentioned`).
3. 그 밖에는 모델이 `view_slides` 도구로 쪽을 요청한다(최대 2라운드). 도구는 이미지, 텍스트, 그 쪽 PIN의 픽셀 좌표를 돌려준다.
4. 위치·그림·숫자 질문은 슬라이드를 보고 답하도록 지시한다(모델이 도구를 쓰지 않던 사례에서 도입).
5. 응답은 스트리밍하고, 끊긴 답은 저장하지 않는다.
