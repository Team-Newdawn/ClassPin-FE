## 0. v1(2026-10-23)에서 바뀐 점

제품 코드가 공급자 무관 흐름(`app/_service/insight-ai.ts`)과 공급자별 어댑터(`app/_service/insight-providers/`)로 나뉘었다(11절 구현 1단계, Claude 어댑터만 있음). 실험이 제품과 같은 호출 경로를 타도록 설계를 고쳤다.

- **호출 경로**: 별도 `providers.ts`와 실험용 `package.json`을 없앤다. 이미지 조건은 제품 어댑터의 `json()`을, E3는 제품의 `analyzeInsight`·`chatInsight`를 그대로 부른다. 제품 어댑터에 없는 PDF 입력만 실험 쪽에서 SDK를 직접 부른다(4절).
- **선행 작업**: OpenAI·Gemini 어댑터(11절 구현 2·3단계)가 먼저 있어야 한다. SDK(`openai`, `@google/genai`)는 그 작업에서 제품 의존성으로 들어간다.
- **이미지**: PNG 1456×819 → 제품과 같은 JPEG(품질 90) 1455×818. 절반 해상도는 728×409.
- **추론 설정**: 어댑터가 정한 값을 그대로 쓴다(Claude `effort: low`). v1의 "기본 추론 설정 보조 조건"은 어댑터에 그 설정이 없어 뺐다.
- **E1b 추가**: 한 호출에 슬라이드 몇 장을 넣을지(1·5·20장). 11절 3항이 OpenAI·Gemini의 묶음 쪽 수를 E1로 정하게 했는데 v1에는 그 조건이 없었다.
- **슬라이드 12장 → 20장**: 20장 묶음 조건을 만들려면 20장이 필요하다(합성 18 + 실제 2).
- **제품 결정 규칙 추가**(8절): E1 결과로 OpenAI·Gemini 어댑터의 이미지 크기·좌표 표기·묶음 쪽 수를 어떻게 정하는지 미리 정한다.
- **E3**: 제품 대화 함수에 조건을 바깥에서 거는 방식으로 바꿨다(제품 코드 변경 없음).

## 2. 제공자별 이미지·PDF 처리 (설계에 영향을 주는 사실)

| 항목 | Claude (4.7 이후) | OpenAI (GPT-6) | Gemini (3·4) |
|---|---|---|---|
| 이미지 축소 | 제품 규칙: 긴 변 1,568px·1,568 토큰(28px 칸) 이내 → 16:9는 1455×818 | `detail`별 상한. 32px 패치, 1455×818 = 1,196 패치 | `media_resolution`(high 1,120 토큰). 내부 해상도 비공개 |
| 축소 감지 | `transformations.oversized_image: "error"`로 축소 시 거부 가능 | 패치 수로 계산 가능 | 불가 |
| PDF 처리 | 페이지 이미지 + 추출 텍스트. 래스터 크기 제어 불가 | 페이지 이미지 + 추출 텍스트 | 페이지 이미지 + 네이티브 텍스트(텍스트 토큰 무료) |
| 좌표 관례 | 절대 픽셀 권장, 0~1000 비권장 | 문서상 관례 없음 | `[ymin, xmin, ymax, xmax]` 0~1000 |

함의: 픽셀 좌표는 Claude에 유리하고 Gemini에 불리할 수 있다. 이것이 H5(모델 × 표기 상호작용)다. 짝 비교를 위해 E1a는 세 제공자 모두에 같은 1455×818 이미지를 보낸다. OpenAI·Gemini 어댑터의 `imageEdge`가 이 값과 다르면 그 값의 C1을 한 번 더 돌려 차이를 기록한다(스모크 단계에서 판단).

## 3. 과제와 데이터

### 과제(E1)

한 호출에 슬라이드 K장(E1a는 1장), 각 슬라이드의 요소 목록(ID + 짧은 설명), PIN 목록(번호, 좌표, 일반 문장 질문)을 준다. 모델은 각 PIN이 가리키는 요소 ID를 고른다(폐쇄형). 응답은 구조화 출력 `{"pins":[{"n":1,"element":"S03-E07"}]}`, `element`는 그 호출에 든 요소 ID와 `NONE`의 enum.

- 메시지 배치는 제품 분석과 같다: 슬라이드마다 `슬라이드 N (이미지 WxHpx):` 글자, 이미지, 목록 순서. 시스템 문장은 실험용 짧은 문장 하나로 고정한다.
- 질문 문장은 예비 실험과 같은 일반 문장 8종이라 위치만 단서가 된다.
- 요소 설명에는 위치 단어(왼쪽·위 등)를 쓰지 않는다.
- 폐쇄형이 과제를 쉽게 만들 수 있으므로, 저가 Claude의 C1·C9에 자유 서술 보조 조건을 두고 사람 2인이 채점해 순위가 같은지 확인한다(κ 보고).

### 슬라이드 (20장)

- 합성 18장: `pdf-lib` + NanumGothic으로 실제 텍스트 레이어가 있는 PDF를 만든다(예비 P2의 `make.mts`와 같은 방식). 그리면서 요소 박스를 기록하므로 정답이 자동으로 생긴다.
  - 구성: 밀집 표 3, 막대 차트 3, 선 차트 2, 파이 차트 2, 다이어그램(상자·화살표) 2, 글머리 목록 2, 이미지+캡션 2, 수식·작은 각주 2.
  - 요소 수: 장당 15~40개. 요소 크기와 인접 간격을 다양하게 해 경계 근처 오류를 볼 수 있게 한다.
- 실제 2장: 예비 실험 피치덱 2·10쪽(`gen2.py`의 요소 박스 재사용, 요소 ID 부여). 사용자가 OpenAI·Google 전송을 거절하면 빼고 합성 20장으로 채운다.
- 렌더: 제품과 같은 `pdftoppm` JPEG 품질 90, 긴 변 1455(C7·C8은 728). PDF 조건은 해당 쪽만 잘라 보낸다.

### PIN

- 밀도 30 / 70 / 150개. 시드 고정. 요소를 가중치로 뽑고(일부 요소 몰림), 요소 박스를 15% 줄인 안쪽에서 균일하게 찍는다.
- 좌표는 0~1 비율로 저장하고 조건마다 표기만 바꾼다. 제품처럼 픽셀은 `Math.round(비율 × 이미지 크기)`.
- 각 PIN에 요소 경계까지의 최단 거리를 기록한다(오류 분석용).
- **같은 (슬라이드, 밀도, 반복)의 PIN 집합은 모든 조건·모델·묶음 크기에서 동일하다** → 조건 간 짝 비교가 정확하다.

## 4. 조건

### E1a: 좌표 표기·좌표계·입력 형태 (슬라이드 1장씩)

| ID | 입력 | 좌표 표기 | 호출 경로 | 비고 |
|---|---|---|---|---|
| C1 | 이미지 1455×818 | 정확한 픽셀 (x, y) | 어댑터 | 현재 제품 방식, 기준 |
| C2 | 이미지 | 정수 % | 어댑터 | |
| C3 | 이미지 | 소수 1자리 % | 어댑터 | |
| C4 | 이미지 | 0~1000 정수 (x, y) | 어댑터 | |
| C5 | 이미지 | 0~1000 정수 (y, x) | 어댑터 | Gemini 관례 순서 |
| C6 | 이미지 + 번호 표시 이미지 | 정확한 픽셀 | 어댑터 | Set-of-Mark형 |
| C7 | 이미지 728×409 | 728 기준 픽셀 | 어댑터 | 해상도만 낮춤(좌표계 정합) |
| C8 | 이미지 728×409 | 1455 기준 픽셀, 프롬프트에 "1455×818"이라고 명시 | 어댑터 | 좌표계 어긋남 |
| C9 | PDF | 정수 % | SDK 직접 | 예비 A 재현 |
| C10 | PDF | 소수 1자리 % | SDK 직접 | |
| C11 | PDF | 0~1000 정수 (x, y) | SDK 직접 | |

- 저가 층 3종: C1~C11 전부, 반복 2회. 중간 층 3종: C1, C2, C4, C8, C9, C10, 반복 1회.
- 호출 수: (슬라이드 20 × 밀도 3) × 반복.
- PDF 조건의 SDK 직접 호출은 어댑터와 같은 모델·추론 설정·출력 상한·JSON 강제를 쓰고, 다른 점은 이미지 대신 PDF 블록 하나뿐이게 한다. 제품은 PDF를 보내지 않으므로 이 조건은 논문 RQ1(H2) 전용이다.

### E1b: 한 호출의 슬라이드 수 (저가 층만)

- 묶음 크기 K = 1 / 5 / 20. K=1은 E1a C1 결과를 재사용한다.
- 표기: 픽셀(C1), 그리고 E1a에서 그 제공자 최고 표기가 픽셀과 다르면 그 표기도.
- 밀도 30·70(150은 20장 묶음의 출력이 3,000 PIN을 넘어 출력 상한에 걸린다), 반복 2회.
- 묶음은 슬라이드 번호 순서로 자른다(제품과 같음). PIN 번호는 호출 안에서 1부터 이어 붙인다(제품의 질문 번호와 같음).
- 출력 잘림(`AI_TRUNCATED`)은 오답이 아니라 별도 지표로 센다.

## 5. 가설 (사전 등록)

주 가설(Holm 보정, α = 0.05):

- **H1 반올림**: 밀도 150에서 C3 > C2, C10 > C9. 예비 실험의 차이 대부분은 정수 반올림 때문이다.
- **H2 입력 형태**: 상대 좌표(소수 %, 0~1000)를 쓰면 이미지와 PDF가 같다. C3 vs C10, C4 vs C11의 차이가 ±2%p 안(TOST 동등성 검정).
- **H3 좌표계 정합**: C8 < C7. 이미지와 좌표 기준이 어긋나면 정확도가 떨어진다.

보조 가설(탐색적, 보정 없이 효과 크기와 95% CI 보고):

- H4 해상도: C1 vs C7.
- H5 모델 × 표기: 최적 표기가 제공자마다 다르다. Claude는 C1 ≥ C4, Gemini는 C5 ≥ C1.
- H6 번호 표시: 좌표가 정확하면 C6 − C1 이득은 작다(GUI-Primitives의 35~57%p와 대비).
- H7 안정성: 반복 간 정확도 표준편차가 C9 > C1.
- H8 묶음 크기: K=20의 정답률이 K=1보다 2%p 넘게 낮지 않다. 낮아진다면 제공자마다 다른지.

## 6. 지표와 분석

- 주 지표: PIN 단위 정답률(요소 ID 일치).
- 보조 지표: 호출 단위 정답률의 반복 간 표준편차, 입력·출력 토큰(어댑터 `onUsage`), 응답 시간, 호출당 비용, `NONE`·`AI_INVALID_OUTPUT`·`AI_TRUNCATED` 비율, 비싼 가격 구간 진입(`overTier`) 여부.
- 오류 분석: 경계 거리 구간별, 요소 종류별(표 칸·막대·문구·아이콘), 오답이 인접 요소인지, E1b에서 오답이 같은 묶음의 다른 슬라이드 요소인지(슬라이드 혼동).
- 통계
  - 짝 비교(H1, H3, H8): 같은 PIN에 대한 McNemar 검정, 슬라이드 단위 군집 부트스트랩 95% CI.
  - H2: 군집 부트스트랩으로 차이의 90% CI를 구해 ±2%p 안이면 동등(TOST).
  - 전체 모형(보조): 정답 ~ 조건 × 밀도 × 모델 + (1 | 슬라이드) + (1 | 호출) 혼합효과 로지스틱(Python `statsmodels`).
- 표본 충분성: 저가 층 조건당 120호출 × 평균 83 PIN ≈ 10,000 판정. 95% 근처 3%p 차이 검출에 필요한 약 1,500쌍(군집 보정)보다 크다. 중간 층은 반복 1회라 약 5,000 판정.

## 7. E2: 글자 판독 재현 (RQ2)

- 모델: 저가 층 3종.
- 세트: 예비 P2와 동일(합성 4쪽 43문항 + 실제 2쪽 10문항) + 깨진 텍스트 레이어 1쪽 추가(읽기 비율 0.9 미만 자료).
- 조건: PDF(SDK 직접), IMG(어댑터), IMG+TXT(어댑터, 제품의 `readableText` 필터와 `<slide_text>` 형식). 3회 반복 → 3 × 7 × 3 × 3 = 189호출.
- 채점: 정규화 완전 일치(자동).
- 기대: 세 제공자 모두 PDF가 내부적으로 이미지+텍스트이므로 PDF ≈ IMG+TXT ≥ IMG. 깨진 레이어 쪽에서 IMG+TXT(필터)가 PDF보다 나은지가 관심사.

## 8. 제품 결정 규칙 (11절 3항)

E1 저가 층 결과로 OpenAI·Gemini 어댑터 값을 아래처럼 정하고, 사용자 승인 뒤 제품 설계 11절과 어댑터를 고친다. 차이가 작으면 공통 코드를 그대로 두는 쪽을 택한다.

- 좌표 표기: 기본은 픽셀(공통 코드). 다른 표기가 C1보다 2%p 넘게 높고 95% CI가 0을 넘을 때만 그 어댑터에 표기 함수를 추가한다.
- 이미지 크기: 1455 기준. C7이 C1과 동등하면(±1%p) 토큰이 적은 쪽을 검토 대상으로 보고한다(바로 바꾸지 않음).
- 묶음 쪽 수: 기본 20. K=20이 K=5보다 2%p 넘게 낮거나 잘림 비율이 1%를 넘으면 그 제공자는 K=5로 낮춘다.
- Claude는 현재 값 유지가 기본이며, 같은 규칙에 걸리면 별도로 보고한다.

## 9. E3: 대화 첨부 정책 (RQ3, 초안)

E1 이후 확정한다. 실제 학생 데이터 대신 합성 덱 + 합성 질문을 쓴다.

- 리포트: 제공자마다 제품 `analyzeInsight`를 합성 덱에 한 번 돌려 만든다(분석 경로 실제 확인을 겸함).
- 질문 세트 60개: 위치·그림·숫자 질문 30(슬라이드를 봐야 답할 수 있음), 개념·요약 질문 30(분석 텍스트로 충분). 각 문항에 정답, "봐야 하는 쪽", 강사가 보고 있는 쪽(절반은 정답 쪽, 절반은 다른 쪽)을 붙인다.
- 조건(모두 제품 `chatInsight` 호출, 제품 코드 변경 없음)
  - R(현재 제품): 그대로 호출.
  - A(항상 첨부): 메시지 앞에 "슬라이드 N"(보고 있는 쪽)을 붙여 제품의 선첨부 경로가 그 쪽을 붙이게 한다.
  - T(슬라이드 없음): `view`가 "볼 수 없다"는 문장만 돌려준다. 분석 텍스트만으로 답하는 기준선.
- 지표: 정답률(정답 키 기준 자동 + 사람 표본 확인), `view` 기록으로 본 쪽과 도구 사용 횟수, 봐야 하는데 안 본 비율, 토큰.
- 저가 층 3종 × 3조건 × 60문항 × 2회 = 1,080호출. 실행 전 별도 승인.

## 10. 실행 구조

- 위치: `docs/paper/experiments/multi-provider/harness/`. 별도 `package.json` 없이 저장소 의존성과 제품 코드를 상대 경로로 가져와 `node`(v22, 타입 제거 내장)로 실행한다.
- 파일
  - `build.mts`: 합성 슬라이드·요소 목록·PIN 생성(시드 고정), 렌더, 정답 박스 겹침 이미지.
  - `pdf.mts`: PDF 조건용 제공자별 SDK 직접 호출 3개(각 어댑터의 요청 설정을 따름).
  - `run.mts`: 조건 × 모델 작업표. 결과를 JSONL에 이어 쓰기(중단 후 재개), 제공자별 동시성 제한(제품 `limiter` 재사용), 재시도는 SDK 기본값.
  - `grade.mts`: 순수 채점 함수(자동 테스트 1개 포함).
  - `analyze.py`: 6절 분석.
- 키: `CLAUDE_API_KEY`, `GEMINI_API_KEY`는 `.env.local`에 있음. **`OPENAI_API_KEY`는 없음 → 추가 필요.** Gemini는 결제 연결된 키만 쓴다(11절 5항). 키 값은 출력하지 않는다.
- 자동 중단: 제공자별 누적 비용이 예산 상한을 넘거나, 최근 50호출 오류율이 10%를 넘으면 그 제공자를 멈춘다.
- 기록: 모든 호출에 모델 ID, 실행 시각, 조건, 사용량, 응답 원문을 저장한다. 결과 JSONL은 `data/`(git 제외).
